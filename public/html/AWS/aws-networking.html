☁️ AWS VPC (Virtual Private Cloud)

VPC is a logically isolated network within AWS cloud.

Network Flow Examples

Public: Load Balancer → Internet Gateway → VPC → Route Table → Subnet → EC2 Private: Load Balancer → Internet Gateway → VPC → Route Table → Subnet → NAT Gateway → Private EC2

🔲 Subnets

Subnets segment VPC by security and operational needs.

  • Public Subnet: Has route to Internet Gateway
  • Private Subnet: No direct internet access
  • Each subnet in one Availability Zone
  • Can have custom IP ranges within VPC CIDR

🛣️ Routing

Route Tables

  • Define routing rules for VPC traffic
  • Main Route Table: Default for all subnets
  • Custom Route Tables: Override main table
  • Associate with subnets

Internet Gateway (IGW)

  • Enables VPC-to-internet communication
  • Horizontally scaled, redundant, highly available
  • Attach to VPC

NAT Gateway

  • Private subnet outbound internet access
  • No inbound traffic from internet
  • Create in public subnet
  • Update private subnet route table

✨ VPC Advanced Features

VPC Endpoints

  • Private AWS service access without internet gateway
  • Gateway Endpoints: S3, DynamoDB
  • Interface Endpoints: Other services (SNS, SQS, etc.)

VPC Peering

  • Connect two VPCs
  • No overlapping IP addresses
  • Update route tables in both VPCs
  • One VPC sends request, other accepts

VPC Flow Logs

  • Captures IP traffic metadata
  • Logs: source/dest IPs, ports, protocol, action
  • Destinations: CloudWatch, S3, Kinesis
  • Use: Security analysis, troubleshooting

AWS Transit Gateway

  • Hub-and-spoke network connecting multiple VPCs
  • Simplifies complex VPC peering
  • Transitive routing support
  • Multi-account support via AWS RAM

AWS Direct Connect

  • Dedicated private connection to AWS
  • Lower latency, higher bandwidth (up to 100 Gbps)
  • More consistent than VPN
  • Use: Enterprise hybrid cloud

AWS PrivateLink

  • Private connectivity between VPCs and services
  • Traffic doesn't traverse internet
  • Access across accounts or AWS Marketplace

⚖️ Application Load Balancer (ALB)

Operates at Layer 7 (Application) for HTTP/HTTPS traffic.

Key Features

  • Path-based Routing: /api/aws/*, /api/azure/*
  • Host-based Routing: api.example.com
  • WebSocket, HTTP/2 support
  • Sticky sessions
  • 60-second timeout

Target Types

  • EC2 instances
  • Lambda functions
  • IP addresses

Use Cases

  • Microservices architectures
  • Containerized applications
  • Advanced routing requirements

🚀 Network Load Balancer (NLB)

Operates at Layer 4 (Transport) for TCP/UDP traffic.

Key Features

  • Ultra-low latency
  • Millions of requests per second
  • Static IP support
  • Preserves source IP
  • No timeout
  • Cross-zone disabled by default

ALB vs NLB

FeatureALBNLB
Layer Layer 7 (Application) Layer 4 (Transport)
Protocol HTTP/HTTPS TCP/UDP
Routing Path/Host-based Port-based
Timeout 60 seconds No timeout
Static IP No Yes
Source IP Not preserved Preserved

🛡️ Gateway Load Balancer (GWLB)

Combines transparent gateway + load balancer.

Features

  • Deploy/scale virtual appliances
  • Firewalls, IDS/IPS
  • Examples: Palo Alto, Checkpoint, Fortinet
  • VPC Ingress/Egress routing

📈 AWS Auto Scaling

Automatically adjusts EC2 instance count based on demand.

Scaling Types

  • Vertical: Increase instance size
  • Horizontal: Add/remove instances

Components

  • Launch Template: AMI, instance type, security groups, IAM role, user data
  • Auto Scaling Group: Min/max instances, scaling policies, health checks

Scaling Policies

TypeDescription
Manual User-controlled adjustments
Scheduled Scale at specific times
Dynamic - Simple Single metric (CPU, network)
Dynamic - Step Incremental based on severity
Predictive ML-based future demand prediction

Maintenance Policies

  • Launch Before Terminate: Zero-downtime updates
  • Terminate and Launch: Brief downtime
  • Custom Behavior: User-defined rules

🌍 AWS Route 53 (DNS Service)

Scalable and highly available DNS web service.

Features

  • Domain registration and management
  • DNS Routing: Simple, weighted, latency-based, geolocation, failover
  • Health Checks: Monitor resources, route away from unhealthy
  • Traffic Flow: Visual editor for complex routing
  • DNS Failover: Auto-redirect to backup
  • DNSSEC: Protection against DNS spoofing
  • Private Hosted Zones: VPC internal DNS

Integrations

  • CloudFront (CDN)
  • S3 (static sites)
  • ELB, API Gateway
  • CloudWatch, VPC

Advanced

  • Route 53 Resolver: Recursive DNS for VPC & on-premises
  • Application Recovery Controller: Automated failover/recovery

🔐 VPN (Virtual Private Network)

Secure connection between networks over the internet.

Types

TypeDescription
Site-to-Site VPN Connects two VPCs or on-premises to VPC
Client VPN Remote client device to VPC

Components

  • Customer Gateway: Customer-side device/software
  • Virtual Private Gateway: AWS side, attached to VPC
  • Client VPN Endpoint: Managed VPN for remote access
