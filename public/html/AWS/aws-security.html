Complete Guide to AWS Security Services & Best Practices

🎯 Security Domains

1. Threat Detection & Incident Response

  • Identify and respond to potential security threats
  • Continuous monitoring for malicious activity
  • Service: Amazon GuardDuty

2. Security Logging & Monitoring

  • Capture and analyze logs from AWS services
  • Detect and respond to security incidents
  • Services: CloudTrail, CloudWatch, VPC Flow Logs

3. Infrastructure Security

  • Protect underlying infrastructure (network, access control, encryption)
  • Services: VPC, Security Groups, NACLs, WAF, Shield, Network Firewall

4. Identity & Access Management

  • Manage user identities and control access to resources
  • Service: AWS IAM (users, groups, roles, policies)

5. Data Protection

  • Secure sensitive data at rest and in transit
  • Services: KMS (encryption), Secrets Manager, Macie (PII discovery)

6. Compliance & Governance

  • Meet regulatory requirements and industry standards
  • Services: Security Hub, Config, Organizations

7. Application Security

  • Secure applications deployed on AWS
  • Services: Inspector (vulnerability scanning), WAF

🛡️ Amazon GuardDuty (Threat Detection)

Continuously monitors AWS accounts for malicious activity and unauthorized behavior.

Key Features

  • Uses ML, anomaly detection, threat intelligence
  • Severity levels: Critical → High → Medium → Low → Informational
  • Findings can trigger EventBridge → Lambda/SNS for automation
  • Supports suppression rules and whitelisting

Protection Plans

PlanDescription
S3 Protection Monitors S3 access patterns
EKS Protection Monitors container activity
Runtime Protection Continuous monitoring
Malware Protection Agentless EBS volume scanning (initial + on-demand)

Severity Levels

  • Critical: High-risk threats requiring immediate attention
  • High: Significant threats impacting security
  • Medium: Potential threats requiring investigation
  • Low: Minor issues to monitor
  • Informational: Additional context, no threat

📜 AWS CloudTrail (API Auditing)

Records all AWS API calls (who, what, when, where).

Event Types

  • Management Events: Control plane operations (CreateBucket, TerminateInstance)
  • Data Events: Resource operations (S3 GetObject, Lambda Invoke)
  • Insight Events: Detect unusual API activity

Key Features

  • 90 days free event history
  • Create trails for long-term storage in S3
  • Integrates with CloudWatch Logs for real-time monitoring
  • Essential for compliance, security analysis, troubleshooting

CloudTrail vs CloudWatch

🔍 Amazon Inspector (Vulnerability Assessment)

Automated security assessment for EC2, Lambda, containers (ECR).

Features

  • Scans for CVEs (Common Vulnerabilities and Exposures)
  • CVSS scoring (0-10, higher = more critical)
  • Requires SSM agent on EC2 instances
  • Provides actionable remediation recommendations

CVE & CVSS

CVE (Common Vulnerabilities and Exposures):
  • Publicly disclosed list of known security vulnerabilities
  • CVE ID format: CVE-YYYY-NNNN
  • Includes description, date published, affected products
CVSS (Common Vulnerability Scoring System):
  • Numerical score (0-10) indicating severity
  • Higher scores = more critical vulnerabilities

🔑 AWS KMS (Key Management Service)

  • Managed encryption key creation and control
  • Customer Master Keys (CMKs) for data encryption
  • Integrates with most AWS services
  • Automatic key rotation support
  • Audit key usage via CloudTrail

Encryption Best Practices

  • At Rest: Use KMS for all storage (S3, EBS, RDS, DynamoDB)
  • In Transit: Use TLS/SSL 1.2+ for all communications
  • End-to-End: Encrypt before uploading to AWS (client-side encryption)
  • Key Rotation: Enable automatic rotation (annual recommended)
  • Access Control: Limit KMS key permissions via key policies
  • Separate Keys: Different keys for different data classifications

🔐 AWS Secrets Manager

  • Store and rotate database credentials, API keys, secrets
  • Automatic rotation for RDS, Redshift, DocumentDB
  • Integrates with IAM for access control
  • Encrypted at rest using KMS

👤 AWS IAM (Identity & Access Management)

Core Components

  • Users: Individual identities with unique credentials
  • Groups: Collections of users with shared permissions
  • Roles: Temporary credentials for AWS services/applications
  • Policies: JSON documents defining permissions

Policy Evaluation Logic

  1. Explicit Deny → Always wins
  2. Explicit Allow → Check all applicable policies
  3. Default Deny → If no allow, deny

👥 IAM Users & Groups

IAM Users

Access Types:

  • Console (password)
  • CLI/API (access keys)
  • CodeCommit (Git credentials)

Security Features:

  • MFA: Multi-factor authentication for additional security
  • Password policy: Enforce complexity, expiration, reuse prevention
  • Create aliases for account sign-in URL

IAM Groups

  • Organize users by function (developers, admins, etc.)
  • Attach policies to groups for easier management
  • Users inherit group permissions

🎭 IAM Roles (5 Types)

💡 Key Benefits:

✅ IAM Best Practices

  • ✓ Enable MFA on root and all users
  • ✓ Never use root account for daily tasks
  • ✓ Create master IAM user for admin tasks
  • ✓ Rotate access keys every 90 days
  • ✓ Delete unused access keys
  • ✓ Use IAM roles instead of access keys where possible
  • ✓ Apply least privilege principle
  • ✓ Use groups to manage permissions
  • ✓ Secure email associated with account
  • ✓ Use account aliases for easier sign-in

⚙️ AWS Config

Tracks resource configuration changes over time.

Features

  • Records configuration snapshots to S3
  • Compliance rules: Detective (after change), Proactive (before creation)
  • Conformance packs: Pre-defined compliance rule sets
  • Triggers: EventBridge → Lambda/SNS for remediation

Use Cases

  • Auditing changes over time (who changed what and when)
  • Enforcing security standards (e.g., encryption at rest)

  • Assisting with compliance requirements (HIPAA, PCI-DSS)

🚨 Incident Response

AWS Services for Incident Response

  • WAF: Block malicious web traffic
  • IAM: Revoke compromised credentials
  • Network Firewall: Filter VPC traffic
  • KMS: Rotate encryption keys
  • CloudTrail: Audit API activity
  • CloudWatch: Real-time monitoring and alerts
  • Inspector: Assess vulnerabilities
  • Detective: Investigate security issues
  • EventBridge: Automate incident response

Event-Driven Incident Response

GuardDuty Finding → EventBridge → Lambda → Automated remediation Examples: Isolate compromised instance, revoke IAM keys, block IPs

Compromised EC2 Instance Response Steps

  1. Lock down: Modify security groups (deny all traffic)
  2. Isolate: Detach from network or stop instance
  3. Investigate: Analyze logs, CloudTrail, VPC Flow Logs
  4. Remediate: Patch vulnerabilities, change credentials
  5. Recover: Restore from clean backup or rebuild

⚠️ Vulnerabilities & Attack Vectors

Terminology

TermDefinition
Vulnerability Weakness in system/application (software bug, misconfiguration)
Exploit Code/technique that takes advantage of vulnerability
Payload Malicious action delivered by exploit (code execution, data theft)
Penetration Testing Simulated attack to find vulnerabilities

Common Attack Vectors

  • SQL Injection: Malicious SQL code in input fields
  • Cross-Site Scripting (XSS): Inject malicious scripts in web pages
  • Cross-Site Request Forgery (CSRF): Trick users into unwanted actions
  • Man-in-the-Middle (MITM): Intercept communication
  • Brute Force: Repeatedly try passwords/keys
  • Zero-Day: Exploit unknown vulnerabilities
  • Social Engineering: Manipulate humans to divulge info
  • Phishing: Fake emails/websites to steal credentials

Common Security Shortcomings

  • Weak passwords (easily guessable)
  • Unpatched software (missing security updates)
  • Improper firewall configuration
  • Lack of WAF for web applications
  • Insufficient server hardening
  • No file integrity monitoring
  • Lack of logging and monitoring
  • No threat detection system
  • Missing incident response plan
  • Inadequate static code analysis
  • Lack of security awareness training

🔒 VPC Security Features

VPC Endpoints

  • Private connection to AWS services (no internet/NAT)
  • Gateway Endpoints: S3, DynamoDB (route table entry)
  • Interface Endpoints: Most other services (powered by PrivateLink)
  • Use: EC2 in private subnet → VPC Endpoint → S3 (no public internet)

VPC Flow Logs

Captures IP traffic metadata for VPC network interfaces.

Format: version account-id interface-id srcaddr dstaddr srcport dstport protocol packets bytes start end action log-status Fields: - action: ACCEPT or REJECT - protocol: 6 = TCP, 17 = UDP - Destinations: CloudWatch Logs, S3, Kinesis Data Firehose

VPC Reachability Analyzer

  • Static configuration analysis (not live traffic)
  • Validates connectivity paths between resources
  • Identifies misconfigurations (route tables, SGs, NACLs)
  • Use: Pre-deployment checks, troubleshooting

Network Access Analyzer

  • Identifies unintended network access to resources
  • Defines network access scope (allowed/denied paths)
  • Generates findings when access violates defined scope
  • Use: Security audits, compliance validation
  • Example: Ensure EC2 only accessible via MongoDB (no internet)

Traffic Mirroring

  • Copy network traffic from ENIs for deep packet inspection
  • Components: Source (ENI) → Filter (protocols) → Target (ENI/NLB)
  • Use: Content inspection, threat monitoring, troubleshooting
  • Integrates with tools like Splunk, Wireshark

🏰 Bastion Host & SSH Agent Forwarding

Bastion Host

  • Secure jump server in public subnet
  • Access private instances via SSH forwarding
  • Minimize attack surface (only bastion exposed)

SSH Agent Forwarding

Key in local machine → bastion → private server

  • No need to store keys on bastion host
  • More secure than copying keys to bastion

🔐 Shared Responsibility Model

AWS Responsibility (Security OF the cloud)

  • Physical infrastructure (data centers, servers, networking)
  • Hardware, software, networking, facilities
  • Managed service operations (RDS, Lambda, S3)
  • Global infrastructure security

Customer Responsibility (Security IN the cloud)

  • Data encryption (at rest and in transit)
  • IAM configuration (users, roles, policies)
  • OS/application patching (EC2, containers)
  • Network/firewall configuration (SGs, NACLs)
  • Application code security
  • Data classification and protection
