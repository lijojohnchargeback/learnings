💾 AWS Storage Services

📦 Storage Types

Storage is critical for any computing system. AWS offers three main types of storage:

TypeDescriptionAWS Services
Block Storage (DAS) Direct Access Storage - stores data in blocks EBS, Instance Store, HDD, SSD
File Storage Stores data in files and directories EFS (Linux), FSx (Windows)
Object Storage Stores data as objects with metadata S3

HDD vs SSD

FeatureHDD (Hard Disk Drive)SSD (Solid State Drive)
Technology Magnetic disks Flash memory
Speed Slower Faster
Cost Lower cost per GB Higher cost per GB
Capacity Larger storage capacity Smaller capacity
Reliability Moving parts (less reliable) No moving parts (more reliable)

⚡ Instance Store

Temporary storage physically attached to the host computer.

Characteristics

  • Ephemeral: Data lost when instance stops/terminates
  • High Performance: Faster than EBS
  • No Additional Cost: Included with instance
  • Local Storage: Not shared between instances

Use Cases

  • Temporary data (caches, buffers)
  • High-performance computing
  • Low latency applications
⚠️ Warning: Instance Store data is lost when the instance stops or terminates. Not suitable for long-term storage!

💿 Amazon EBS (Elastic Block Store)

EBS provides persistent block storage for EC2 instances.

EBS vs Instance Store

FeatureEBSInstance Store
Type Persistent block storage Temporary block storage
Data Retention Persists after stop/terminate Lost when instance stops
Availability Highly available Not highly available
Durability Multiple copies across AZs No redundancy
Performance Consistent High performance
Cost Pay-as-you-go No additional cost

EBS Volume Types

TypeDescriptionUse Case
gp2/gp3 (General Purpose SSD) Balance of price and performance Boot volumes, dev/test, small-medium databases
io1/io2 (Provisioned IOPS SSD) High performance, low latency I/O-intensive apps, databases, big data
st1 (Throughput Optimized HDD) Low cost, high throughput Big data, data warehousing
sc1 (Cold HDD) Lowest cost Infrequently accessed data, backups

Mounting EBS Volume in Ubuntu

# Check available disks lsblk # Create file system sudo mkfs -t ext4 /dev/xvdf # Create mount point sudo mkdir /mnt/myebsvolume # Mount the volume sudo mount /dev/xvdf /mnt/myebsvolume # Verify mount df -h # Make mount persistent (add to /etc/fstab) /dev/xvdf /mnt/myebsvolume ext4 defaults,nofail 0 2 # Unmount sudo umount /mnt/myebsvolume

📸 EBS Snapshots

A snapshot is a point-in-time copy of an EBS volume stored in S3.

Key Features

  • Incremental: Only changes since last snapshot are stored
  • Stored in S3: Highly durable and available
  • Create New Volumes: Restore or create new EBS volumes
  • Share: Share with other AWS accounts or make public
  • Encrypted: Can be encrypted for security
  • Create AMIs: Use to create Amazon Machine Images

Data Lifecycle Manager (DLM)

Automates creation, retention, and deletion of EBS snapshots:

  • Schedule-based snapshots
  • Event-based snapshots
  • Tag-based management
  • Reduces storage costs

📁 Amazon EFS (Elastic File System)

EFS is a scalable file storage service for Linux-based workloads using NFS protocol.

Key Features

  • Highly Available: Multiple copies across AZs
  • Scalable: Automatically grows/shrinks
  • Cost-Effective: Pay-as-you-go pricing
  • Shared Access: Multiple EC2 instances can access simultaneously
  • NFS Protocol: Standard Linux file system

Mounting EFS

# Install EFS utils sudo apt-get update sudo apt-get install -y git binutils rustc cargo pkg-config libssl-dev sudo git clone https://github.com/aws/efs-utils cd efs-utils sudo ./build-deb.sh sudo apt-get -y install ./build/amazon-efs-utils*deb # Permanent mounting (add to /etc/fstab) fs-0bbc10dde901a37cf.efs.ap-northeast-3.amazonaws.com:/ /var/www/html efs _netdev,tls 0 0

🪟 Amazon FSx

FSx is a fully managed file storage service supporting Windows File Server and Lustre.

Key Features

  • Windows File Server: SMB protocol for Windows workloads
  • Lustre: High-performance computing and big data
  • Highly Available: Multiple copies across AZs
  • Scalable: Easily adjust capacity
  • Secure: Built-in encryption and access controls

🗄️ Amazon S3 (Simple Storage Service)

S3 is a scalable object storage service designed for high availability and durability.

Key Features

  • Highly Available: 99.99% availability
  • Durable: 99.999999999% (11 9's) durability
  • Scalable: Unlimited storage capacity
  • Cost-Effective: Pay only for what you use
  • Secure: Encryption, access controls, versioning

Use Cases

  • Backup and archiving
  • Content delivery (websites, media)
  • Big data analytics
  • Disaster recovery
  • Static website hosting

📊 S3 Storage Classes

ClassDescriptionUse Case
S3 Standard Frequently accessed data, high performance Active data, websites, content delivery
S3 Intelligent-Tiering Automatically moves data between tiers Unpredictable access patterns
S3 Standard-IA Infrequently accessed, lower cost Backups, disaster recovery
S3 One Zone-IA Single AZ, lower cost Easily recreatable data
S3 Glacier Long-term archival, low cost Archives, compliance data
S3 Glacier Deep Archive Lowest cost, longest retrieval Long-term archives (7-10 years)
S3 Express One Zone Single AZ, high performance Frequently accessed data in one zone

🔄 S3 Bucket Versioning

Versioning keeps multiple versions of an object in S3.

Benefits

  • Protect against accidental deletions
  • Recover previous versions
  • Works with lifecycle management
  • Disabled by default (must enable)

Lifecycle Management

Automate transitions between storage classes:

  • 30 days → Standard-IA
  • 60 days → Glacier
  • 90 days → Glacier Deep Archive
  • 365 days → Delete (expiration)

🔒 S3 Encryption

Encryption Types

TypeDescriptionKey Management
SSE-S3 Server-Side Encryption with S3-managed keys AWS manages keys (AES-256)
SSE-KMS Server-Side Encryption with KMS Customer or AWS managed keys, key rotation
SSE-C Server-Side Encryption with Customer keys Customer provides and manages keys
Client-Side Encrypt before uploading to S3 Client responsibility
💡 Recommended: Use SSE-KMS for better control and audit trails.

✨ S3 Advanced Features

1. Static Website Hosting

  • Host static websites on S3
  • Bucket name should match domain name
  • Only HTTP supported
  • Bucket must be public

2. CORS (Cross-Origin Resource Sharing)

Control access from other domains

3. Cross-Region Replication

  • Replicate objects across regions
  • Improves availability and durability
  • Reduces latency
  • Requires versioning enabled

4. Transfer Acceleration

  • Accelerate uploads to S3
  • Uses CloudFront edge locations
  • Best for large files
  • Additional cost

5. Presigned URLs

Generate temporary URLs for secure sharing

6. MFA Delete

  • Require MFA for deletions
  • Versioning must be enabled
  • Only via Console or CLI

7. Event Notifications

Trigger Lambda, SNS, or SQS on S3 events

8. VPC Endpoints

  • Gateway Endpoints: For S3 and DynamoDB
  • Interface Endpoints: For other services
  • Access S3 without public internet

9. Access Points

  • Create custom endpoints for S3 buckets
  • Fine-grained access control
  • One bucket, multiple access points
  • Easier policy management

🌐 Amazon CloudFront

CloudFront is a Content Delivery Network (CDN) that distributes content globally.

Key Features

  • Edge Locations: Cache content closer to users
  • Low Latency: Faster content delivery
  • Global Reach: Worldwide distribution
  • Security: DDoS protection, SSL/TLS
  • Integration: Works with S3, EC2, ELB

Origins

  • S3 buckets
  • EC2 instances
  • Elastic Load Balancer
  • Custom HTTP servers

Security Features

  • Signed URLs/Cookies: Restrict access
  • Trusted Key Groups: Manage signing keys
  • Geo-Restriction: Block/allow countries
  • AWS Certificate Manager: SSL/TLS certificates

Cache Behavior

  • Path patterns
  • Automatic compression
  • Viewer protocol policy (HTTP/HTTPS)
  • TTL (Time To Live)
