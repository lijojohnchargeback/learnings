🏠 Introduction to Computers

A computer is an electronic device that takes input, processes it using software and hardware, stores it, and produces output.

What is a Computer?

Definition: A computer is a programmable electronic machine that can:

  • 📥 Accept Input: Receive data from users or other sources
  • ⚙️ Process Data: Perform calculations and operations
  • 💾 Store Information: Save data for future use
  • 📤 Produce Output: Display or deliver results

The IPO Cycle (Input-Process-Output)

┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │ INPUT │ → │ PROCESS │ → │ STORAGE │ → │ OUTPUT │ │ │ │ │ │ │ │ │ │ Keyboard │ │ CPU │ │ HDD/SSD │ │ Monitor │ │ Mouse │ │ Software │ │ RAM │ │ Printer │ │ Scanner │ │ ALU │ │ │ │ Speakers │ └─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘

Key Computer Characteristics

Characteristic Description
Speed Performs millions/billions of operations per second
Accuracy Extremely precise; errors are usually human mistakes
Diligence Works continuously without fatigue
Storage Can store vast amounts of data
Versatility Can perform many different tasks
Automation Can work automatically with minimal supervision

Main Components

Hardware (Physical Parts)

  • 🖥️ Input Devices: Keyboard, Mouse, Scanner, Microphone
  • 🖥️ Output Devices: Monitor, Printer, Speakers
  • 🖥️ Processing Unit: CPU (Brain of computer), RAM
  • 🖥️ Storage Devices: Hard Drive, SSD, USB Drive

Software (Programs/Instructions)

  • 💿 System Software: Operating Systems (Windows, macOS, Linux)
  • 💿 Application Software: Word processors, browsers, games

Basic Steps to Use a Computer

  1. Start the Computer: Press the power button
  2. Operating System Loads: System boots up
  3. Login: Enter username and password (if required)
  4. Use Applications: Open programs and work
  5. Save Work: Store documents to storage
  6. Shut Down Properly: Use OS shutdown option

📅 Generations of Computers

Generation Period Technology Examples
1st Generation 1940-1956 Vacuum Tubes ENIAC, UNIVAC
2nd Generation 1956-1963 Transistors IBM 1401, IBM 7094
3rd Generation 1964-1971 Integrated Circuits (IC) IBM System/360, PDP-8
4th Generation 1971-Present Microprocessors (VLSI) Intel 4004, Personal Computers
5th Generation Present & Beyond AI, Quantum Computing Supercomputers, AI Systems

Detailed Features by Generation

1st Generation (1940-1956): Vacuum Tubes

Technology: Vacuum tubes for circuitry, magnetic drums for memory

Programming: Machine language (binary)

Features:

  • ❌ Very large in size and expensive
  • ❌ High electricity consumption and heat generation
  • ❌ Slow processing speed
  • ❌ Prone to frequent hardware failures
  • ✅ First programmable computers

2nd Generation (1956-1963): Transistors

Technology: Transistors replaced vacuum tubes

Programming: Assembly language

Features:

  • ✅ Smaller, faster, and more reliable
  • ✅ More energy-efficient, less heat
  • ✅ Lower maintenance costs
  • ⚠️ Still expensive but more accessible

3rd Generation (1964-1971): Integrated Circuits

Technology: Integrated Circuits (ICs) - multiple transistors on one chip

Programming: High-level languages (FORTRAN, COBOL)

Features:

  • ✅ Much smaller and more powerful
  • ✅ Increased reliability and reduced cost
  • ✅ Multiprogramming capability
  • ✅ Time-sharing systems began

4th Generation (1971-Present): Microprocessors

Technology: Microprocessors (VLSI - Very Large Scale Integration)

Programming: High-level languages (C, C++, Java, Python)

Features:

  • ✅ Entire CPU on a single chip
  • ✅ Personal computers became common and affordable
  • ✅ GUI (Graphical User Interface) introduced
  • ✅ Networking and internet became widespread
  • ✅ Portable computers (laptops, tablets)

5th Generation (Present & Beyond): AI & Quantum

Technology: ULSI (Ultra Large Scale Integration), AI, quantum computing, cloud

Programming: AI frameworks, natural language processing

Features:

  • 🚀 Focus on artificial intelligence and machine learning
  • 🚀 Parallel processing and quantum computing
  • 🚀 Highly portable and connected (smartphones, IoT)
  • 🚀 Natural language understanding
  • 🚀 Advanced robotics and expert systems

🏗️ Computer Level Hierarchy

The Computer Level Hierarchy breaks down a computer system into layers, from user interaction to physical hardware.

The 7-Level Hierarchy

Level Name Description
Level 6 User Level Users interact with applications and programs
Level 5 High-Level Language Python, Java, C++, JavaScript
Level 4 Assembly Language Low-level instructions (MIPS, x86)
Level 3 System Software OS, compilers, assemblers translate code
Level 2 Instruction Set Architecture (ISA) CPU instructions set definition
Level 1 Microarchitecture Internal CPU implementation (ALU, registers, buses)
Level 0 Digital Logic Physical circuits: gates, transistors, flip-flops

Explanation of Each Level

Level 6: User Level

Highest level where users interact with software (Word, browser, games)

Level 5: High-Level Language Level

Developers write programs using high-level languages that must be compiled or interpreted

Level 4: Assembly Language Level

Low-level, human-readable representation with one-to-one mapping to machine instructions

Level 3: System Software Level

Operating systems, compilers, linkers bridge high-level code and hardware

Level 2: ISA Level

Interface between software and hardware; defines registers, instructions, memory access

Level 1: Microarchitecture Level

Actual ISA implementation using ALU, registers, buses; handles pipelining and instruction decoding

Level 0: Digital Logic Level

Basic electronic circuits forming the foundation of all computing hardware

Why It Matters:

  • ✅ Helps understand how code becomes electrical signals
  • ✅ Aids in designing efficient software and hardware
  • ✅ Useful for debugging and performance optimization
  • ✅ Essential for system design and architecture

🏛️ Computer Organization vs Architecture

Computer Organization

Definition: Deals with implementation details of how hardware components interact and execute instructions

Focus: How the system is implemented

Viewpoint: Hardware engineer's perspective

Key Topics:

  • Control Unit and ALU
  • Data paths and control signals
  • Registers and memory organization (cache, RAM, ROM)
  • Input/Output mechanisms
  • Instruction cycle (fetch, decode, execute)
  • Microprogramming
  • Bus structures (address, data, control buses)

Typical Questions:

  • How is an instruction executed at hardware level?
  • How do memory, ALU, and control units communicate?

Computer Architecture

Definition: The design and behavior of a computer system as seen by a programmer

Focus: How the system is designed and functions

Viewpoint: Programmer's perspective

Key Topics:

  • Instruction Set Architecture (ISA)
  • RISC vs. CISC design
  • Pipelining and instruction-level parallelism
  • Performance metrics (CPI, MIPS, FLOPS)
  • Addressing modes
  • Memory hierarchy and cache organization
  • Multicore and parallel processing

Typical Questions:

  • What operations does the computer support?
  • How does architecture influence performance?

Key Differences

Aspect Computer Organization Computer Architecture
Focus How system is implemented How system is designed
Viewpoint Hardware engineer Programmer
Concerned With Internal hardware operation Instruction design & performance
Abstraction Level Lower-level (implementation) Higher-level (interface & design)

Study Tip:

To understand a computer system completely:

  1. Learn architecture first to understand what the computer is supposed to do
  2. Then study organization to see how it actually does it

The Central Processing Unit (CPU) is the brain of the computer that executes instructions.

CPU Components

Component Function
Control Unit (CU) Directs operations of the processor; fetches and decodes instructions
Arithmetic Logic Unit (ALU) Performs arithmetic (+, -, ×, ÷) and logical (AND, OR, NOT) operations
Registers Small, fast storage locations inside CPU
Cache Memory Very fast memory between CPU and RAM (L1, L2, L3)
Buses Pathways for data transfer (data bus, address bus, control bus)

CPU Performance Factors

  • ⚡ Clock Speed: Measured in GHz (billion cycles/second)
  • ⚡ Number of Cores: Dual-core, Quad-core, Octa-core

  • ⚡ Architecture: RISC vs CISC
  • ⚡ Thread Count: Hyper-threading, SMT

RISC vs CISC

Aspect RISC (Reduced Instruction Set) CISC (Complex Instruction Set)

Execution Time One cycle per instruction Multiple cycles per instruction

🔄 Fetch-Decode-Execute Cycle

Also called the Instruction Cycle, this is the basic cycle through which a computer processes each instruction.

The Four Stages

1. Fetch

What happens: CPU retrieves the next instruction from RAM

How:

  • Program Counter (PC) holds address of next instruction
  • Address sent to Memory Address Register (MAR)
  • Instruction fetched into Memory Buffer Register (MBR)
  • Moved to Instruction Register (IR)

Outcome: CPU has instruction ready to decode

2. Decode

What happens: Control Unit interprets the instruction

How:

  • Breaks instruction into: operation code (opcode) and operands
  • Determines which units or registers are needed
  • Example: `5 + 6` → separates data (5, 6) and instruction (+)

Outcome: CPU understands what to do and what data to use

3. Execute

What happens: Instruction is executed by appropriate CPU part

How:

  • Arithmetic operation → ALU performs it
  • Memory operation → data read/written to memory
  • Jump/branch → Program Counter (PC) updated

Outcome: Instruction completed; CPU moves to next one

4. Store (Optional)

What happens: Result stored in register or memory

Instruction Cycle Summary

Step Action Components Used
Fetch Get instruction from memory PC, MAR, MBR, IR
Decode Understand the instruction Control Unit
Execute Perform the instruction ALU, Registers, Memory
Store Save the result Registers, Memory

Example

Instruction: ADD R1, R2, R3 (Add values in R2 and R3, store in R1) Step 1 (Fetch): Get "ADD R1, R2, R3" from memory Step 2 (Decode): Recognize as addition operation Step 3 (Execute): Perform R1 = R2 + R3 using ALU Step 4 (Store): Result already in R1

Instruction Cycle Diagram

┌───────────┐ │ START │ └─────┬─────┘ │ ▼ ┌───────────┐ │ FETCH │ ← PC points to next instruction │ │ ← Instruction loaded into IR └─────┬─────┘ │ ▼ ┌───────────┐ │ DECODE │ ← CU interprets instruction │ │ ← Identifies opcode & operands └─────┬─────┘ │ ▼ ┌───────────┐ │ EXECUTE │ ← ALU performs operation │ │ ← Or memory access occurs └─────┬─────┘ │ ▼ ┌───────────┐ │ STORE │ ← Result saved (optional) └─────┬─────┘ │ ▼ ┌────────────────┐ │ Repeat for next│ │ instruction │ └────────────────┘

📋 Special Purpose Registers

Special Purpose Registers (SPRs) are CPU registers that perform specific control or tracking functions during instruction execution.

Common Special Purpose Registers

Register Full Name Purpose
PC Program Counter Holds address of next instruction to fetch
IR Instruction Register Holds current instruction being executed
MAR Memory Address Register Holds memory address to read from or write to
MBR/MDR Memory Buffer/Data Register Holds data read from or to be written to memory
ACC Accumulator Stores intermediate results of ALU operations
SR/FLAGS Status Register Holds flags (Zero, Carry, Sign, Overflow)
SP Stack Pointer Points to top of stack in memory
PSW Program Status Word Combines status register and control info

Detailed Explanations

Program Counter (PC)

  • Automatically increments after each instruction
  • Controls the flow of execution
  • Can be modified by jump/branch instructions

Instruction Register (IR)

  • Holds current instruction after it's fetched
  • Sent to decoder for execution
  • Contains opcode and operands

Memory Address Register (MAR)

  • Used to access memory
  • Specifies WHERE in memory data is located
  • Connected to address bus

Memory Buffer Register (MBR/MDR)

  • Temporarily stores data being moved to/from memory
  • Connected to data bus
  • Acts as buffer between CPU and memory

Accumulator (ACC)

  • Core register for ALU operations
  • Stores immediate calculation results
  • Common in simple CPU architectures

Status Register (SR/FLAGS)

Common Flags:

  • Zero (Z): Result is zero
  • Carry (C): Arithmetic overflow/carry out
  • Sign (S): Result is negative
  • Overflow (O): Signed overflow occurred
  • Parity (P): Even/odd number of 1s

Used for branching and condition checking in programs

Stack Pointer (SP)

  • Grows or shrinks as values pushed/popped from stack
  • Crucial in function calls and interrupts
  • Points to last item pushed onto stack

Program Status Word (PSW)

  • Combines PC, SR, and other control bits
  • Describes current state of processor
  • Saved during context switches

Register Summary Chart

Abbreviation Function Category
PC Controls instruction sequence Control Register
IR Stores current instruction Control Register
MAR Memory address handling Memory Access
MBR/MDR Memory data handling Memory Access
ACC Stores operation results ALU Register
SR/FLAGS Holds condition flags Status Register
SP Manages call stack Stack Management
PSW Holds processor state Control & Status

💾 Memory & Storage

Types of Memory

1. Flash Memory

Type: Non-volatile memory (retains data without power)

Use: USB drives, SSDs, memory cards, smartphone storage

Features: Can be electrically erased and reprogrammed

Examples: USB pen drives, Solid State Drives, SD cards

Advantages:

  • ✅ Fast read/write speed
  • ✅ Rewritable multiple times
  • ✅ No moving parts (durable)
  • ✅ Low power consumption

2. ROM (Read-Only Memory)

Type: Non-volatile memory with permanent or semi-permanent data

Use: Stores system firmware or bootloader

Types of ROM:

  • Masked ROM: Programmed at factory, cannot be changed
  • PROM: Programmable ROM - can be written once
  • EPROM: Erasable PROM - erased with UV light
  • EEPROM: Electrically erasable and programmable

Advantages:

  • ✅ Retains data when power is off
  • ✅ Used for critical startup code

Limitations:

  • ❌ Limited or no ability to modify (except EEPROM)

3. Firmware

Definition: Software permanently stored in ROM or flash memory

Function: Controls basic hardware operations

Use: Found in computers, printers, routers, smart TVs, smartphones

Examples:

  • BIOS/UEFI firmware in PCs
  • Embedded firmware in appliances and routers

Key Characteristics:

  • ✅ Bridges hardware and software
  • ✅ Stored in ROM or flash
  • ✅ Can sometimes be updated (firmware upgrade)

Relationship Summary

Term What It Is Stored In Editable?
Flash Memory Rewritable non-volatile storage EEPROM, SSD, USBs Yes, multiple times
ROM Memory storing permanent code Factory-programmed chips No (or limited, like EEPROM)
Firmware Software controlling hardware ROM or Flash Memory Sometimes (via update tools)

PC Memory Example

  • 🔹 BIOS/UEFI = Firmware
  • 🔹 Stored in Flash Memory
  • 🔹 Which is a type of ROM

📦 System Software

System software is designed to run a computer's hardware and application programs.

Types of System Software

1. Operating System (OS)

Function: Manages computer hardware, software resources, and provides services for applications

Examples:

  • Windows (10, 11)
  • macOS (Monterey, Ventura, Sonoma)
  • Linux (Ubuntu, Fedora, Debian)
  • Android
  • iOS

2. Device Drivers

Function: Allows OS to communicate with hardware devices

Examples:

  • Printer driver
  • Graphics card driver (NVIDIA, AMD)
  • Sound card driver
  • USB driver
  • Network adapter driver

3. Utility Software

Function: Performs specific tasks to maintain the system

Examples:

  • Antivirus software (Norton, McAfee, Kaspersky)
  • Disk cleanup tools
  • File compression (WinRAR, 7-Zip)
  • Backup software
  • Disk defragmenter
  • System monitors

4. Firmware (BIOS & UEFI)

Function: Low-level software stored in motherboard; starts system and prepares it to load OS

🔹 BIOS (Basic Input/Output System)

  • Legacy firmware interface
  • Runs POST (Power-On Self Test)
  • Uses MBR (Master Boot Record) for booting
  • Keyboard-only interface
  • Limited hardware support (usually under 2TB drives)
  • Booting takes more time

🔹 UEFI (Unified Extensible Firmware Interface)

  • Modern replacement for BIOS
  • Supports larger drives (up to 9 ZB)
  • Uses GPT (GUID Partition Table)
  • Supports mouse and better graphics interface
  • Secure boot support
  • Faster boot times and better security

Note: Most modern computers use UEFI instead of BIOS

5. Programming Language Translators

Function: Convert high-level code into machine code for CPU execution

Types & Examples:

  • Compiler: Translates entire program at once (C, Java Compiler)
  • Interpreter: Translates line-by-line (Python, JavaScript)
  • Assembler: Converts assembly language to machine code

6. System Management Software

Function: Manages system operations and performance

Examples:

  • Task Manager
  • System monitors
  • Virtualization software (VMware, Hyper-V, VirtualBox)
  • Performance analyzers

Summary Table

Type Function Examples
Operating System Manages hardware & software Windows, Linux, Android
Device Drivers Communicate with hardware Printer, graphics drivers
Utility Software System maintenance Antivirus, Disk Cleanup
Firmware Hardware control at low level BIOS, UEFI, router firmware

📊 Data Representation in Computers

Computers do not understand letters or symbols directly. All data (text, images, sound, video) is represented in binary form (0s and 1s).

1. Number Systems

System Base Digits Used Use
Binary 2 0, 1 Main language of computers
Decimal 10 0–9 Used by humans
Octal 8 0–7 Short-hand for binary
Hexadecimal 16 0–9, A–F Compact binary representation

2. Representation of Different Data Types

A. Numbers

Represented using binary numbers

Example: Decimal 10 = Binary 1010

B. Characters (Text)

Represented using character encoding schemes:

  • ASCII (American Standard Code for Information Interchange)
    Example: 'A' = 65 → Binary: 01000001
  • Unicode (Supports many languages globally)
    Example: 'अ' = U+0905

C. Images

Represented using pixels, each pixel's color stored as binary

  • File formats: JPEG, PNG, BMP, GIF
  • RGB Color Model: Each color uses 8 bits (1 byte) → 24 bits per pixel
    Example: Red = (255, 0, 0), Blue = (0, 0, 255)

D. Audio

Stored as digital samples of sound waves

  • Sample Rate: e.g., 44.1 kHz (CD quality)
  • Bit Depth: e.g., 16-bit, 24-bit
  • Formats: MP3, WAV, AAC, FLAC

E. Video

Combination of images (frames) + audio

  • Stored as compressed binary data streams
  • Formats: MP4, AVI, MKV, MOV
  • Frame Rate: 24fps, 30fps, 60fps

3. Units of Data

Unit Size Equivalent
Bit Smallest unit 0 or 1
Nibble 4 bits Half byte
Byte 8 bits 1 character
Kilobyte (KB) ≈ 1,024 bytes Small text file
Megabyte (MB) ≈ 1,024 KB MP3 song, photo
Gigabyte (GB) ≈ 1,024 MB HD movie, software
Terabyte (TB) ≈ 1,024 GB Large databases
Petabyte (PB) ≈ 1,024 TB Data centers

Why Is Data Representation Important?

  • ✅ Enables storage, processing, and transmission of all data types
  • ✅ Ensures accurate communication between hardware and software
  • ✅ Allows efficient data compression and encoding
  • ✅ Foundation for all digital technologies
