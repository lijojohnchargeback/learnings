📐 Data Structures & Algorithms

Complete DSA guide — data structures, full algorithms with steps and walkthroughs, Big-O, graph algorithms, and problem-solving patterns.

What is DSA?

DSA = Data Structures + Algorithms. A data structure is how you store and organize data. An algorithm is a step-by-step procedure that uses those structures to solve a problem. You pick a structure for access patterns, then an algorithm for the job — search, sort, traverse, or transform.

Left = shapes. Right = recipes. Arrays and hash maps for everyday APIs; trees and graphs when hierarchy or links matter. Search, sort, BFS, and DFS are starter algorithms. Big-O answers: “if input grows 10×, does cost grow 10× or 100×?”

Data structures

Array, linked list, stack, queue, hash map, tree, graph — choose by how you insert, find, and update.

Algorithms

Search, sort, traverse, recurse, and optimize. Same problem can have many recipes with different costs.

Complexity

Big-O describes how time and memory grow with input size n — the language of tradeoffs.

PieceMeaningStarter examples
Data structuresHow data is laid out and accessedArray, list, stack, queue, hash map, tree, graph
AlgorithmsSteps that compute a resultLinear/binary search, sort, recursion, BFS/DFS
Complexity (Big-O)How time/memory grow with nO(1), O(log n), O(n), O(n log n), O(n²)

Why it matters in production

  • Idempotency keys and caches → hash maps
  • Job workers and BFS → queues
  • Undo, call stacks, DFS → stacks
  • Org charts, file trees, indexes → trees
  • Social graphs, dependency graphs → graphs

Big-O complexity

Big-O describes the worst-case growth rate of an algorithm as input size n gets large. Constants and lower-order terms are dropped so you can compare shapes of growth.

Flatter is better as n grows. O(1) and O(log n) stay cheap. O(n²) and exponential blow up quickly — fine for tiny n, dangerous at scale.
NotationNameIntuitionExample
O(1)ConstantSame cost regardless of nArray index, hash map get (avg)
O(log n)LogarithmicHalves the problem each stepBinary search
O(n)LinearOne pass over the inputLinear search, simple loop
O(n log n)LinearithmicTypical efficient sortMerge sort, heap sort
O(n²)QuadraticNested loops over nBubble / selection sort
O(2ⁿ)ExponentialExplodes with nNaive recursive subsets

Time complexity

How the number of operations grows. Dominates latency when data is large.

Space complexity

Extra memory beyond the input. Recursion depth, copies, and DP tables all count.

Practical tip

Big-O ignores constants. An O(n) algorithm with heavy work per element can lose to a tight O(n log n) for moderate n. Measure hot paths — use Big-O to eliminate clearly bad designs first.

Arrays & linked lists

Both store sequences. Arrays pack elements in contiguous memory; linked lists chain nodes with pointers.

Array = fast index, costly middle insert. Linked list = cheap insert/delete at a known node, slow random access.
OperationArray (dynamic)Singly linked list
Access by indexO(1)O(n)
Search (unsorted)O(n)O(n)
Insert / delete at endAmortized O(1)*O(1) with tail / O(n) without
Insert / delete in middleO(n) shiftsO(1) if you hold the node

*Dynamic arrays occasionally resize (copy) — amortized constant for append.

When to use which

  • Array / slice / list (Python/JS): default choice — cache-friendly, simple indexing
  • Linked list: frequent insert/delete in the middle when you already have a node pointer; rare in high-level app code
  • Deque: fast push/pop at both ends (queues, sliding windows)

Stacks & queues

Restricted access sequences. A stack is LIFO (last in, first out). A queue is FIFO (first in, first out).

Stack = undo / call frames / DFS. Queue = task workers / BFS / fair scheduling.

Stack

  • push / pop / peek → O(1)
  • Function call stack
  • Undo history, matching brackets
  • DFS (explicit stack)

Queue

  • enqueue / dequeue → O(1)
  • Job / message workers
  • BFS level-order traversal
  • Print / request buffering

Mental models

Stack: a pile of plates — you only touch the top plate.

Queue: a ticket line — the person who arrived first is served first.

Hash tables

A hash table (dict / Map / object) maps keys to values in average O(1) time by hashing the key into a bucket index.

Hash → bucket → value. Collisions are normal; chaining or open addressing resolves them. Worst case degrades toward O(n) if everything collides.
OperationAverageWorst
InsertO(1)O(n)
LookupO(1)O(n)
DeleteO(1)O(n)

Production uses

  • Caches and memoization
  • Idempotency / dedupe keys
  • Counting frequencies (word count)
  • Tool registries and config maps
  • Set membership tests

Gotchas

  • Keys must be hashable / stable (mutable keys break lookups)
  • Order is not sorted (use a tree map / sorted structure if you need order)
  • Hash floods and bad hash functions hurt — language runtimes mitigate this

Trees

A tree is a hierarchy: one root, children, no cycles. A binary search tree (BST) keeps left < parent < right so search can be logarithmic when balanced.

Balanced BST ≈ O(log n) search/insert. Skewed trees become O(n) — like a linked list. Self-balancing trees (AVL, red-black) keep height small.

Common tree types

TypeIdeaUse
Binary treeEach node ≤ 2 childrenExpression trees, heaps
BSTOrdered binary treeSorted sets/maps
HeapParent ≥ or ≤ childrenPriority queues
TriePrefix tree of charactersAutocomplete, dictionaries
B-Tree / B+Wide balanced treeDatabase / filesystem indexes

Traversals

  • Pre-order: node → left → right (copy / serialize)
  • In-order: left → node → right (BST sorted order)
  • Post-order: left → right → node (delete / evaluate)
  • Level-order: BFS by depth (pretty print, shortest path in unweighted tree)

Graphs

A graph is nodes (vertices) plus edges. Edges may be directed or undirected, weighted or unweighted. Represented as adjacency lists (common) or matrices.

BFS = closest first (queue). DFS = deep dive (stack/recursion). Same graph, different visit order and use cases.
TraversalStructureGood for
BFSQueueShortest path in unweighted graphs, level order
DFSStack / recursionCycle detect, topological ideas, connectivity, backtracking

Where graphs show up

  • Social networks and recommendations
  • Service dependency / package graphs
  • Routing and maps (weighted → Dijkstra / A*)
  • Knowledge graphs and RAG entity links

Searching — overview

Find a target in a collection. Choice depends on whether data is sorted and how often you search.

Unsorted → linear O(n). Sorted → binary O(log n). If you search often, pay once to sort or keep a hash set / tree.

Linear search (full algorithm)

Scan from left to right until the target is found or the list ends. Works on any sequence — sorted or not.

Idea

  1. Start at index 0
  2. Compare a[i] with target
  3. If equal → return index
  4. Else increment i and repeat
  5. If loop ends → not found

Walkthrough

Array: [4, 2, 9, 7, 1] · Target: 7

Pseudocode

function linearSearch(a, target): for i from 0 to length(a) - 1: if a[i] == target: return i return -1 // not found
BestAverageWorstSpace
O(1) — first elementO(n)O(n) — last / missingO(1)

When to use

  • Small lists, or unsorted data you will search once
  • Streaming / one-pass checks
  • Not for large repeated lookups (prefer hash / binary)

Binary search (full algorithm)

On a sorted array, repeatedly discard half of the remaining range by comparing the middle element to the target.

Idea

  1. Set lo = 0, hi = n - 1
  2. While lo ≤ hi: compute mid = (lo + hi) // 2
  3. If a[mid] == target → found
  4. If a[mid] < target → search right half (lo = mid + 1)
  5. Else search left half (hi = mid - 1)

Walkthrough

Sorted array: [1, 3, 5, 7, 9, 11, 13] · Target: 9

Steplohimida[mid]Decision
106377 < 9 → lo = 4
24651111 > 9 → hi = 4
34449Found at index 4

Pseudocode (iterative)

function binarySearch(a, target): lo = 0 hi = length(a) - 1 while lo <= hi: mid = lo + (hi - lo) // 2 // avoids overflow style if a[mid] == target: return mid else if a[mid] < target: lo = mid + 1 else: hi = mid - 1 return -1

Pseudocode (recursive)

function binarySearchRec(a, target, lo, hi): if lo > hi: return -1 mid = lo + (hi - lo) // 2 if a[mid] == target: return mid if a[mid] < target: return binarySearchRec(a, target, mid + 1, hi) return binarySearchRec(a, target, lo, mid - 1)
TimeSpace (iterative)Space (recursive)Prerequisite
O(log n)O(1)O(log n) stackSorted ascending (or known order)

Common bugs

  • Array not sorted → wrong answers
  • Infinite loop if lo/hi updates wrong (mid+1 / mid-1)
  • Off-by-one on empty array or single element

Bubble sort (full algorithm)

Repeatedly compare adjacent pairs and swap if out of order. Largest values “bubble” to the end each pass.

Steps

  1. For pass i = 0 .. n-2:
  2. Scan j = 0 .. n-2-i
  3. If a[j] > a[j+1] → swap them
  4. Optional: if a pass had zero swaps → already sorted, stop early

Walkthrough

Start: [5, 1, 4, 2]

PassComparisons / swapsArray after pass
15↔1, 5↔4, 5↔2[1, 4, 2, 5]
24↔2[1, 2, 4, 5]
3no swaps[1, 2, 4, 5] done

Pseudocode

function bubbleSort(a): n = length(a) for i from 0 to n - 2: swapped = false for j from 0 to n - 2 - i: if a[j] > a[j + 1]: swap(a[j], a[j + 1]) swapped = true if not swapped: break

Use for: teaching only. Too slow for large n. Stable, in-place.

Selection sort (full algorithm)

For each position, find the minimum in the unsorted suffix and swap it into place.

Steps

  1. For i = 0 .. n-2: assume min index = i
  2. Scan j = i+1 .. n-1; update min index if smaller
  3. Swap a[i] with a[minIndex]

Walkthrough

Pseudocode

function selectionSort(a): n = length(a) for i from 0 to n - 2: minIndex = i for j from i + 1 to n - 1: if a[j] < a[minIndex]: minIndex = j swap(a[i], a[minIndex])

Insertion sort (full algorithm)

Build a sorted prefix. Take the next element and insert it into the correct place by shifting larger elements right.

Steps

  1. For i = 1 .. n-1: let key = a[i]
  2. Shift elements a[j] > key one step right while j ≥ 0
  3. Place key in the opened slot

Walkthrough

Start: [3, 1, 4, 2]

ikeyActionArray
11Shift 3 right; place 1[1, 3, 4, 2]
24Already in place[1, 3, 4, 2]
32Shift 4,3; place 2[1, 2, 3, 4]

Pseudocode

function insertionSort(a): for i from 1 to length(a) - 1: key = a[i] j = i - 1 while j >= 0 and a[j] > key: a[j + 1] = a[j] j = j - 1 a[j + 1] = key

Best O(n) on nearly sorted data. Used inside Timsort for small runs. Stable, in-place.

Merge sort (full algorithm)

Divide and conquer: split the array in half, sort each half recursively, then merge two sorted halves into one sorted array.

Steps

  1. Base case: length ≤ 1 → already sorted
  2. Divide: mid = n/2; left = a[0..mid), right = a[mid..n)
  3. Conquer: recursively merge-sort left and right
  4. Merge: walk both halves with two pointers; always take the smaller head into the result

Quick sort (full algorithm)

Pick a pivot, partition so smaller elements go left and larger go right, then recursively sort both sides.

Lomuto partition (common teaching version)

  1. Choose pivot = last element a[hi]
  2. Maintain boundary i for “less than pivot” region
  3. Scan j from lo to hi-1; if a[j] < pivot, swap into place and bump i
  4. Swap pivot into index i; return pivot index
  5. Recurse on left of pivot and right of pivot

Walkthrough (one partition)

Array: [3, 7, 1, 4] · pivot = 4

ja[j]ActionArray
033 < 4 → swap with i, i++[3, 7, 1, 4]
177 ≥ 4 → skip[3, 7, 1, 4]
211 < 4 → swap[3, 1, 7, 4]
——Place pivot[3, 1, 4, 7]

Pivot at index 2. Recurse on [3, 1] and [7].

Pseudocode

function quickSort(a, lo, hi): if lo >= hi: return p = partition(a, lo, hi) quickSort(a, lo, p - 1) quickSort(a, p + 1, hi) function partition(a, lo, hi): pivot = a[hi] i = lo for j from lo to hi - 1: if a[j] < pivot: swap(a[i], a[j]) i += 1 swap(a[i], a[hi]) return i

Worst case O(n²)

Already sorted data + always picking last element as pivot → unbalanced partitions. Fix: random pivot, median-of-three, or introsort (quick + heap fallback).

Heap sort (full algorithm)

Use a max-heap: parent ≥ children. Build a heap, then repeatedly extract the max into the sorted suffix.

Steps

  1. Heapify: build max-heap in-place (bottom-up from last parent)
  2. For end = n−1 down to 1:
  3. Swap root (max) with a[end]
  4. Reduce heap size by 1; sift-down the new root

Index math (0-based array heap)

  • Parent of i: (i - 1) // 2
  • Left child: 2*i + 1
  • Right child: 2*i + 2

Pseudocode (sift-down + sort)

function siftDown(a, start, end): root = start while 2*root + 1 <= end: child = 2*root + 1 swapIdx = root if a[swapIdx] < a[child]: swapIdx = child if child + 1 <= end and a[swapIdx] < a[child + 1]: swapIdx = child + 1 if swapIdx == root: return swap(a[root], a[swapIdx]) root = swapIdx function heapSort(a): n = length(a) // build heap for start from (n // 2 - 1) down to 0: siftDown(a, start, n - 1) // extract max for end from n - 1 down to 1: swap(a[0], a[end]) siftDown(a, 0, end - 1)
TimeSpaceStable?Notes
O(n log n)O(1)NoGuaranteed bound; often slower than well-tuned quicksort in practice

BFS — Breadth-First Search (full algorithm)

Explore a graph level by level using a queue. First time you reach a node is a shortest path in an unweighted graph.

BFS uses a queue. Visit neighbors before going deeper — closest nodes first.

Steps

  1. Enqueue start; mark visited
  2. While queue not empty: dequeue u
  3. Process u (record order / distance)
  4. For each neighbor v of u: if not visited → mark, enqueue, set parent/dist

Walkthrough

Visit order: A, B, C, D. Distances from A: B=1, C=1, D=2.

Pseudocode

function BFS(graph, start): queue = [start] visited = {start} order = [] while queue is not empty: u = queue.dequeue() order.append(u) for v in graph.neighbors(u): if v not in visited: visited.add(v) queue.enqueue(v) return order

DFS — Depth-First Search (full algorithm)

Go as deep as possible along one path, then backtrack. Implement with recursion or an explicit stack.

Steps (recursive)

  1. Mark current node visited; process it
  2. For each unvisited neighbor: recurse
  3. Backtrack when no unvisited neighbors remain

Walkthrough

Same graph as BFS. One possible DFS from A (neighbors ordered B then C): A → B → D → C.

Enter DA, B, D{A,B,D}
Backtrack to B, AA{A,B,D}
Enter CA, C{A,B,D,C}

Pseudocode (recursive)

function DFS(graph, u, visited, order): visited.add(u) order.append(u) for v in graph.neighbors(u): if v not in visited: DFS(graph, v, visited, order) function DFSStart(graph, start): visited = {} order = [] DFS(graph, start, visited, order) return order

Pseudocode (iterative stack)

function DFSIter(graph, start): stack = [start] visited = {} order = [] while stack is not empty: u = stack.pop() if u in visited: continue visited.add(u) order.append(u) for v in reverse(graph.neighbors(u)): // optional order control if v not in visited: stack.push(v) return order

Dijkstra’s algorithm (full details)

Shortest paths from a source in a graph with non-negative edge weights. Greedy: always expand the unsettled node with the smallest known distance.

Steps

  1. Set dist[start] = 0, all others = ∞
  2. Put all nodes in a priority queue keyed by distance (or start with only start)
  3. While PQ not empty: pop node u with smallest dist
  4. For each edge u → v with weight w: if dist[u] + w < dist[v] → relax and update PQ

Walkthrough

Edges: A→B (4), A→C (2), C→B (1), B→D (5), C→D (8) · Start A

B (3)D=min(10,3+5)=80, 3, 2, 8
D (8)—done

Shortest A→D = 8 via A→C→B→D.

Common algorithm patterns

Most interview and production problems are combinations of a few patterns. Learn the shapes, then adapt.

Pattern first, code second. Name the pattern out loud — it narrows the approach before you touch the keyboard.

Two pointers (full algorithm pattern)

Two indices move through a structure (often from ends toward center, or both forward at different speeds).

Classic: pair sum in sorted array

Find two numbers that add to target.

  1. lo = 0, hi = n-1
  2. While lo < hi: sum = a[lo]+a[hi]
  3. If sum == target → found
  4. If sum < target → lo++
  5. If sum > target → hi--

Pseudocode

function twoSumSorted(a, target): lo = 0 hi = length(a) - 1 while lo < hi: s = a[lo] + a[hi] if s == target: return (lo, hi) else if s < target: lo += 1 else: hi -= 1 return not found

Time O(n), space O(1). Also used for: palindrome check, remove duplicates in-place, container-with-most-water.

Sliding window (full algorithm pattern)

Maintain a contiguous window [left, right] that grows/shrinks to satisfy a constraint while tracking a metric (sum, distinct count, etc.).

Classic: longest substring with ≤ k distinct characters

  1. Expand right; add s[right] into a frequency map
  2. While distinct count > k: remove s[left], left++
  3. Update max length = right − left + 1

Pseudocode

function longestWithKDistinct(s, k): freq = {} left = 0 best = 0 for right from 0 to length(s) - 1: freq[s[right]] = freq.get(s[right], 0) + 1 while number of keys in freq > k: freq[s[left]] -= 1 if freq[s[left]] == 0: delete freq[s[left]] left += 1 best = max(best, right - left + 1) return best

Time O(n) for typical char/ascii alphabets. Also used for: max sum subarray of size k, minimum window substring.

Recursion (full details)

A function solves a problem by calling itself on a smaller instance until a base case.

Checklist

  1. Base case — when to stop
  2. Recursive case — shrink toward the base
  3. Stack depth — O(depth) extra space
  4. Memoize — if the same inputs repeat (path to DP)

Example: factorial

function factorial(n): if n <= 1: // base return 1 return n * factorial(n - 1) // recursive

Example: binary tree in-order

function inorder(node): if node is null: return inorder(node.left) visit(node) inorder(node.right)

Naive Fibonacci trap

fib(n) = fib(n-1) + fib(n-2) without memo is O(2ⁿ). Same recurrence with memo / DP is O(n).

Dynamic programming (full details)

DP solves problems with overlapping subproblems and optimal substructure by storing answers instead of recomputing.

Steps to design a DP

  1. Define state: what does dp[i] / dp[i][j] mean?
  2. Write recurrence relating states
  3. Identify base cases
  4. Choose order: bottom-up (iterate) or top-down (memoized recursion)
  5. Extract the answer from the table / memo

Example: Fibonacci bottom-up

function fib(n): if n <= 1: return n dp = array of size n + 1 dp[0] = 0 dp[1] = 1 for i from 2 to n: dp[i] = dp[i - 1] + dp[i - 2] return dp[n] // Time O(n), Space O(n) — can optimize to O(1) with two variables

Example: 0/1 knapsack idea

For each item, either skip it or take it if weight allows:

dp[i][w] = max( dp[i-1][w], // skip item i dp[i-1][w - weight[i]] + value[i] // take item i (if w allows) )
StyleHowPros
Top-downRecursion + memo mapOnly computes needed states
Bottom-upIterate tableClear complexity; no stack risk

Greedy algorithms (full details)

At each step, pick the locally best option and never undo it. Works only when a greedy choice property holds.

Classic: activity / interval scheduling

  1. Sort intervals by end time
  2. Pick the first interval; then repeatedly pick the next that starts after the last chosen end

Pseudocode

function maxActivities(intervals): sort intervals by end ascending chosen = [] currentEnd = -∞ for (start, end) in intervals: if start >= currentEnd: chosen.append((start, end)) currentEnd = end return chosen

Other greedy examples

  • Coin change with canonical denominations (not always optimal for arbitrary coins → then DP)
  • Huffman coding
  • Dijkstra (greedy on distances with non-negative weights)

If you cannot prove the greedy choice is safe, default to DP or exhaustive search with pruning.
