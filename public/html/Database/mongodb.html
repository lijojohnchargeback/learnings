🍃 MongoDB Complete Guide

NoSQL Document Database

📚 MongoDB Architecture & The CAP Theorem

MongoDB is a distributed, document-oriented database. Unlike relational databases that use tables and rows, MongoDB stores data in BSON (Binary JSON), allowing for hierarchical, nested data structures.

The Architectural Perspective: CAP Theorem

In the CAP Theorem (Consistency, Availability, Partition Tolerance), MongoDB is primarily a CP (Consistent and Partition Tolerant) system. While it offers high availability through Replica Sets, in the event of a network partition, it prioritizes data consistency by pausing writes until a primary is elected.

Senior Tip: Why NoSQL?

Don't choose MongoDB just because it's "schemaless." Choose it when your data model is hierarchical, when you need horizontal scalability (Sharding), or when your application requires rapid iteration where a rigid relational schema becomes a bottleneck. Remember: Schemaless doesn't mean "no schema design"—it means "flexible schema."

Core Concepts

  • 🗂️ Database: Container for collections
  • 📂 Collection: Group of documents (like tables)
  • 📄 Document: Single record (like row)
  • 🔑 Field: Key-value pair in document (like column)

BSON Data Format

MongoDB uses BSON (Binary JSON) which extends JSON with additional types:

{ "_id": ObjectId("507f1f77bcf86cd799439011"), "name": "John Doe", "age": 30, "email": "john@example.com", "createdAt": ISODate("2024-01-01T00:00:00Z"), "hobbies": ["reading", "gaming"], "address": { "city": "New York", "zip": "10001" } }

🔧 CRUD Operations

Database & Collection Commands

// Show all databases show dbs // Switch to/create database use myDatabase // Show current database db // Show collections show collections // Drop database db.dropDatabase() // Drop collection db.users.drop()

Create - Insert Operations

// Insert one document db.users.insertOne({ name: "John Doe", age: 30, email: "john@example.com" }); // Insert multiple documents db.users.insertMany([ { name: "Alice", age: 25, city: "NYC" }, { name: "Bob", age: 35, city: "LA" }, { name: "Charlie", age: 28, city: "Chicago" } ]);

Read - Find Operations

// Find all documents db.users.find() // Find with filter db.users.find({ age: 30 }) // Find one document db.users.findOne({ name: "John Doe" }) // Projection (select specific fields) db.users.find( { age: { $gt: 25 } }, { name: 1, age: 1, _id: 0 } ) // Sort and limit db.users.find().sort({ age: -1 }).limit(5) // Count documents db.users.countDocuments({ age: { $gte: 30 } })

Update Operations

// Update one document db.users.updateOne( { name: "John Doe" }, { $set: { age: 31, city: "Boston" } } ) // Update multiple documents db.users.updateMany( { age: { $lt: 30 } }, { $set: { status: "young" } } ) // Replace entire document db.users.replaceOne( { name: "Bob" }, { name: "Robert", age: 36, city: "SF" } ) // Upsert (update or insert) db.users.updateOne( { email: "new@example.com" }, { $set: { name: "New User", age: 25 } }, { upsert: true } )

Update Operators

// $set - Set field value db.users.updateOne( { name: "John" }, { $set: { age: 32 } } ) // $inc - Increment value db.users.updateOne( { name: "John" }, { $inc: { age: 1 } } ) // $unset - Remove field db.users.updateOne( { name: "John" }, { $unset: { middleName: "" } } ) // $push - Add to array db.users.updateOne( { name: "John" }, { $push: { hobbies: "reading" } } ) // $pull - Remove from array db.users.updateOne( { name: "John" }, { $pull: { hobbies: "gaming" } } )

Delete Operations

// Delete one document db.users.deleteOne({ name: "John Doe" }) // Delete multiple documents db.users.deleteMany({ age: { $lt: 25 } }) // Delete all documents db.users.deleteMany({})

🔍 Query Operators

Comparison Operators

Operator Description Example
$eq Equal to {age: {$eq: 30}}
$gt Greater than {age: {$gt: 25}}
$gte Greater than or equal {age: {$gte: 30}}
$lt Less than {age: {$lt: 40}}
$lte Less than or equal {age: {$lte: 35}}
$ne Not equal {status: {$ne: "inactive"}}
$in In array {city: {$in: ["NYC", "LA"]}}

Logical Operators

// $and - All conditions must be true db.users.find({ $and: [ { age: { $gte: 25 } }, { city: "NYC" } ] }) // $or - At least one condition must be true db.users.find({ $or: [ { age: { $lt: 25 } }, { city: "LA" } ] }) // $not - Inverts condition db.users.find({ age: { $not: { $lt: 30 } } }) // $nor - No condition is true db.users.find({ $nor: [ { age: { $lt: 20 } }, { status: "banned" } ] })

Array Operators

// $elemMatch - Match array element db.users.find({ hobbies: { $elemMatch: { title: "sports", frequency: { $gte: 3 } } } }) // $size - Array length db.users.find({ hobbies: { $size: 3 } }) // $all - Contains all elements db.users.find({ tags: { $all: ["mongodb", "database"] } })

Real-World Query Examples

// Find users aged 25-35 in NYC db.users.find({ age: { $gte: 25, $lte: 35 }, city: "NYC" }) // Find active users with email db.users.find({ status: "active", email: { $exists: true, $ne: null } }) // Search by regex (pattern matching) db.users.find({ email: { $regex: /@gmail\.com$/ } })

📊 Aggregation Framework

The aggregation pipeline processes documents through multiple stages to transform and analyze data. It's a framework for data aggregation modeled on the concept of data processing pipelines.

How Aggregation Pipelines Work:

  1. Each stage performs an operation on input documents (filter, group, calculate)
  2. Documents output from a stage are passed to the next stage
  3. Can return results for groups of documents (totals, averages, min, max)

Pipeline Stages Overview

Stage Description Use Case
$match Filter documents (like find) Reduce documents early in pipeline
$group Group documents by field Aggregate data, count, sum, average
$project Select/reshape fields Include/exclude fields, create computed fields
$sort Sort documents Order results by field(s)
$limit Limit number of documents Get top N results
$skip Skip documents Pagination
$unwind Deconstruct array fields Create document per array element
$lookup Join with another collection Left outer join
$addFields Add new fields Computed fields, transformations
$count Count documents Get total count
$bucket Categorize into buckets Histogram, grouping by ranges
$unset Remove fields Exclude fields from output

1. $match - Filter Documents

Filters documents to pass only matching ones to next stage. Should be used early in pipeline.

// Basic match db.persons.aggregate([ { $match: { city: "New York" } } ]) // Match with comparison operator db.persons.aggregate([ { $match: { age: { $gt: 25 } } } ]) // Match with multiple conditions db.persons.aggregate([ { $match: { $and: [ { age: { $gt: 25 } }, { gender: "female" } ] } } ])

2. $group - Group and Aggregate

Groups documents by specified field and performs aggregations.

// Group by single field db.persons.aggregate([ { $group: { _id: "$userId" } } ]) // Count documents per group db.persons.aggregate([ { $group: { _id: "$city", count: { $sum: 1 } } } ]) // Multiple aggregations db.persons.aggregate([ { $group: { _id: "$city", count: { $sum: 1 }, avgAge: { $avg: "$age" }, minAge: { $min: "$age" }, maxAge: { $max: "$age" } } } ]) // Group by multiple fields db.persons.aggregate([ { $group: { _id: { age: "$age", gender: "$gender" }, count: { $sum: 1 } } } ]) // Group with embedded field db.persons.aggregate([ { $group: { _id: "$company.location", total: { $sum: "$price" } } } ])

3. $project - Reshape Documents

Include, exclude, or add computed fields. 1 = include, 0 = exclude.

// Include specific fields db.persons.aggregate([ { $project: { name: 1, "company.title": 1 } } ]) // Exclude _id db.persons.aggregate([ { $project: { _id: 0, name: 1, age: 1 } } ]) // Exclude fields (include everything else) db.persons.aggregate([ { $project: { name: 0, "company.title": 0 } } ]) // Add computed field db.persons.aggregate([ { $project: { name: 1, age: 1, isActive: true } } ]) // Rename field db.persons.aggregate([ { $project: { age: 1, company: "$company.title" } } ]) // Transform with expression db.persons.aggregate([ { $project: { name: { $toUpper: "$name" }, age: 1 } } ])

4. $addFields - Add New Fields

Add fields with default values or computed values without removing other fields.

// Add simple field db.collection.aggregate([ { $addFields: { status: "active", category: "premium" } } ]) // Add embedded field db.collection.aggregate([ { $addFields: { "address.country": "USA" } } ]) // Overwrite existing field db.collection.aggregate([ { $addFields: { age: { $add: ["$age", 1] } } } ]) // Replace field with another field's value db.posts.aggregate([ { $addFields: { _id: "$body", item: "$_id" } } ])

5. $sort - Sort Documents

Sort documents by field(s). 1 = ascending, -1 = descending.

// Sort by single field db.persons.aggregate([ { $sort: { age: -1 } } ]) // Sort by multiple fields db.persons.aggregate([ { $sort: { age: 1, name: 1 } } ])

6. $limit - Limit Results

// Return first 100 documents db.persons.aggregate([ { $limit: 100 } ]) // Combined pipeline: filter, sort, limit db.persons.aggregate([ { $match: { age: { $gt: 20 } } }, { $sort: { age: -1 } }, { $limit: 10 }, { $project: { name: 1, age: 1 } } ])

7. $skip - Skip Documents

// Skip first 20 documents (pagination) db.persons.aggregate([ { $skip: 20 }, { $limit: 10 } ])

8. $unwind - Deconstruct Arrays

Creates a new document for each element in an array field.

// Basic unwind db.persons.aggregate([ { $unwind: "$tags" }, { $limit: 100 }, { $project: { name: 1, gender: 1, tags: 1 } } ]) // Unwind with options db.persons.aggregate([ { $unwind: { path: "$hobbies", includeArrayIndex: "arrayIndex", preserveNullAndEmptyArrays: true } } ]) // Unwind then group db.persons.aggregate([ { $unwind: "$tags" }, { $group: { _id: { age: "$age", name: "$name", tags: "$tags" } } } ])

9. $count - Count Documents

// Count all documents db.persons.aggregate([ { $count: "allDocumentCount" } ]) // Count specific field db.persons.aggregate([ { $count: "totalCountries" } ]) // Count after filtering db.persons.aggregate([ { $match: { age: { $gt: 25 } } }, { $count: "usersOver25" } ]) // Alternative count methods db.persons.aggregate([]).toArray().length db.persons.aggregate([]).itcount()

10. $unset - Remove Fields

// Remove single field db.unwinds.aggregate([ { $unset: "name" } ]) // Remove multiple fields db.unwinds.aggregate([ { $unset: ["name", "_id"] } ]) // Remove embedded document fields db.unwinds.aggregate([ { $unset: ["name", "_id", "person.age"] } ])

11. $bucket - Categorize into Buckets

Categorizes documents into groups (buckets) based on specified boundaries.

db.artists.aggregate([ { $bucket: { groupBy: "$year_born", boundaries: [1840, 1850, 1860, 1870, 1880], default: "Other", output: { count: { $sum: 1 }, artists: { $push: { name: { $concat: ["$first_name", " ", "$last_name"] }, year_born: "$year_born" } } } } }, { $match: { count: { $gt: 3 } } } ])

Accumulator Operators

Operator Description Example
$sum Sum of values {$sum: "$price"} or {$sum: 1}
$avg Average of values {$avg: "$age"}
$max Maximum value {$max: "$score"}
$min Minimum value {$min: "$score"}
$push Array of all values {$push: "$item"}
$addToSet Array of unique values {$addToSet: "$category"}
$first First value {$first: "$date"}
$last Last value {$last: "$date"}

Accumulator Examples

// Count documents per group db.persons.aggregate([ { $group: { _id: "$favoriteFruit", count: { $sum: 1 } } } ]) // Sum, avg, min, max db.orders.aggregate([ { $group: { _id: "$customer", totalAmount: { $sum: "$amount" }, avgAmount: { $avg: "$amount" }, minAmount: { $min: "$amount" }, maxAmount: { $max: "$amount" } } } ])

Complex Pipeline Examples

Example 1: Sales Report by City

db.orders.aggregate([ // Stage 1: Filter by status { $match: { status: "A" } }, // Stage 2: Group by customer and sum amounts { $group: { _id: "$cust_id", total: { $sum: "$amount" } } }, // Stage 3: Sort by total descending { $sort: { total: -1 } }, // Stage 4: Limit to top 10 { $limit: 10 } ])

Example 2: User Analytics

db.users.aggregate([ // Match active users { $match: { status: "active" } }, // Unwind hobbies array { $unwind: "$hobbies" }, // Group by hobby { $group: { _id: "$hobbies", count: { $sum: 1 }, users: { $push: "$name" } } }, // Sort by count { $sort: { count: -1 } }, // Add percentage field { $addFields: { percentage: { $multiply: [ { $divide: ["$count", 100] }, 100 ] } } } ])

Example 3: Age Demographics

db.persons.aggregate([ // Bucket by age ranges { $bucket: { groupBy: "$age", boundaries: [0, 18, 30, 50, 65, 100], default: "Other", output: { count: { $sum: 1 }, avgAge: { $avg: "$age" }, people: { $push: "$name" } } } } ])

Aggregation Best Practices:

  • ✅ Use $match early to reduce documents
  • ✅ Use indexes for $match and $sort stages
  • ✅ Use $project to reduce document size
  • ✅ Order stages efficiently (filter → project → sort)
  • ✅ Use allowDiskUse: true for large datasets
  • ⚠️ Avoid unnecessary $unwind operations
  • ⚠️ Be mindful of memory limits (100MB per stage)

⚡ Indexing & Performance Optimization

Indexes improve query performance by creating data structures that allow faster searches. Without indexes, MongoDB must perform a collection scan, scanning every document in the collection.

The ESR Rule: Designing Compound Indexes

When creating compound indexes, follow the ESR (Equality, Sort, Range) rule for optimum performance:

  • E (Equality): Fields queried with exact matches (e.g., { status: "A" }) should come first.
  • S (Sort): Fields used for sorting should follow equality fields.
  • R (Range): Fields queried with ranges (e.g., { age: { $gt: 25 } }) should come last.

Senior Perspective: Index Overhead

Every index adds a write performance cost. Each insert, update, and delete must update the B-Tree structure of the index. Always monitor your Execution Plan (explain('executionStats')) to ensure your indexes are actually being used and aren't providing diminishing returns.

Index Commands

// Create single field index db.users.createIndex({ email: 1 }) // Create unique index db.users.createIndex( { email: 1 }, { unique: true } ) // Create compound index db.users.createIndex({ city: 1, age: -1 }) // View all indexes db.users.getIndexes() // Drop index db.users.dropIndex("email_1") // Analyze query performance db.users.find({ email: "test@example.com" }).explain("executionStats")

When to Use Indexes

Create indexes for:

  • Fields frequently used in queries
  • Fields used for sorting
  • Fields used in aggregations
  • Unique constraints (like email)

Index Types

Type Description Use Case
Single Field Index on one field createIndex({email: 1})
Compound Index on multiple fields createIndex({city: 1, age: -1})
Multikey Index on array fields Automatically created for arrays
Text Full-text search createIndex({description: "text"})
Geospatial Location-based queries createIndex({location: "2dsphere"})
TTL Auto-delete documents createIndex({createdAt: 1}, {expiresAfterSeconds: 3600})

📋 Advanced Query Techniques

Embedded Document Queries

// Match entire embedded document db.users.find({ address: { city: "New York", zip: "10001" } }) // Query on nested field (more flexible) db.users.find({ "address.city": "New York" }) // Query with operator on nested field db.users.find({ "address.zipCode": { $gt: 10000 } })

Array Query Techniques

1. Match Exact Array

// Exact match (order and elements matter) db.inventory.find({ tags: ["red", "blank"] }) // Contains all elements (order doesn't matter) db.inventory.find({ tags: { $all: ["red", "blank"] } })

2. Query Array for Element

// Contains at least one element db.inventory.find({ tags: "red" }) // Array element meets condition db.inventory.find({ dim_cm: { $gt: 25 } })

3. Multiple Conditions on Array

// Any element matches either condition db.inventory.find({ dim_cm: { $gt: 15, $lt: 20 } }) // Single element matches both conditions db.inventory.find({ dim_cm: { $elemMatch: { $gt: 22, $lt: 30 } } })

4. Query by Array Index

// Query second element in array db.inventory.find({ "dim_cm.1": { $gt: 25 } }) // Query array length db.inventory.find({ tags: { $size: 3 } })

Array of Embedded Documents

// Match embedded document in array db.inventory.find({ instock: { warehouse: "A", qty: 5 } }) // Query field in embedded document db.inventory.find({ "instock.qty": { $lte: 20 } }) // Use array index db.inventory.find({ "instock.0.qty": { $lte: 20 } }) // Single document meets multiple conditions db.inventory.find({ instock: { $elemMatch: { qty: 5, warehouse: "A" } } })

Null and Missing Fields

// Equality filter (matches null and missing) db.inventory.find({ item: null }) // Type check (only null values) db.inventory.find({ item: { $type: 10 } }) // Existence check (field doesn't exist) db.inventory.find({ item: { $exists: false } })

Projection Advanced

// Return specific fields db.inventory.find( { status: "A" }, { item: 1, status: 1 } ) // Suppress specific fields db.inventory.find( { status: "A" }, { status: 0, instock: 0 } ) // Return specific embedded fields db.inventory.find( { status: "A" }, { item: 1, "size.uom": 1 } ) // Project specific array elements ($slice) db.inventory.find( { status: "A" }, { item: 1, instock: { $slice: -1 } } )

🔄 Replication & High Availability

A replica set is a group of MongoDB servers that maintain the same data set, providing redundancy and high availability.

Consistency vs. Latency: Tuning the Knobs

To control the trade-off between consistency and latency, MongoDB provides two critical settings:

  • Write Concern: (e.g., w: "majority") Defines how many members must acknowledge a write before it is considered successful. Senior Tip: Always use "majority" for critical data to prevent "rollback" during failovers.
  • Read Preference: (e.g., primaryPreferred, secondary) Defines where the driver reads data from. Reading from secondaries increases throughput but risks stale reads.

Senior Perspective: The Oplog Mechanics

Replication is asynchronous. It works via the Oplog (Operations Log), a capped collection that stores a rolling record of all data modifications. Secondaries tail this log and apply the changes. If a secondary falls too far behind the primary's Oplog (e.g., during a massive bulk write), it may go into Recovering state and require a full resync.

Benefits of Replica Sets

Benefit Description
High Availability Automatic failover ensures uptime
Data Redundancy Multiple copies protect against data loss
Read Scaling Distribute reads across secondaries
Disaster Recovery Backup nodes in different datacenters
Zero Downtime Maintenance Update nodes one at a time

Read Preference

// Read from primary (default) db.users.find().readPref("primary") // Read from primary preferred db.users.find().readPref("primaryPreferred") // Read from secondary db.users.find().readPref("secondary") // Read from secondary preferred db.users.find().readPref("secondaryPreferred") // Read from nearest node db.users.find().readPref("nearest")

📦 Sharding - Horizontal Scaling

Sharding is MongoDB's approach to meeting the demands of data growth by distributing data across multiple servers.

Sharding Components

  • 🔹 Shards: Each shard contains a subset of the data (can be replica set)
  • 🔹 Mongos: Query router that directs operations to appropriate shards
  • 🔹 Config Servers: Store metadata and configuration settings

Shard Key

The shard key determines how data is distributed across shards.

Shard Key Selection is Critical:

  • ✅ Choose fields with high cardinality
  • ✅ Ensure even data distribution
  • ✅ Consider query patterns
  • ⚠️ Shard key cannot be changed after sharding
  • ⚠️ Poor shard key leads to performance issues

Sharding Strategies

Strategy Description Best For
Range-based Divide data by shard key ranges Ordered data, range queries
Hash-based Hash shard key for distribution Even distribution, random access
Zone-based Associate data ranges with specific shards Geographic distribution

When to Shard

  • 📊 Data size exceeds single server capacity
  • 📊 Working set exceeds RAM
  • 📊 Write throughput exceeds single server
  • 📊 Need to distribute data geographically

💳 Transactions

Multi-document transactions allow you to execute multiple operations atomically.

ACID Properties

  • ✅ Atomicity: All operations succeed or all fail
  • ✅ Consistency: Data remains valid
  • ✅ Isolation: Concurrent transactions don't interfere
  • ✅ Durability: Committed data persists

Transaction Example

// Start session const session = db.getMongo().startSession(); // Start transaction session.startTransaction(); try { // Perform operations db.accounts.updateOne( { _id: "account1" }, { $inc: { balance: -100 } }, { session } ); db.accounts.updateOne( { _id: "account2" }, { $inc: { balance: 100 } }, { session } ); // Commit transaction session.commitTransaction(); } catch (error) { // Abort on error session.abortTransaction(); } finally { session.endSession(); }

Transaction Considerations:

  • ⚠️ Use only when necessary (performance overhead)
  • ⚠️ Requires replica set or sharded cluster
  • ⚠️ Keep transactions short
  • ⚠️ Document-level atomicity is often sufficient

Document-Level Atomicity

MongoDB provides atomicity at the document level by default:

// This operation is atomic db.users.updateOne( { _id: 1 }, { $set: { name: "John" }, $inc: { age: 1 }, $push: { hobbies: "reading" } } )

🌍 Geospatial Queries

MongoDB supports geospatial queries for location-based data.

GeoJSON Format

// Store location as GeoJSON { name: "Central Park", location: { type: "Point", coordinates: [-73.968285, 40.785091] // [longitude, latitude] } }

Create Geospatial Index

// Create 2dsphere index for GeoJSON db.places.createIndex({ location: "2dsphere" })

Geospatial Query Operators

$near - Find Nearby Locations

// Find places near a point db.places.find({ location: { $near: { $geometry: { type: "Point", coordinates: [-73.968285, 40.785091] }, $maxDistance: 5000, // 5km in meters $minDistance: 1000 // 1km minimum } } })

$geoWithin - Find Within Area

// Find places within a polygon db.places.find({ location: { $geoWithin: { $geometry: { type: "Polygon", coordinates: [[ [-73.98, 40.78], [-73.96, 40.78], [-73.96, 40.80], [-73.98, 40.80], [-73.98, 40.78] ]] } } } })

$geoIntersects - Find Intersecting Geometries

// Find geometries that intersect db.places.find({ location: { $geoIntersects: { $geometry: { type: "Point", coordinates: [-73.968285, 40.785091] } } } })

Supported Geometry Types

  • 📍 Point: Single location
  • 📍 LineString: Path or route
  • 📍 Polygon: Area boundary
  • 📍 MultiPoint: Multiple points
  • 📍 MultiLineString: Multiple lines
  • 📍 MultiPolygon: Multiple polygons

  • 🔐 Enable Authentication: Always enable auth in production
  • 🔐 Use SSL/TLS: Encrypt data in transit
  • 🔐 Principle of Least Privilege: Grant minimum necessary permissions
  • 🔐 Network Security: Use firewalls, VPNs
  • 🔐 Encrypt at Rest: Enable encryption for stored data
  • 🔐 Regular Auditing: Monitor database activity
  • 🔐 Keep Software Updated: Apply security patches

Number Types Explained

Integers (int32)

Default for whole numbers. Can store up to 12 digits by default.

db.products.insertOne({ quantity: NumberInt(100) })

Longs (int64)

For larger integers beyond int32 range

db.stats.insertOne({ views: NumberLong("9999999999") })

Doubles (64-bit)

Default for decimal numbers

db.products.insertOne({ price: 29.99 })

Decimal128 (High Precision)

For financial calculations requiring exact precision

db.transactions.insertOne({ amount: NumberDecimal("99.99") })

Working with Dates

// Current date db.events.insertOne({ name: "Launch Event", date: new Date() }) // Specific date db.events.insertOne({ name: "Conference", date: ISODate("2024-12-31T00:00:00Z") }) // Query by date range db.events.find({ date: { $gte: ISODate("2024-01-01"), $lt: ISODate("2024-12-31") } })
