Modern JavaScript Features and Best Practices

📚 Introduction to ES6

ES6 (ECMAScript 2015) introduced major improvements to JavaScript, making it more powerful and easier to write.

What is ES6?

ES6 is the 6th edition of ECMAScript, released in June 2015. It brought revolutionary changes to JavaScript:

  • ✅ New syntax for common patterns
  • ✅ Better tools for large applications
  • ✅ Support for Object-Oriented Programming
  • ✅ Improved asynchronous programming

Browser Support

Modern browsers support ES6+, but you can use Babel to transpile ES6 to ES5 for older browsers.

📦 var, let, and const

Under the Hood: The TDZ

While var is initialized with undefined during the creation phase of the Execution Context, let and const variables are placed in the Temporal Dead Zone. They exist in memory but are marked as "uninitialized," making any access attempt throw a ReferenceError.

Feature var let const
Scope Function/Global Block Block
Initialization undefined None (TDZ) None (TDZ)
Redeclaration ✅ Possible ❌ SyntaxError ❌ SyntaxError
// const ensures reference immutability, not value immutability const config = { port: 8080 }; config.port = 3000; // ✅ Legal // config = {}; // ❌ TypeError: Assignment to constant variable

🔍 Scope & Shadowing

Scope defines the accessibility of variables in different parts of your code.

Types of Scope

🌍 Scope Hierarchy Visualization
🌍 Global Scope
var globalVar = "I'm global"; const globalConst = "Also global"; console.log(globalVar); // Accessible everywhere ✅
🔧 Function Scope
function myFunction() { var functionVar = "I'm in function"; console.log(globalVar); // ✅ Can access console.log(functionVar); // ✅ Can access }
📦 Block Scope (let/const)
if (true) { let blockVar = "I'm in block"; console.log(globalVar); // ✅ Can access console.log(functionVar); // ✅ Can access console.log(blockVar); // ✅ Can access } console.log(blockVar); // ❌ ReferenceError!

Inner scopes can access outer scopes, but not vice versa! ⬆️

Variable Shadowing

Shadowing occurs when a variable in an inner scope has the same name as a variable in an outer scope.

✅ Legal Shadowing

function test() { let x = 10; // Outer scope if (true) { let x = 20; // Shadows outer 'x' ✅ console.log(x); // 20 } console.log(x); // 10 (outer x unchanged) } // let can shadow var var a = 10; function example() { let a = 20; // ✅ Legal console.log(a); // 20 }

❌ Illegal Shadowing

// var cannot shadow let (crosses boundary) function illegalExample() { let x = 10; if (true) { var x = 20; // ❌ SyntaxError! // var is function-scoped, tries to redeclare let } }

⚠️ Illegal Shadowing Rules:

  • var cannot shadow let or const in the same function scope
  • This prevents accidental redeclaration issues
  • Always check scope boundaries when using different variable keywords

➡️ Arrow Functions

Shorter syntax for functions, with lexical this binding

// Traditional function function add(a, b) { return a + b; } // Arrow function const add = (a, b) => a + b; // Multiple lines need curly braces const calculate = (a, b) => { const sum = a + b; return sum * 2; }; // Real example: Array operations const numbers = [1, 2, 3, 4, 5]; const doubled = numbers.map(n => n * 2); const evens = numbers.filter(n => n % 2 === 0); console.log(doubled); // [2, 4, 6, 8, 10] console.log(evens); // [2, 4]

🔑 Key Characteristics:

  • ✅ Lexical this binding: Arrow functions don't have their own this
  • ✅ Shorter syntax: Perfect for callbacks and array methods
  • ❌ Cannot be used as constructors: No new keyword
  • ❌ No arguments object: Use rest parameters instead

📝 Template Literals

String interpolation and multi-line strings

// Old way const name = "John"; const age = 30; const message1 = "Hello, my name is " + name + " and I am " + age; // New way with template literals const message2 = `Hello, my name is ${name} and I am ${age}`; // Multi-line strings const html = ` <div class="card"> <h2>${name}</h2> <p>Age: ${age}</p> </div> `; // Expressions inside const price = 100; const total = `Total: $${(price * 1.08).toFixed(2)}`;

💡 Benefits:

  • ✅ Easy string interpolation with ${}
  • ✅ Multi-line strings without \n
  • ✅ Embed expressions directly
  • ✅ Better readability than concatenation

🌟 Spread Operator (...)

Expand arrays and objects

// Array spreading const arr1 = [1, 2, 3]; const arr2 = [4, 5, 6]; const combined = [...arr1, ...arr2]; console.log(combined); // [1, 2, 3, 4, 5, 6] // Copy array const original = [1, 2, 3]; const copy = [...original]; // Object spreading const user = { name: "John", age: 30 }; const updatedUser = { ...user, age: 31, city: "NYC" }; console.log(updatedUser); // {name: "John", age: 31, city: "NYC"} // Real example: Merge settings const defaultSettings = { theme: "light", fontSize: 14 }; const userSettings = { fontSize: 16 }; const finalSettings = { ...defaultSettings, ...userSettings }; console.log(finalSettings); // {theme: "light", fontSize: 16}

🎯 Common Use Cases:

  • ✅ Combining arrays
  • ✅ Copying arrays/objects (shallow copy)
  • ✅ Merging objects with overrides
  • ✅ Passing array elements as function arguments

📊 Rest Parameters

Collect multiple elements into an array

// Rest parameters function sum(...numbers) { return numbers.reduce((total, num) => total + num, 0); } console.log(sum(1, 2, 3)); // 6 console.log(sum(1, 2, 3, 4, 5)); // 15 // Real example: Logger function logMessage(level, ...messages) { console.log(`[${level}]`, ...messages); } logMessage("ERROR", "Failed to load", "user data");

📌 Spread vs Rest:

  • Spread (...): Expands an array/object → [...arr]
  • Rest (...): Collects arguments into an array → function(...args)
  • Same syntax, opposite purposes!

🎯 Default Parameters

// Old way function greet(name) { name = name || "Guest"; return `Hello, ${name}`; } // ES6 way function greet(name = "Guest") { return `Hello, ${name}`; } // Real example: API request function fetchData(url, method = "GET", timeout = 5000) { console.log(`Fetching ${url} with ${method}, timeout: ${timeout}ms`); } fetchData("/api/users"); // Uses defaults

✅ Benefits:

  • Cleaner function signatures
  • Avoid || operator issues with falsy values
  • Can use expressions as defaults
  • Better readability and maintainability

✨ Enhanced Object Literals

const name = "John"; const age = 30; // Old way const person1 = { name: name, age: age, greet: function() { return "Hello"; } }; // ES6 way const person2 = { name, age, greet() { return "Hello"; } };

📦 Destructuring

Array Destructuring

// Extract values from array const colors = ["red", "green", "blue"]; const [first, second, third] = colors; console.log(first); // "red" // Skip elements const [, , third] = colors; console.log(third); // "blue" // Default values const [a, b, c, d = "default"] = [1, 2, 3]; console.log(d); // "default" // Real example: Swap variables let x = 1, y = 2; [x, y] = [y, x]; console.log(x, y); // 2, 1

Object Destructuring

// Extract properties const user = { name: "John", age: 30, email: "john@example.com" }; const { name, age } = user; console.log(name, age); // "John", 30 // Rename variables const { name: userName, age: userAge } = user; console.log(userName); // "John" // Default values const { name, age, country = "USA" } = user; console.log(country); // "USA" // Real example: Function parameters function displayUser({ name, age, email }) { console.log(`${name}, ${age}, ${email}`); } displayUser(user);

🎯 Promises

Promises represent the eventual completion (or failure) of an asynchronous operation.

Promise States

🎯 Promise State Transitions
⏳
Pending

Initial state
Operation in progress

→
✅
Fulfilled

Operation successful
Data available via .then()

→
❌
Rejected

Operation failed
Error caught via .catch()

📌 Important: Once settled (fulfilled/rejected), a promise cannot change state!

Creating Promises

// Basic promise const promise = new Promise((resolve, reject) => { const success = true; if (success) { resolve("Operation successful!"); } else { reject("Operation failed!"); } }); promise .then(result => console.log(result)) .catch(error => console.error(error)); // Real example: Fetch user data function fetchUser(userId) { return new Promise((resolve, reject) => { setTimeout(() => { if (userId > 0) { resolve({ id: userId, name: "John Doe" }); } else { reject("Invalid user ID"); } }, 1000); }); } fetchUser(1) .then(user => console.log(user)) .catch(error => console.error(error));

Promise Methods

Promise.all()

Behavior: All must succeed
Rejects: When ANY fails
Returns: Array of all values
Use Case: Dependent tasks

Promise.allSettled()

Behavior: Wait for all
Rejects: Never rejects
Returns: Array of objects
Use Case: Independent tasks

Promise.race()

Behavior: First to settle
Rejects: If first rejects
Returns: First result
Use Case: Timeout logic

Promise.any()

Behavior: First success
Rejects: If all fail
Returns: First fulfilled
Use Case: Fastest API

Detailed Examples

// 1. Promise.all() - All must succeed const p1 = Promise.resolve(3); const p2 = Promise.resolve(42); const p3 = new Promise((resolve) => setTimeout(resolve, 100, 'foo')); Promise.all([p1, p2, p3]) .then(values => console.log(values)); // [3, 42, "foo"] // If one fails, entire Promise.all() fails const p4 = Promise.reject("error"); Promise.all([p1, p4, p3]) .catch(error => console.log(error)); // "error" // 2. Promise.allSettled() - Wait for all, never rejects Promise.allSettled([p1, p4, p3]) .then(results => console.log(results)); // [{status: "fulfilled", value: 3}, // {status: "rejected", reason: "error"}, // {status: "fulfilled", value: "foo"}] // 3. Promise.race() - First to finish (resolve OR reject) const fast = new Promise((resolve) => setTimeout(resolve, 100, 'fast')); const slow = new Promise((resolve) => setTimeout(resolve, 500, 'slow')); Promise.race([fast, slow]) .then(value => console.log(value)); // "fast" // 4. Promise.any() - First successful resolution const rejected = Promise.reject('Error'); const delayed = new Promise((resolve) => setTimeout(resolve, 200, 'success')); Promise.any([rejected, delayed]) .then(value => console.log(value)); // "success"

Promise Chaining

Execute a sequence of asynchronous tasks one after another:

🔗 Promise Chaining Flow
1
fetch()

Initial request

2
.then()

Process data

3
.then()

Return new promise

4
.then()

⚠️ .catch() catches errors from any step above
// Sequential async operations new Promise((resolve, reject) => { setTimeout(() => resolve(1), 1000); }) .then(result => { console.log(result); // 1 return result * 2; }) .then(result => { console.log(result); // 2 return result * 3; }) .then(result => { console.log(result); // 6 return result * 4; }) .then(result => { console.log(result); // 24 }); // Real-world example: User data flow fetchUser(1) .then(user => { console.log("User:", user); return fetchUserPosts(user.id); }) .then(posts => { console.log("Posts:", posts); return fetchComments(posts[0].id); }) .then(comments => { console.log("Comments:", comments); }) .catch(error => { console.error("Error:", error); });

Promise Rules

📜 Promise Contract:

  • ✅ A promise supplies a standard-compliant .then() method
  • ✅ A pending promise may transition into either fulfilled or rejected
  • ✅ A fulfilled or rejected promise is settled and cannot change state
  • ✅ Once settled, the value/reason must not change

Error Handling

// Multiple .catch() for different errors fetchData() .then(data => processData(data)) .catch(error => { console.error("Fetch error:", error); return "default data"; // Recover from error }) .then(data => displayData(data)) .catch(error => { console.error("Display error:", error); }); // Ignore promise errors safely await promise.catch((e) => void e);

⚡ Async/Await

Async/await is syntactic sugar over Promises, making asynchronous code look synchronous.

Basic Syntax

// Async function async function fetchData() { try { const response = await fetch("/api/data"); const data = await response.json(); return data; } catch (error) { console.error("Error:", error); } } // Using the async function fetchData().then(data => console.log(data)); // Or with await (inside async function) async function main() { const data = await fetchData(); console.log(data); }

Real-World Example

// E-commerce checkout flow async function checkout(userId, cartId) { try { // Step 1: Validate cart const cart = await validateCart(cartId); console.log("Cart validated"); // Step 2: Process payment const payment = await processPayment(userId, cart.total); console.log("Payment processed"); // Step 3: Create order const order = await createOrder(userId, cart, payment); console.log("Order created"); // Step 4: Send confirmation await sendConfirmationEmail(userId, order); return order; } catch (error) { console.error("Checkout failed:", error); throw error; } } // Multiple parallel requests async function loadDashboard() { const [user, stats, notifications] = await Promise.all([ fetchUser(), fetchStats(), fetchNotifications() ]); return { user, stats, notifications }; }

Error Handling

// Try-catch for error handling async function fetchUserData(userId) { try { const response = await fetch(`/api/users/${userId}`); if (!response.ok) { throw new Error(`HTTP error! status: ${response.status}`); } const data = await response.json(); return data; } catch (error) { console.error("Failed to fetch user:", error); return null; } }

🎓 ES6 Classes

Classes provide a cleaner syntax for creating objects and implementing inheritance.

Basic Class

class Person { constructor(name, age) { this.name = name; this.age = age; } greet() { return `Hello, I'm ${this.name}`; } haveBirthday() { this.age++; console.log(`Happy ${this.age}th birthday!`); } } const john = new Person("John", 30); console.log(john.greet()); // "Hello, I'm John" john.haveBirthday(); // "Happy 31th birthday!"

Inheritance

class Employee extends Person { constructor(name, age, jobTitle, salary) { super(name, age); // Call parent constructor this.jobTitle = jobTitle; this.salary = salary; } getDetails() { return `${this.name}, ${this.jobTitle}, $${this.salary}`; } greet() { return `${super.greet()}, I'm a ${this.jobTitle}`; } } const emp = new Employee("Jane", 28, "Developer", 80000); console.log(emp.greet()); // "Hello, I'm Jane, I'm a Developer"

Static Methods

class MathUtils { static add(a, b) { return a + b; } static multiply(a, b) { return a * b; } } // Call without creating instance console.log(MathUtils.add(5, 3)); // 8 console.log(MathUtils.multiply(4, 5)); // 20

💡 When to Use Classes:

  • ✅ Creating multiple similar objects
  • ✅ Need inheritance/polymorphism
  • ✅ Organizing related functionality
  • ✅ Building libraries/frameworks

⚙️ JavaScript Execution Model

JavaScript is a single-threaded, non-blocking, asynchronous programming language.

Key Characteristics

Single-Threaded

One call stack
One task at a time
Main thread executes code
Runtime is single-threaded

Non-Blocking

Async operations don't block
Uses Web APIs
Callbacks/Promises
Event Loop manages flow

Asynchronous

Doesn't wait for completion
Multiple operations in progress
Callbacks execute later
Improves performance

Memory Organization

🧠 JavaScript Memory Model

📚 Call Stack (LIFO)

Purpose: Track function execution
Structure: Stack (Last In, First Out)
Contains: Execution contexts
// Call stack visualization [Global Context] ↑ [main()] ↑ [helper()] ↑ [calculate()]

💾 Heap Memory

Purpose: Store objects & data
Structure: Unstructured region
Contains: Variables, objects, arrays
// Heap stores objects const user = { name: "John", age: 30 };

Execution Context

Two Components of Execution Context:

  • Memory Component (Variable Environment): Stores variables and functions
  • Code Component (Thread of Execution): Executes code line by line

Two Phases:

  • Creation Phase: Allocate space, functions take as-is, variables = undefined
  • Execution Phase: Assign values to variables, invoke functions

Synchronous vs Asynchronous

// Synchronous - Blocks execution console.log("Start"); function syncTask() { // Heavy computation blocks everything for(let i = 0; i < 1000000000; i++) {} return "Done"; } console.log(syncTask()); // Blocks until done console.log("End"); // Asynchronous - Non-blocking console.log("Start"); setTimeout(() => { console.log("Async Task"); }, 2000); console.log("End"); // Doesn't wait! // Output: Start → End → (2s later) → Async Task

🔄 Event Loop

The Event Loop is the mechanism that enables JavaScript's asynchronous behavior despite being single-threaded.

🔄 Event Loop Architecture
1️⃣ Call Stack

Executes synchronous code

↓
2️⃣ Web APIs

setTimeout, fetch, DOM events
(Multi-threaded capabilities)

↓
3️⃣ Callback Queue

Waits for call stack to empty

↓
4️⃣ Event Loop

Pushes callback to call stack when empty

How setTimeout Works

// Step-by-step breakdown console.log("Start"); // 1. Executes immediately setTimeout(() => { console.log("Timeout"); // 4. Executes after call stack is empty }, 0); // 2. Sent to Web API console.log("End"); // 3. Executes immediately // Output: Start → End → Timeout // Even with 0ms delay, setTimeout is async!

🔑 Event Loop Steps:

  1. Call Stack: setTimeout() is called
  2. Web API: Timer runs in separate thread
  3. Callback Queue: After delay, callback enters queue
  4. Event Loop: When call stack is empty, moves callback to stack
  5. Execute: Callback function runs

Microtasks vs Macrotasks

// Microtasks (higher priority) console.log("1. Sync"); setTimeout(() => console.log("2. Macrotask"), 0); Promise.resolve().then(() => console.log("3. Microtask")); console.log("4. Sync"); // Output: 1. Sync → 4. Sync → 3. Microtask → 2. Macrotask // Microtasks (Promises) execute before Macrotasks (setTimeout)

⚠️ Important Concepts:

  • Microtasks: Promises, queueMicrotask()
  • Macrotasks: setTimeout, setInterval, setImmediate
  • Priority: Microtasks execute before Macrotasks
  • Blocking: Long-running code blocks the event loop

📦 Modules (Import/Export)

ES6 modules allow you to split code into reusable files with import and export.

Export Types

1. Named Exports

// utils.js - Multiple named exports export const PI = 3.14159; export function add(a, b) { return a + b; } export class Calculator { multiply(a, b) { return a * b; } } // Or export all at once const name = "John"; const age = 30; export { name, age };

2. Default Export

// user.js - One default export per file export default class User { constructor(name) { this.name = name; } } // or const config = { theme: "dark" }; export default config;

Import Types

1. Named Imports

// Importing specific exports import { PI, add, Calculator } from './utils.js'; console.log(PI); // 3.14159 console.log(add(2, 3)); // 5 // Rename imports import { add as sum } from './utils.js'; console.log(sum(5, 5)); // 10 // Import all import * as utils from './utils.js'; console.log(utils.PI); console.log(utils.add(1, 2));

2. Default Import

// Can use any name import User from './user.js'; import MyUser from './user.js'; // Same thing, different name const user = new User("John");

3. Mixed Import

// Import both default and named exports import User, { PI, add } from './utils.js';
