💡 JavaScript Extra Topics

The practical extras that sit between “I know the syntax” and “I can ship a real app” — events, the DOM, performance, browser APIs, modules, and the patterns you will meet in interviews and production.

🗺️ What This Page Covers

The other JavaScript pages teach language mechanics: types, functions, objects, ES6, and how the engine runs your code. This page is the toolbox around that language — the things you actually wire into a search box, a list, a fetch call, or a production bundle.

⏱️ Debouncing & Throttling

Both techniques limit how often a function runs. They solve the same pain — events that fire dozens of times per second — in opposite ways. Debounce waits for quiet. Throttle allows a regular pulse.

Debounce collapses a burst into one call after the user pauses. Throttle keeps a steady beat while the event is still happening.

Why this matters

An input handler can fire on every keystroke. A scroll handler can fire more than 60 times a second. If each call hits the network, measures the DOM, or writes layout, the page stutters and your API bill climbs. You do not want to “slow JavaScript.” You want to decouple the event rate from the work rate.

Debounce — wait for quiet

Every event restarts the timer. The function runs only after no new events arrive for delay milliseconds. Use it when the latest value is the only one that matters.

Throttle — allow a pulse

The function runs at most once per window. Extra events in that window are ignored (or queued for the end). Use it when you need continuous updates, just not 200 of them.

Debounce in detail

Think of an elevator door. Each person walking in resets the “close” timer. The door only closes when nobody new arrives. That is trailing debounce — the most common form, and the one you want for search boxes and autosave.

function debounce(func, delay) { let timeoutId; return function debounced(...args) { const context = this; clearTimeout(timeoutId); timeoutId = setTimeout(() => { func.apply(context, args); }, delay); }; } const searchAPI = (query) => { console.log(`GET /search?q=${query}`); }; const debouncedSearch = debounce(searchAPI, 400); searchInput.addEventListener('input', (e) => { debouncedSearch(e.target.value); }); // User types "hello" quickly // h e l l o → timer keeps resetting // 400ms of silence → one call with "hello"

Use debounce when: search-as-you-type, form validation, autosave, window resize layout, anything where intermediate values are waste.

Throttle in detail

Think of a turnstile. People can keep arriving, but only one person goes through every 300ms. You still get updates while the user is scrolling — you just do not do the expensive work on every pixel.

function throttle(func, delay) { let lastCall = 0; return function throttled(...args) { const now = Date.now(); if (now - lastCall >= delay) { lastCall = now; func.apply(this, args); } }; } const updateProgress = () => { const scrolled = window.scrollY; const height = document.documentElement.scrollHeight - window.innerHeight; progressEl.style.width = `${(scrolled / height) * 100}%`; }; window.addEventListener('scroll', throttle(updateProgress, 100), { passive: true });

Leading vs trailing

A trailing call fires after the burst. A leading call fires immediately on the first event, then ignores the rest of the window. Search wants trailing (wait until the query is complete). A “like” button wants leading (react now, ignore double-clicks for 300ms).

Search input

Debounce 300–500ms, trailing. One network request with the final string.

Scroll / mousemove

Throttle 50–100ms, or use requestAnimationFrame if you are painting.

Button / submit

Leading throttle so the first click counts and the next few are ignored.

Details that bite in production: preserve this and arguments with apply. Cancel the timer on unmount so a dead component does not run. For fetch, pair debounce with AbortController so an older request cannot overwrite a newer one.

💾 Memoization

Memoization caches a function’s return value for a given set of arguments. The next call with the same inputs skips the work and returns the stored result. It is a time-for-memory trade: you spend RAM to avoid repeating expensive, pure computation.

1
Build a key

Usually from the arguments.

2
Cache hit?

Return the stored value.

3
Cache miss

Run the real function.

4
Store & return

Save the result for next time.

A classic example is naive Fibonacci. Without a cache, fib(40) recomputes the same subproblems thousands of times. With a cache — or better, with memoization inside the recursion — each n is computed once.

function memoize(fn) { const cache = new Map(); return function memoized(...args) { const key = JSON.stringify(args); if (cache.has(key)) return cache.get(key); const result = fn.apply(this, args); cache.set(key, result); return result; }; } function fib(n) { if (n <= 1) return n; return fib(n - 1) + fib(n - 2); } const fastFib = memoize(function fibMemo(n) { if (n <= 1) return n; return fibMemo(n - 1) + fibMemo(n - 2); });
Wrapping a recursive fib from the outside only caches the top-level call. Inner recursive calls still explode. Memoize the recursive function itself, or pass the cache down.
Memoize pure functions only. If the function reads the current time, a random value, or live DOM state, a cache will return stale lies.

Where it shows up

  • React useMemo / React.memo — skip re-render or recompute when props and deps are unchanged.
  • Selectors — derive filtered lists from store state without walking the array on every render.
  • API GET by id — cache JSON for a URL, and invalidate when you mutate that resource.

🎬 requestAnimationFrame

setTimeout(fn, 16) is a rough guess at 60fps. requestAnimationFrame is the browser’s real paint clock. It runs your callback just before the next frame, pauses in background tabs, and keeps animations aligned with the display refresh.

function onScroll() { // schedule at most one update per frame if (ticking) return; ticking = true; requestAnimationFrame(() => { box.style.transform = `translateY(${window.scrollY * 0.3}px)`; ticking = false; }); } window.addEventListener('scroll', onScroll, { passive: true });

Rule of thumb: debounce for “wait until they stop.” Throttle for “keep a pulse of logic.” requestAnimationFrame for “I am about to touch pixels.”

🎯 Event Handling

The browser turns user actions and document changes into Event objects and delivers them to listeners. You almost always want addEventListener — it lets many handlers coexist, and it exposes capturing, once, passive, and abort options that onclick = cannot.

const button = document.querySelector('#save'); button.addEventListener('click', function onSave(event) { event.preventDefault(); // stop native submit / navigation console.log(event.type); // "click" console.log(event.currentTarget); // the element with the listener console.log(event.target); // the deepest element clicked console.log(event.clientX, event.clientY); }); // Options object (not the old boolean) button.addEventListener('click', handler, { capture: false, once: true, // auto-remove after first fire passive: false // true = you promise not to preventDefault });

The event object, in plain language

event.target

The element that actually originated the event — the clicked icon inside the button, for example.

event.currentTarget

The element whose listener is running right now. In a delegated listener this is the parent you subscribed to.

preventDefault()

Stops the browser’s default: following a link, submitting a form, ticking a checkbox. Does not stop other listeners.

stopPropagation()

Stops the event from traveling to other nodes. Use rarely — it breaks delegation and analytics further up the tree.

Memory leaks: a listener on window or document that closes over a removed component will keep that component alive. Store the same function reference and removeEventListener, or pass an AbortSignal and abort it on teardown.

🌊 Event Flow: Capturing, Target, Bubbling

A click is not delivered only to the button. The event travels. First it walks down from window toward the target (capturing). Then it fires on the target. Then it walks back up (bubbling). That path is why a parent div can hear a click that started on a child button.

Phase 1 goes down. Phase 2 is the element you clicked. Phase 3 goes back up. Most listeners run in phase 3 unless you pass capture: true.
window / document
div.card
button — the target
Click the button 1. CAPTURING window → document → .card → button 2. TARGET button listeners (capture and bubble both run here) 3. BUBBLING button → .card → document → window addEventListener(type, fn, true) // capturing addEventListener(type, fn, false) // bubbling (default)
// HTML: window > .card > button document.querySelector('.card').addEventListener('click', () => { console.log('card — capturing'); }, true); document.querySelector('button').addEventListener('click', () => { console.log('button — target'); }); document.querySelector('.card').addEventListener('click', () => { console.log('card — bubbling'); }); // Logs: card — capturing → button — target → card — bubbling

Some events do not bubble (focus, blur, mouseenter, mouseleave). For those, listen in capture or use bubbling cousins like focusin / focusout / mouseover.

🎯 Event Delegation

If a list has 500 items, you do not attach 500 click listeners. You attach one listener on the parent and use bubbling plus event.target to find which child was involved. New items that appear later are handled automatically. That is event delegation.

The child is clicked. The event bubbles. The parent’s single listener asks “which item?” with closest or target.
const list = document.querySelector('#todo-list'); list.addEventListener('click', (event) => { const deleteBtn = event.target.closest('[data-action="delete"]'); if (!deleteBtn || !list.contains(deleteBtn)) return; const item = deleteBtn.closest('li'); item.remove(); }); // Later — no extra listeners needed list.insertAdjacentHTML('beforeend', '<li>New task <button data-action="delete">x</button></li>' );

Why it wins

Fewer listeners, less memory, works for items created after page load, and one place to read the logic.

What to watch

Check that the click happened inside your list. Use closest so clicks on an icon inside the button still count. Do not stopPropagation on children unless you intend to break this.

📣 Custom Events

Components can talk without importing each other by firing a CustomEvent on a DOM node (or on window). The parent listens. The child dispatches. This is how a lot of design systems implement “the modal closed” or “the tab changed” without a full state library.

// Child widget box.dispatchEvent(new CustomEvent('qtychange', { bubbles: true, detail: { sku: 'hat', qty: 2 } })); // Ancestor document.querySelector('#cart').addEventListener('qtychange', (e) => { console.log(e.detail.sku, e.detail.qty); });

Set bubbles: true if a parent should hear it. Put payload on detail, not on random extra fields — that is the standard place.

🌳 The DOM

The Document Object Model is the live tree of objects the browser builds from HTML. JavaScript does not edit the .html file. It talks to these objects. Change a node, and the page updates. That is the whole job of client-side UI before frameworks abstract it.

Tags become element nodes. Text between tags becomes text nodes. document is the root you start from.

Finding nodes

querySelector / querySelectorAll are the modern default — they take any CSS selector. getElementById is still the fastest for a single id. Live collections (getElementsByClassName) update as the DOM changes; NodeList from querySelectorAll is static.

const header = document.getElementById('header'); const first = document.querySelector('.item'); const all = document.querySelectorAll('.item'); const nested = document.querySelector('form.checkout input[name="email"]');

Reading and writing

el.textContent = 'Safe text'; // no HTML parsed el.innerHTML = '<em>Risky if user data</em>'; el.setAttribute('aria-busy', 'true'); el.style.color = 'crimson'; // inline style el.classList.toggle('is-open'); const li = document.createElement('li'); li.textContent = 'Walk the dog'; list.append(li); // modern; accepts nodes and strings li.remove();

Walking the tree

Up

parentElement, closest('.modal') — closest is the one you will use daily.

Down

children (elements only), childNodes (includes text), firstElementChild.

Sideways

nextElementSibling, previousElementSibling. Prefer the Element variants so whitespace text nodes do not surprise you.

Reflow: reading layout (offsetHeight, getBoundingClientRect) after writes forces the browser to recalculate style. Batch reads, then writes. Creating 1,000 nodes? Build them in a DocumentFragment and append once.

🌐 CORS (Cross-Origin Resource Sharing)

Browsers enforce the same-origin policy. An origin is scheme + host + port. https://shop.com is not the same origin as https://api.shop.com or http://shop.com or https://shop.com:3000. JavaScript on one origin cannot read another origin’s response unless that other origin opts in with CORS headers.

The browser is the bouncer. Your frontend cannot “turn CORS off.” The API server must send the allow headers.

Simple request vs preflight

A “simple” GET/POST with a small set of headers goes straight to the server. Anything else — PUT, DELETE, JSON Content-Type, custom headers like Authorization — first triggers an automatic OPTIONS preflight. The browser asks “am I allowed?” If the answer headers look right, the real request is sent.

Frontend at https://shop.com 1. fetch('https://api.shop.com/cart', { method: 'PUT', ... }) 2. Browser sends OPTIONS /cart Origin: https://shop.com Access-Control-Request-Method: PUT 3. API must answer: Access-Control-Allow-Origin: https://shop.com Access-Control-Allow-Methods: GET, PUT, POST Access-Control-Allow-Headers: Content-Type, Authorization 4. Then the real PUT is sent 5. The response must again include Allow-Origin or JS cannot read the body
fetch('https://api.shop.com/data', { method: 'GET', credentials: 'include' // cookies — then Allow-Origin cannot be * }) .then((res) => res.json()) .catch((err) => console.error('Blocked or network error', err));

How you actually fix it

  1. API headers — the real fix. Express cors, Rails, Django, Nginx, API Gateway: send Access-Control-Allow-Origin for your frontend origin.
  2. Dev proxy — Vite / webpack proxy makes the browser think the API is same-origin during local development.
  3. Your own backend — the browser talks only to your server; your server talks to third-party APIs. No browser CORS on that second hop.
CORS is not an API security model. It protects the user’s browser from hostile pages reading their other tabs. A server that trusts only CORS headers is still callable from curl, Postman, and other backends.

📄 JSON

JSON is a text format that looks like a subset of JavaScript object literals. APIs, localStorage, and config files use it because every language can parse it. Two methods matter: JSON.stringify (value → text) and JSON.parse (text → value).

const user = { name: 'Ada', age: 36, active: true }; const text = JSON.stringify(user); // '{"name":"Ada","age":36,"active":true}' const pretty = JSON.stringify(user, null, 2); localStorage.setItem('user', text); try { const again = JSON.parse(localStorage.getItem('user')); console.log(again.name); } catch (e) { console.error('Corrupt JSON', e); }

Survives the trip

string, number, boolean, null, objects, arrays. Nested combinations of those.

Dropped or changed

undefined, functions, Symbol, and Date (becomes a string). Keys that are symbols vanish. Use a replacer / reviver if you need dates back.

🗄️ Web Storage, Cookies, and IndexedDB

The browser can remember data after a refresh. The four common shelves have very different sizes, lifetimes, and whether they hitch a ride on HTTP requests.

Cookies travel with requests — keep them tiny and sensitive. localStorage is a simple key/value shelf. IndexedDB is the real client database.
localStorage.setItem('theme', 'dark'); const theme = localStorage.getItem('theme'); localStorage.removeItem('theme'); sessionStorage.setItem('wizardStep', '2'); // dies with the tab const cart = { items: [1, 2] }; localStorage.setItem('cart', JSON.stringify(cart)); const restored = JSON.parse(localStorage.getItem('cart') ?? 'null');

Cookies

~4KB, sent on matching requests. Use HttpOnly + Secure + SameSite for session ids. Do not store large JSON here.

localStorage / sessionStorage

Synchronous strings only. Fine for theme and draft UI. Never store access tokens if XSS is possible — JS can read them.

Storage events fire in other tabs, not the tab that wrote the value. That is how you sync logout across windows. Quota can throw. Always try/catch writes in Safari private mode.

📬 postMessage

Iframes, popups, and web workers do not share your JavaScript scope. postMessage is the safe pipe between windows. You send a structured value and a target origin. The other side listens for message and must check event.origin before trusting the data.

const iframe = document.getElementById('checkout'); iframe.contentWindow.postMessage( { type: 'init', cartId: 'c_19' }, 'https://pay.trusted.com' ); window.addEventListener('message', (event) => { if (event.origin !== 'https://pay.trusted.com') return; if (event.data?.type === 'paid') markOrderPaid(event.data.orderId); });
Never use targetOrigin: '*' for anything that includes tokens, personal data, or payment state. A hostile page that captured a window reference could receive that message.

🛑 AbortController

Debouncing search is not enough if the first request is slower than the second. The old response can arrive last and overwrite the new results. AbortController lets you cancel fetch, streams, and even event listeners (via signal).

let controller; async function search(query) { controller?.abort(); controller = new AbortController(); try { const res = await fetch(`/api/search?q=${query}`, { signal: controller.signal }); return res.json(); } catch (err) { if (err.name === 'AbortError') return; // expected throw err; } }

You can also pass the same signal to addEventListener so removing listeners is one abort() on unmount:

const ac = new AbortController(); window.addEventListener('resize', onResize, { signal: ac.signal }); // later ac.abort();

👀 Intersection & Mutation Observers

Polling getBoundingClientRect on scroll is how pages used to jank. Observers let the browser tell you when something important changed.

IntersectionObserver

Fires when an element enters or leaves the viewport (or any root). Infinite scroll, lazy images, “chapter in view” analytics, and reveal animations all start here.

MutationObserver

Fires when nodes are added, removed, or attributes change. Useful for integrating with widgets you do not control. Easy to create feedback loops — observe narrowly.

const io = new IntersectionObserver((entries) => { for (const entry of entries) { if (entry.isIntersecting) { const img = entry.target; img.src = img.dataset.src; io.unobserve(img); } } }, { rootMargin: '200px' }); document.querySelectorAll('img[data-src]').forEach((img) => io.observe(img));

⛓️ Optional Chaining (?.)

Reading user.profile.email throws if profile is missing. Optional chaining stops at the first null or undefined and returns undefined instead of exploding. It is a safe walk, not a default value — pair it with ?? when you need a fallback.

Left: ?. turns a missing link into undefined. Right: ?? only replaces null and undefined, so 0 and false stay real values.
const city = user?.address?.city; const first = users?.[0]?.name; const label = settings?.formatTitle?.(); const value = obj?.[dynamicKey]; // Combined with a default const email = response?.data?.user?.email ?? 'unknown';

It short-circuits. obj?.method() will not call method if obj is nullish. Side effects on the right-hand side do not run. That is a feature — and a surprise if you expected the call to always happen.

❓ Nullish Coalescing (??)

|| treats every falsy value as “missing”: 0, '', false, NaN, null, undefined. ?? only treats null and undefined as missing. Use it whenever those other falsy values are legal answers.

console.log(0 || 25); // 25 — wrong if 0 is a valid age console.log(0 ?? 25); // 0 console.log('' ?? 'n/a'); // '' console.log(false ?? true); // false console.log(null ?? 'fallback'); // 'fallback' const timeout = config.timeout ?? 5000; const retries = config.retries ?? 3; const enabled = config.enabled ?? true;

??= assigns only when the left side is nullish: settings.title ??= 'Untitled'. You cannot mix ?? with || or && without parentheses — the parser refuses the ambiguity on purpose.

🔄 Iterators, Iterables, and Generators

An iterable is any object that implements Symbol.iterator. Arrays, strings, maps, sets, and NodeList are iterables. for...of, spread, and destructuring all ask for that iterator and pull { value, done } until done is true.

const iterator = ['a', 'b'][Symbol.iterator](); iterator.next(); // { value: 'a', done: false } iterator.next(); // { value: 'b', done: false } iterator.next(); // { value: undefined, done: true } for (const char of 'Hi') { console.log(char); }

Generators

A function* can yield many times. Each yield pauses and hands a value out. That is how you build custom iterables and lazy sequences without allocating a giant array.

function* range(start, end) { for (let i = start; i <= end; i++) yield i; } for (const n of range(1, 3)) { console.log(n); // 1, 2, 3 } async function* paged(url) { let next = url; while (next) { const page = await fetch(next).then((r) => r.json()); yield* page.items; next = page.nextUrl; } }

📦 JavaScript Modules

A module is a file with its own scope. Nothing leaks into window unless you put it there. You export the public surface and import it where you need it. That graph is what bundlers use to delete unused code.

Named exports keep names. A default export is the file’s main value. Unused exports can be dropped at build time.
// math.js export const add = (a, b) => a + b; export const multiply = (a, b) => a * b; export default function sumAll(...nums) { return nums.reduce((a, b) => a + b, 0); } // app.js import sumAll, { add } from './math.js'; import * as math from './math.js'; console.log(add(2, 3)); console.log(math.multiply(4, 5));

ESM in the browser

<script type="module"> is deferred by default, needs paths or an import map, and runs in strict mode.

CommonJS

require / module.exports in older Node. Live bindings work differently. Prefer ESM in new code.

Why bother

Namespacing, reuse, testability, and tree shaking. A 2,000-line utils.js dumped on window cannot be shaken.

🔧 Polyfills

A polyfill implements a modern API on an older engine so the same source can run there. A transpile (Babel) rewrites syntax you cannot polyfill — =>, let, optional chaining. You often need both: syntax transform plus runtime helpers / polyfills.

if (!Array.prototype.at) { Array.prototype.at = function at(index) { const i = Math.trunc(index) || 0; const k = i >= 0 ? i : this.length + i; if (k < 0 || k >= this.length) return undefined; return this[k]; }; }

In 2026: ship core-js or polyfill.io only for the browsers you actually support. Shipping every polyfill to every user is how bundles get fat. Feature-detect, don’t sniff the user agent string.

⚙️ Service Workers

A service worker is a script that sits between the page and the network. It can cache responses, serve a page offline, show a push notification, and sync when the user comes back online. It has no DOM. It wakes on events, then goes idle.

Register from the page. Install fills a cache. Activate takes control. Fetch is where you choose cache, network, or a mix.
1
Register

navigator.serviceWorker.register('/sw.js')

2
Install

Open a cache, add the app shell.

3
Activate

Delete old caches. Claim clients.

4
Fetch

Intercept requests. Cache first or network first.

if ('serviceWorker' in navigator) { navigator.serviceWorker.register('/sw.js'); } // sw.js (runs in a worker, not the page) self.addEventListener('install', (event) => { event.waitUntil( caches.open('shell-v1').then((cache) => cache.addAll(['/', '/styles.css', '/app.js']) ) ); }); self.addEventListener('fetch', (event) => { event.respondWith( caches.match(event.request).then((hit) => hit || fetch(event.request)) ); });

HTTPS only (localhost is allowed). A buggy worker can brick your site until you unregister it — always version caches and have a kill switch. Users may run an old worker for a visit or two after you deploy.

📱 Progressive Web Apps

A PWA is a website that earns app privileges: install to the home screen, launch without a browser chrome, work offline, and optionally receive push. The browser decides “is this installable?” from a web app manifest, a service worker, HTTPS, and a usable UI.

{ "name": "Notes", "short_name": "Notes", "start_url": "/", "display": "standalone", "background_color": "#0f172a", "theme_color": "#4f46e5", "icons": [ { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" }, { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any maskable" } ] }

Link it with <link rel="manifest" href="/manifest.json">, register a service worker, and serve over HTTPS. “Progressive” means the same URL still works as a normal site for browsers that ignore the extras.

🧵 Web Workers

The main thread owns the DOM and the event loop. If you parse a 20MB CSV there, scrolling dies. A Web Worker is a second JavaScript thread with its own heap. You talk only through messages. It cannot touch the DOM — that restriction is the point: UI stays responsive.

UI on the left. Heavy work on the right. postMessage is the only bridge. Structured clone copies the data unless you transfer it.
// main.js const worker = new Worker('/parse-worker.js', { type: 'module' }); worker.postMessage({ csvText }); worker.onmessage = (e) => renderTable(e.data.rows); worker.onerror = (e) => console.error(e.message); // parse-worker.js self.onmessage = (e) => { const rows = heavyParse(e.data.csvText); self.postMessage({ rows }); };

Dedicated worker

One page, one worker. Default choice for “crunch this file.”

Shared worker

Several tabs share one worker. Rare, useful for a single WebSocket.

Service worker

Not for math. It is a network proxy with a different lifecycle.

🔒 Strict Mode

"use strict" turns sloppy historic JavaScript into a smaller, safer language. Modules and classes are strict automatically. In sloppy mode, assigning to an undeclared name creates a global. In strict mode it throws. That single change prevents an entire class of bugs.

'use strict'; x = 10; // ReferenceError let y = 5; delete y; // SyntaxError function sum(a, a) {} // SyntaxError: duplicate params false.foo = 1; // TypeError (primitives are not objects) function show() { console.log(this); // undefined, not window } show();

ES modules already do this. You still see the pragma in old scripts and in interview questions. Know what it forbids: implicit globals, with, octal literals, and this defaulting to the global object in a bare function call.

💥 Error Handling

Failures are values you can catch. try / catch / finally is for synchronous throws and for await. Promise rejections need .catch or a surrounding async function that awaits them. An unhandled rejection is a bug, not a log line.

class HttpError extends Error { constructor(status, message) { super(message); this.name = 'HttpError'; this.status = status; } } async function loadUser(id) { try { const res = await fetch(`/api/users/${id}`); if (!res.ok) throw new HttpError(res.status, res.statusText); return await res.json(); } catch (err) { if (err instanceof HttpError && err.status === 404) return null; throw err; } finally { hideSpinner(); } }

Built-in types

TypeError, RangeError, SyntaxError, URIError, AggregateError. Catch specific classes first, then a fallback.

Don’t swallow

Empty catch (e) {} hides outages. Log with context, rethrow if you cannot recover, and never catch just to ignore.

🐛 Debugging

console.log is a flashlight. Breakpoints are a workshop. The debugger statement pauses if DevTools is open. Conditional breakpoints pause only when an expression is true — that is how you catch the 1-in-1,000 bad payload without stopping every loop.

console.log({ user, cart }); // label the object, don't stringify blindly console.table(rows); console.time('sort'); rows.sort(); console.timeEnd('sort'); console.trace('who called me?'); function checkout(cart) { debugger; return charge(cart); }
  • Line breakpoint — click the gutter. Step over / into / out of calls.
  • Conditional — right-click the gutter: item.price < 0.
  • XHR / fetch breakpoint — pause when a URL substring matches.
  • DOM breakpoint — pause when a node’s children or attributes change.

🌲 Tree Shaking

Bundlers treat your ESM graph like a tree and drop unused exports (dead code elimination). It only works if the file is a real ES module, the export is statically visible, and the module is marked side-effect free. A console.log at the top level, or export default { add, multiply } as one object, makes shaking harder.

// utils.js — shakeable named exports export function add(a, b) { return a + b; } export function unusedHugeThing() { /* ... */ } // app.js import { add } from './utils.js'; add(1, 2); // unusedHugeThing never appears in the production bundle

📦 Minification & Obfuscation

Minification deletes comments and whitespace and shortens local names. The program is the same; the bytes are fewer. Obfuscation goes further — it rewrites control flow so humans struggle. Minify always in production. Obfuscate only if you have a real reason; it is not security, just delay.

Before function calculateTotal(price, quantity) { const subtotal = price * quantity; return subtotal + subtotal * 0.1; } After minify function calculateTotal(e,t){const a=e*t;return a+.1*a}

🎨 Programming Paradigms

A paradigm is a habit of thinking, not a religion. JavaScript lets you mix them. The useful distinction on a Tuesday afternoon is imperative vs declarative: do I list the steps, or do I describe the result?

Imperative — how

Allocate an array, loop an index, push. You manage the machinery. Fine for algorithms and performance-sensitive loops.

Declarative — what

numbers.filter(n => n > 0).map(double). You name the transformation. React JSX is declarative UI: “the tree should look like this given state.”

const nums = [1, 2, 3]; let doubled = []; for (let i = 0; i < nums.length; i++) doubled.push(nums[i] * 2); const also = nums.map((n) => n * 2);

You will also hear object-oriented (bundle data with methods), functional (pure functions, immutability, composition), and event-driven (react to clicks and messages). Real apps use all four in the same file.

🏗️ The Four OOP Pillars

JavaScript’s objects are prototypes first and classes second. The class syntax still expresses the same four ideas every interview expects.

1. Encapsulation

Keep state private; expose a small API. #balance is real privacy. Closures are the older version of the same idea.

2. Abstraction

Call machine.makeCoffee(). Hide grind / heat / brew. The caller should not need the internals to use the thing.

3. Inheritance

class Dog extends Animal. Share structure, override what changes. Prefer a shallow tree. Deep hierarchies get brittle.

4. Polymorphism

Same message, different types: every Shape has area(). You loop shapes and never if (circle) ... else if (rect).

class BankAccount { #balance = 0; constructor(start) { this.#balance = start; } deposit(amount) { if (amount > 0) this.#balance += amount; } getBalance() { return this.#balance; } } class Shape { area() { return 0; } } class Circle extends Shape { constructor(r) { super(); this.r = r; } area() { return Math.PI * this.r ** 2; } }

🧩 Design Patterns You Will Actually Use

Patterns are named solutions, not homework. These four show up constantly in frontend and Node code.

Module / revealing module

A file (or an IIFE in old code) hides helpers and exports a tiny API. ESM is this pattern.

Observer

Subscribe / unsubscribe / notify. DOM events, Redux, EventTarget, RxJS. Custom events are a DOM-native observer.

Factory

A function that returns an object without forcing new. createLogger('checkout') beats a zoo of subclasses.

Singleton

One shared instance — a store, a DB pool, a config. ESM already caches a module. Do not invent a class just to have one object.

function createStore(initial) { let state = initial; const listeners = new Set(); return { get() { return state; }, set(next) { state = next; listeners.forEach((fn) => fn(state)); }, subscribe(fn) { listeners.add(fn); return () => listeners.delete(fn); } }; }

🧬 Shallow vs Deep Copy

Assignment copies the reference, not the object. A shallow copy duplicates the outer box; nested objects are still shared. A deep copy clones the whole tree. Mutating a nested field on a shallow copy mutates the original — that is the bug that makes React state “randomly” change.

Spread and Object.assign are shallow. structuredClone is the built-in deep clone for most everyday values.
const user = { name: 'Ada', address: { city: 'Pune' } }; const shallow = { ...user }; shallow.address.city = 'Mumbai'; console.log(user.address.city); // 'Mumbai' — shared nest const deep = structuredClone(user); deep.address.city = 'Goa'; console.log(user.address.city); // still 'Mumbai'

JSON.parse(JSON.stringify(obj)) is a crude deep clone: it drops functions, undefined, Date becomes a string, and it throws on cycles. Prefer structuredClone. It still cannot clone functions or DOM nodes.

🛡️ XSS and Sanitizing the DOM

Cross-site scripting happens when you treat attacker-controlled text as HTML. innerHTML, document.write, and template strings dumped into the page are the usual doors. The fix is boring and correct: put untrusted data in textContent, or run it through a sanitizer if you truly need markup.

el.innerHTML = comment.body — if body is <img onerror="..."> you just ran their script in your users’ browsers.

el.textContent = comment.body — always safe for text. If you need rich text, use setHTML / DOMPurify and a strict allow-list, never a regex you wrote at 1am.

function renderComment(text) { const li = document.createElement('li'); li.textContent = text; // escaped automatically list.append(li); }

Related extras: CSP (Content-Security-Policy) limits which scripts can run. SameSite cookies reduce CSRF. Sanitize on output, not only on input — a stored comment can sit in the database for years.
