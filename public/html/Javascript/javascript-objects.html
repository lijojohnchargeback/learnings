📦 JavaScript Objects

Complete Guide to Objects, Classes, Prototypes, and Modern Object APIs

📚 Introduction to Objects

An object is a collection of properties — named key-value pairs that can hold data or functions (methods). Almost everything non-primitive in JavaScript is an object: arrays, functions, dates, errors, and even modules. Primitives (string, number, boolean, null, undefined, symbol, bigint) are not objects, though some of them get a temporary object wrapper when you call methods like "hi".toUpperCase().

Value vs Reference

Primitives are copied by value. Objects are copied by reference: the variable stores a pointer to a heap location. Two variables can point at the same object, so a change through one is visible through the other.

let a = 10; let b = a; b = 20; console.log(a); // 10 — primitives are independent copies const user1 = { name: "Sam" }; const user2 = user1; // same object in memory user2.name = "Alex"; console.log(user1.name); // "Alex" — both variables share one object console.log(user1 === user2); // true (same reference) console.log({ name: "Sam" } === { name: "Sam" }); // false (two objects)

Real-World Analogy: Car

  • Properties: Static attributes like color, brand, model, and year.
  • Methods: Dynamic behaviors like start(), stop(), and accelerate().

Why Use Objects?

  • ✅ Organize data: Group related fields instead of loose variables.
  • ✅ Model the real world: Users, products, orders, configs.
  • ✅ Reuse behavior: Share methods through prototypes or classes.
  • ✅ Pass structured data: APIs, function options, React props.
⚠️ typeof quirks: typeof null is "object" (a long-standing language bug). Arrays and functions are objects too: typeof [] === "object" and typeof function(){} === "function". Use Array.isArray(value) to detect arrays, and value === null to detect null.
const user = { firstName: "John", lastName: "Doe", age: 30, email: "john@example.com", address: { city: "Austin", zip: "78701" }, // Method shorthand (ES6) getFullName() { return this.firstName + " " + this.lastName; }, // Computed property name (ES6) ["last_login_" + Date.now()]: new Date() }; console.log(user.getFullName()); // "John Doe" console.log(user.address.city); // "Austin"

🔑 Property Access

You can read and write properties with dot notation or bracket notation. Dot notation is cleaner when the key is a valid identifier. Brackets are required for dynamic keys, keys with spaces, or keys that start with a number.

const book = { title: "Clean Code", "page count": 464, 2024: "reprint" }; console.log(book.title); // dot — identifier keys console.log(book["page count"]); // brackets — space in the key console.log(book[2024]); // brackets — numeric-looking key const field = "title"; console.log(book[field]); // "Clean Code" — dynamic key book.author = "Robert Martin"; // add book.title = "Clean Code (2e)"; // update delete book[2024]; // remove

Optional chaining and defaults

?. stops evaluation if the left side is null or undefined, instead of throwing. Combine it with ?? (nullish coalescing) when you want a fallback only for nullish values — not for 0 or "".

const order = { customer: { name: "Lina" } }; console.log(order.customer?.name); // "Lina" console.log(order.shipping?.city); // undefined (no throw) console.log(order.shipping?.city ?? "N/A"); // "N/A" // Optional call — only runs if the method exists order.notify?.("shipped");
Tip: Prefer obj?.prop over long obj && obj.prop chains. Do not overuse it to hide missing data you should have validated at the API boundary.

🔨 Object Creation Methods

JavaScript gives you several ways to create objects. Pick the pattern that matches how many instances you need and whether they should share behavior.

1. Object Literal (Most Common)

A comma-separated list of name-value pairs in curly braces. Fast, readable, and the right default for a single object or a config.

Why use it?
  • ✅ Zero ceremony: no constructor call.
  • ✅ Easy for engines to optimize.
  • ✅ Supports shorthand, methods, and computed keys.
const name = "Hyundai"; const year = 2007; const car = { name, // shorthand for name: name year, show() { console.log(`${this.name} manufactured in ${this.year}`); } }; car.color = "blue"; car.show();

2. Object Constructor

Uses the built-in Object() constructor. Works, but a literal is usually clearer.

const car = new Object(); car.color = "green"; car.brand = "Honda"; car.year = 2024; delete car.color; console.log("color" in car); // false

3. Object.create() (Prototypal Inheritance)

Creates a new object whose prototype is an existing object. You only specify what is different from the parent — this is differential inheritance.

const person = { showDetails() { return `${this.name} - ${this.email}`; } }; const john = Object.create(person); john.name = "John"; john.email = "john@gmail.com"; console.log(john.showDetails()); // Second argument: property descriptors at creation time const admin = Object.create(person, { role: { value: "superuser", writable: false, enumerable: true, configurable: false } }); console.log(admin.role); // "superuser" admin.role = "guest"; // ignored in sloppy mode; TypeError in strict mode
Empty dictionary: Object.create(null) makes an object with no prototype. It has no inherited methods like toString, which is useful for a pure key-value map — but prefer Map for that job in modern code.

4. Constructor Function (Classical Pattern)

A regular function used as a blueprint. Calling it with new runs a four-step lifecycle.

The new keyword lifecycle:
  1. Create a new empty object {}.
  2. Set that object's prototype to the function's .prototype.
  3. Bind this to the new object and run the function body.
  4. Return the object (unless the function returns a different object).
function Employee(name, email, age) { this.name = name; this.email = email; this.age = age; } const sam = new Employee("Sam", "sam@gmail.com", 20); console.log(sam instanceof Employee); // true function Mobile(name, price) { this.name = name; this.price = price; this.profile = function () { console.log(`${this.name} costs $${this.price}`); }; } const phone = new Mobile("iPhone", 999); phone.profile();
⚠️ Forgot new? In sloppy mode this becomes the global object and you pollute window. In modules / strict mode, this is undefined and the assignment throws. Classes always require new.

5. Constructor with Prototype Delegation

Put methods on Constructor.prototype so every instance shares one function in memory instead of copying it per object.

function Student(name, email, classes) { this.name = name; this.email = email; this.class = classes; } Student.prototype.login = function (date) { this.date = date; return `${this.name} logged on ${this.date}`; }; const jane = new Student("Jane", "jane@gmail.com", 4); console.log(jane.login("2024-01-15")); console.log(jane.hasOwnProperty("login")); // false — it lives on the prototype

6. Factory Function Pattern

A function that returns a new object without new. Closures give you real privacy, and you avoid most this binding bugs.

Structural benefits:
  • ✅ Encapsulation: Private variables via closures.
  • ✅ No this surprises: The object is returned explicitly.
  • ✅ Composition: Easier to mix behaviors than deep class trees.
function createTeam(name, players) { let score = 0; // private via closure return { teamName: name, players, addPoint() { score += 1; return score; }, message() { return `${name} has ${players} players and ${score} points`; } }; } const myTeam = createTeam("Champions", 20); myTeam.addPoint(); console.log(myTeam.message()); console.log(myTeam.score); // undefined — not exposed

🎯 The this Keyword in Objects

this is not the object where the function was defined. It is set by how the function is called (except arrow functions, which inherit this from the enclosing scope).

const counter = { count: 0, inc() { this.count += 1; return this.count; }, // Arrow as a method is usually wrong: no own this brokenInc: () => { // this is NOT counter return this.count; } }; console.log(counter.inc()); // 1 const detached = counter.inc; // detached(); // TypeError in strict mode — this is undefined setTimeout(counter.inc, 0); // loses this unless you bind it setTimeout(() => counter.inc(), 0); // safe setTimeout(counter.inc.bind(counter), 0); // also safe
⚠️ Passing a method as a callback detaches it from the object. Bind it, wrap it in an arrow, or use a class field arrow if you truly need auto-bound methods (at the cost of one function per instance).

📦 Destructuring, Spread, and Rest

These syntax features let you unpack, copy, and merge objects without listing every property by hand.

Destructuring

const product = { id: 12, title: "Keyboard", price: 79, meta: { sku: "KB-12", stock: 8 } }; const { title, price } = product; const { title: name, price: cost = 0 } = product; // rename + default const { meta: { sku } } = product; // nested function format({ title, price }) { return `${title}: $${price}`; } console.log(format(product));

Spread and rest

const base = { role: "user", active: true }; const extra = { name: "Dev", active: false }; const merged = { ...base, ...extra, id: 1 }; // extra.active wins — later keys overwrite earlier ones console.log(merged); // { role: "user", active: false, name: "Dev", id: 1 } const { id, ...publicFields } = merged; console.log(publicFields); // everything except id
⚠️ Spread is a shallow copy. Nested objects are still shared. Mutating copy.address.city also changes the original. See Cloning Objects below.

🔎 Checking Properties

There are several ways to ask “does this object have this key?” They disagree on inherited properties and on keys whose value is undefined.

CheckOwn keysInherited keysNotes
"key" in objYesYesTrue even if value is undefined
obj.hasOwnProperty("key")YesNoCan break on objects with no prototype
Object.hasOwn(obj, "key")YesNoPreferred modern check
obj.key !== undefinedMaybeMaybeWrong if the stored value is actually undefined
const animal = { eats: true }; const rabbit = Object.create(animal); rabbit.jumps = true; rabbit.color = undefined; console.log("eats" in rabbit); // true (inherited) console.log(Object.hasOwn(rabbit, "eats")); // false console.log(Object.hasOwn(rabbit, "jumps")); // true console.log(Object.hasOwn(rabbit, "color")); // true (key exists) console.log(rabbit.color !== undefined); // false — misleading

🧬 Cloning Objects

Copying an object is one of the most common sources of bugs. Decide whether you need a shallow clone (top-level keys only) or a deep clone (nested objects too).

const original = { name: "Sam", tags: ["js", "web"], address: { city: "Austin" } }; // Shallow copies — nested objects are shared const copy1 = { ...original }; const copy2 = Object.assign({}, original); copy1.name = "Alex"; console.log(original.name); // "Sam" — top-level primitive is safe copy1.address.city = "Dallas"; console.log(original.address.city); // "Dallas" — nested object was shared // Deep clone (modern browsers / Node 17+) const deep = structuredClone(original); deep.address.city = "Miami"; console.log(original.address.city); // still "Dallas" // JSON clone — loses functions, undefined, Date, Map, Symbol keys const jsonClone = JSON.parse(JSON.stringify(original));

When to use which clone

  • Spread / Object.assign: Flat configs, props, Redux-style updates of one level.
  • structuredClone: Nested data, Dates, Maps, Sets, ArrayBuffers. Cannot clone functions or DOM nodes.
  • JSON.parse(JSON.stringify): Simple JSON-safe data only. Dates become strings.

📄 JSON and Objects

JSON is a data format, not a JavaScript object. JSON.stringify turns a value into a string for storage or a network request. JSON.parse turns that string back into data.

const payload = { id: 7, title: "Notebook", inStock: true, created: new Date("2024-01-15"), skip: undefined, toJSON() { return { id: this.id, title: this.title }; } }; const text = JSON.stringify(payload); console.log(text); // '{"id":7,"title":"Notebook"}' — toJSON wins const parsed = JSON.parse(text); console.log(parsed.title); // "Notebook" // Pretty print + pick keys JSON.stringify(payload, ["id", "title"], 2); // Reviver — restore types while parsing const withDate = JSON.parse( '{"when":"2024-01-15T00:00:00.000Z"}', (key, value) => key === "when" ? new Date(value) : value );
JSON cannot represent: undefined, functions, Symbol keys, Infinity, circular references. JSON.stringify throws on cycles. Dates stringify as ISO strings, not Date objects.

🎓 ES6 Classes

Classes are templates for creating objects. They are syntactic sugar over constructor functions and prototypes, with a cleaner syntax and a few extra rules.

Technical nuances:
  • ✅ Not hoisted like functions: A class declaration sits in the Temporal Dead Zone until it is evaluated. You cannot new it before the declaration.
  • ✅ Always strict: The class body runs in 'use strict'.
  • ✅ Methods live on the prototype: Instances share one copy of each method.
  • ✅ Must use new: Calling a class as a plain function throws TypeError.

The prototype vs __proto__ confusion

  • prototype: A property on a constructor function / class. Instances created with new get that object as their prototype.
  • [[Prototype]] / __proto__: The internal link on an instance to its prototype. Prefer Object.getPrototypeOf(obj) over __proto__.

Basic class

class House { owner = "unknown"; // public field — per instance constructor(name, email, age) { this.name = name; this.email = email; this.age = age; } getFullName() { return `${this.name} - ${this.email}`; } describe() { return `${this.getFullName()} (owner: ${this.owner})`; } } const home = new House("Ada", "ada@mail.com", 36); console.log(home.getFullName()); console.log(home instanceof House); // true console.log(typeof House); // "function"

Class expressions

const Cart = class { constructor() { this.items = []; } add(item) { this.items.push(item); } }; const cart = new Cart(); cart.add({ sku: "A1", qty: 2 });

🔗 Inheritance with extends and super

Inheritance lets a class reuse another class's fields and methods. extends sets up the prototype link. super calls the parent constructor or a parent method.

class Person { constructor(name) { this.name = name; } introduce() { return `${this.name} is a person`; } } class Teacher extends Person { constructor(name, email, phone) { super(name); // must run before using this this.email = email; this.phone = phone; } introduce() { return `${super.introduce()} and teaches via ${this.email}`; } fullDetails() { return `${this.name} - ${this.email} - ${this.phone}`; } } const sara = new Teacher("Sara", "sara@gmail.com", "901871771"); console.log(sara.introduce()); console.log(sara.fullDetails()); console.log(sara instanceof Teacher); // true console.log(sara instanceof Person); // true
⚠️ super() first: In a subclass constructor you must call super(...) before you touch this. Forgetting it throws ReferenceError. If the child has no constructor, the engine calls the parent constructor for you.
Prefer composition for deep trees. One or two levels of extends is fine. Past that, mix small objects or helper functions instead of AdminManagerUserBase pyramids.

⚡ Static Methods and Fields

Static members are called on the class, not on instances. They are stored on the constructor function itself. Use them for utilities, factories, and values shared by the type — not by each object.

When to use:
  • ✅ Utility functions (Math.max, Array.from)
  • ✅ Factory / parse methods (User.fromJson)
  • ✅ Shared constants and caches
class Calculator { static version = "1.0.0"; static add(a, b) { return a + b; } static multiply(a, b) { return a * b; } } console.log(Calculator.add(5, 3)); // 8 console.log(Calculator.multiply(5, 3)); // 15 console.log(Calculator.version); // "1.0.0" const calc = new Calculator(); // calc.add(1, 2); // TypeError — static methods are not on the instance class User { constructor(name) { this.name = name; } static fromJson(json) { const data = JSON.parse(json); return new User(data.name); } } const u = User.fromJson('{"name":"Kai"}'); console.log(u.name); // "Kai"

🔒 Private Fields and Methods

ES2022 private class features start with #. Unlike the _name convention (only a style agreement), #name is enforced by the engine. Outside code cannot read, write, or even detect the field with in in the usual way.

class BankAccount { #balance = 0; static #bankCode = "X9"; constructor(owner, opening = 0) { this.owner = owner; this.#balance = opening; } #assertAmount(amount) { if (amount <= 0) throw new RangeError("Amount must be positive"); } deposit(amount) { this.#assertAmount(amount); this.#balance += amount; return this.#balance; } get balance() { return this.#balance; } static getBankCode() { return BankAccount.#bankCode; } } const acct = new BankAccount("Lijo", 100); acct.deposit(50); console.log(acct.balance); // 150 console.log(BankAccount.getBankCode()); // console.log(acct.#balance); // SyntaxError // console.log(acct.balance = 0); // no setter — ignored / error in strict

Hard privacy vs closures

#fields are per-instance and checked at runtime (a “brand check”). Factory closures also hide data, but each method is a new function. Classes with private fields keep methods on the prototype and still hide state.

📞 Call, Apply, and Bind

These three methods set this manually so you can reuse a function with different objects.

call() — arguments listed one by one

const person1 = { firstName: "Akash", lastName: "John" }; const person2 = { firstName: "Sachin", lastName: "Tendulkar" }; function printFullName(hometown, state) { console.log(`${this.firstName} ${this.lastName} from ${hometown}, ${state}`); } printFullName.call(person1, "Bangalore", "Karnataka"); printFullName.call(person2, "Mumbai", "Maharashtra");

apply() — arguments as an array

printFullName.apply(person1, ["Bangalore", "Karnataka"]); printFullName.apply(person2, ["Mumbai", "Maharashtra"]); const nums = [3, 9, 1, 14]; console.log(Math.max.apply(null, nums)); // older pattern console.log(Math.max(...nums)); // modern equivalent

bind() — returns a new function

bind does not run the function. It returns a bound function you can pass to setTimeout, event listeners, or React callbacks.

const later = printFullName.bind(person2, "Mumbai", "Maharashtra"); later(); // still uses person2 as this const greetMumbai = printFullName.bind(person2, "Mumbai"); greetMumbai("Maharashtra"); // partial application

🔧 Built-in Object Methods

The Object constructor exposes static helpers for listing keys, merging, locking, and converting objects.

Object.keys(), values(), entries(), fromEntries()

const person = { name: "John", age: 30, city: "New York" }; console.log(Object.keys(person)); // ["name", "age", "city"] console.log(Object.values(person)); // ["John", 30, "New York"] console.log(Object.entries(person)); // [["name","John"], ["age",30], ...] const doubled = Object.fromEntries( Object.entries({ a: 1, b: 2 }).map(([k, v]) => [k, v * 2]) ); console.log(doubled); // { a: 2, b: 4 }
These helpers list own enumerable string keys. They skip inherited keys, Symbol keys, and non-enumerable properties. Use Object.getOwnPropertySymbols or Reflect.ownKeys when you need everything.

Object.assign() — merge (shallow)

const target = { a: 1, b: 2 }; const source = { b: 4, c: 5 }; Object.assign(target, source); console.log(target); // { a: 1, b: 4, c: 5 } — target was mutated const merged = Object.assign({}, target, source); // safer copy const also = { ...target, ...source }; // same idea with spread

Object.is() — same-value comparison

=== treats +0 and -0 as equal, and treats NaN as not equal to itself. Object.is does the opposite for those two cases.

console.log(NaN === NaN); // false console.log(Object.is(NaN, NaN)); // true console.log(+0 === -0); // true console.log(Object.is(+0, -0)); // false

Locking objects: freeze, seal, preventExtensions

APIAdd keysDelete keysChange values
Object.preventExtensionsNoYesYes
Object.sealNoNoYes
Object.freezeNoNoNo
const frozen = { prop: 42 }; Object.freeze(frozen); frozen.prop = 33; // silent fail, or TypeError in strict mode console.log(frozen.prop); // 42 console.log(Object.isFrozen(frozen)); // true const sealed = { property1: 42 }; Object.seal(sealed); sealed.property1 = 33; // allowed delete sealed.property1; // fails console.log(Object.isSealed(sealed)); // true const limited = { name: "John" }; Object.preventExtensions(limited); limited.age = 30; // fails limited.name = "Jane"; // works delete limited.name; // works console.log(Object.isExtensible(limited)); // false
⚠️ Freeze is shallow. Nested objects inside a frozen parent can still be mutated. Freeze each level, or treat the data as immutable by convention (spread updates) instead of relying on Object.freeze for deep safety.

🎯 Getters and Setters

Accessors look like data properties but run a function. Use them to validate writes, format reads, or compute a value on the fly without exposing internal fields.

Benefits:
  • ✅ Hide internal storage (_price or #price)
  • ✅ Validate before assignment
  • ✅ Compute values only when read
  • ✅ Offer read-only or write-only surfaces
class Product { constructor(name, price) { this._name = name; this._price = price; } get price() { return `$${this._price}`; } set price(value) { if (value <= 0) { throw new Error("Price must be greater than zero"); } this._price = value; } get name() { return this._name; } } const p = new Product("Laptop", 1000); console.log(p.price); // "$1000" p.price = 1200; console.log(p.price); // "$1200" const account = { _n: "Kai", get displayName() { return this._n.toUpperCase(); } }; console.log(account.displayName); // "KAI"

🛠️ Property Descriptors

Every own property is more than a key and a value. It has attributes that control writing, listing, and deletion. Data properties have value + writable. Accessor properties have get / set instead.

AttributeDefault (literals)Meaning
valuethe assigned valueStored data
writabletrueCan assign a new value
enumerabletrueShows up in for...in and Object.keys
configurabletrueCan delete or redefine the property
const obj = { visible: 1 }; console.log(Object.getOwnPropertyDescriptor(obj, "visible")); // { value: 1, writable: true, enumerable: true, configurable: true } Object.defineProperty(obj, "id", { value: 99, writable: false, enumerable: false, configurable: false }); console.log(obj.id); // 99 console.log(Object.keys(obj)); // ["visible"] — id is hidden obj.id = 100; // ignored (or TypeError in strict) console.log(obj.id); // 99 Object.defineProperties(obj, { label: { get() { return `item-${this.visible}`; } } }); console.log(obj.label); // "item-1"

🔗 Prototypes and Delegation

Every object has an internal [[Prototype]] link. When a property is missing, the engine walks that chain. This is how shared methods work — not by copying functions onto every instance.

The prototype chain

  1. Look on the object itself. Found? Use it.
  2. Otherwise look on Object.getPrototypeOf(obj).
  3. Keep walking until a property is found or the chain ends at null.
  4. If nothing matches, the result is undefined.
const animal = { eats: true, walk() { return "walking"; } }; const rabbit = { jumps: true }; Object.setPrototypeOf(rabbit, animal); console.log(rabbit.eats); // true — delegated console.log(rabbit.walk()); // "walking" console.log(Object.getPrototypeOf(rabbit) === animal); // true console.log(animal.isPrototypeOf(rabbit)); // true function Dog(name) { this.name = name; } Dog.prototype.bark = function () { return `${this.name} says woof`; }; const rex = new Dog("Rex"); console.log(rex.bark()); console.log(Object.getPrototypeOf(rex) === Dog.prototype); // true
Avoid __proto__ in application code. It exists for compatibility. Use Object.getPrototypeOf / Object.setPrototypeOf, or set the prototype at creation time with Object.create. Changing prototypes on live objects is also slow.

🗺️ Map and WeakMap

A Map is a collection of key-value pairs designed for frequent add/lookup/delete. Unlike a plain object, keys can be any value — objects, functions, numbers — and insertion order is guaranteed.

TopicObjectMap
Key typesStrings and SymbolsAny value, including objects
SizeManual (Object.keys)map.size
OrderInteger keys then insertionInsertion order
IterationNeed Object.entriesDirectly iterable
Prototype keysCan clash with toString etc.No inherited keys

const scores = new Map(); const user = { id: 1 }; scores.set("kai", 12); scores.set(user, 99); scores.set("kai", 15); // update existing key console.log(scores.get("kai")); // 15 console.log(scores.has(user)); // true console.log(scores.size); // 2 for (const [key, value] of scores) { console.log(key, value); } scores.delete("kai"); scores.clear(); // Build from pairs const fromPairs = new Map([ ["html", 1], ["css", 2] ]);

WeakMap for memory hygiene

A WeakMap only accepts objects as keys and holds them weakly. If nothing else points at that object, it can be garbage-collected — the WeakMap entry disappears with it. Keys are not enumerable (no .size, no iteration). Use WeakMap for private metadata, caches, or DOM-node state that should not keep the node alive.

const privateData = new WeakMap(); class Session { constructor(id) { privateData.set(this, { id, openedAt: Date.now() }); } get id() { return privateData.get(this).id; } } const s = new Session("abc"); console.log(s.id); // "abc" // When s is no longer referenced, its WeakMap entry can be collected

🎭 Proxy and Reflect

A Proxy wraps a target object and intercepts operations: read, write, in, delete, function calls, and more. Reflect provides the default implementation of those same operations so traps can forward cleanly.

const target = { message: "hello", count: 1 }; const handler = { get(obj, prop, receiver) { if (prop in obj) { return Reflect.get(obj, prop, receiver); } return "Default Value"; }, set(obj, prop, value, receiver) { if (prop === "count" && value < 0) { throw new RangeError("count cannot be negative"); } return Reflect.set(obj, prop, value, receiver); }, has(obj, prop) { return prop !== "secret" && Reflect.has(obj, prop); } }; const proxy = new Proxy(target, handler); console.log(proxy.message); // "hello" console.log(proxy.missing); // "Default Value" proxy.count = 4; // proxy.count = -1; // RangeError
Common uses: validation, logging, reactive state (Vue), default values, and wrapping APIs. Keep traps small — a Proxy on a hot path is slower than a plain object.

🔄 for...in vs for...of

for...in walks enumerable property keys (including inherited ones). for...of walks iterable values — arrays, strings, Maps, Sets, and anything with Symbol.iterator.

Featurefor...infor...of
YieldsKeys (strings)Values
Best withPlain objectsArrays, Maps, Sets, strings
Inherited keysYes (usually unwanted)No
Works on plain objects?YesNo (objects are not iterable)
const arr = ["a", "b", "c"]; arr.extra = "newValue"; for (const key in arr) { console.log(key); // "0", "1", "2", "extra" } for (const value of arr) { console.log(value); // "a", "b", "c" } const user = { name: "Sam", role: "dev" }; // Safer object loops for (const key of Object.keys(user)) { console.log(key, user[key]); } for (const [key, value] of Object.entries(user)) { console.log(key, value); } // If you must use for...in, skip inherited keys for (const key in user) { if (Object.hasOwn(user, key)) { console.log(key); } }

⚠️ JavaScript Errors

Errors are objects. They carry a name, a message, and a stack. Throwing and catching them is how you recover from invalid data, missing references, and failed I/O.

Built-in error types

// RangeError — value outside an allowed range const checkRange = (num) => { if (num < 30) throw new RangeError("Wrong number"); return true; }; // ReferenceError — unknown variable // console.log(x); // TypeError — value is the wrong type const num = 15; // num.split(""); // SyntaxError — invalid source (usually at parse time) // const func = () => console.log("hello") } // URIError — bad encodeURI / decodeURI input // decodeURI("%sdfk");

try / catch / finally and custom errors

class ValidationError extends Error { constructor(message, field) { super(message); this.name = "ValidationError"; this.field = field; } } function createUser(data) { if (!data.email) { throw new ValidationError("email is required", "email"); } return { ...data }; } try { createUser({ name: "Sam" }); } catch (error) { console.log(error.name); // ValidationError console.log(error.message); // email is required console.log(error.field); // email console.log(error.stack); } finally { console.log("always runs"); }

📌 Object Best Practices

  • ✅ Use object literals for one-off data and configs.
  • ✅ Use classes (or factories) when you need many instances with shared methods.
  • ✅ Prefer const for object bindings — the binding is fixed, the contents can still change.
  • ✅ Copy before you mutate shared state ({ ...obj, key: next }).
  • ✅ Use Object.hasOwn or Object.keys instead of raw for...in.
  • ✅ Use Map when keys are not strings, or when you add and delete keys often.
  • ✅ Keep this methods attached, or bind them before passing as callbacks.
  • ✅ Do not use objects as deep-cloneable dumps of functions and Dates — pick structuredClone or a serializer.

Quick decision guide

  • Need a record of named fields? Object literal.
  • Need many similar instances? Class or factory.
  • Need a dictionary with unknown keys? Map (or Object.create(null)).
  • Need hidden instance data? #fields or a WeakMap.
  • Need to intercept reads/writes? Proxy.
