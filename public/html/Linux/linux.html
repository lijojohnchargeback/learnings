Operating System Fundamentals, Architecture & Command-Line Mastery

📚 Introduction to Linux

Linux is a family of open-source, Unix-like operating systems built on the Linux kernel. It powers servers, cloud infrastructure, containers, embedded devices, and developer workstations worldwide.

Why Learn Linux?

  • ✅ Server Dominance: Most web servers, databases, and cloud VMs run Linux
  • ✅ DevOps & Cloud: AWS, Docker, Kubernetes, and CI/CD pipelines rely on Linux
  • ✅ Security & Stability: Fine-grained permissions, process isolation, and long uptime
  • ✅ Free & Open Source: No licensing cost; full control over the system
  • ✅ Powerful CLI: Automate tasks, manage servers, and debug systems efficiently

Popular Linux Distributions

Distribution Best For Package Manager

🆚 Linux vs Unix vs Windows

Feature Linux Unix Windows
Origin 1991, Linus Torvalds (Linux kernel) 1970s, AT&T Bell Labs Microsoft (1985+)
License Open source (GPL) Mix of proprietary & open (BSD) Proprietary
Primary Interface CLI (Shell) + optional GUI CLI (Shell) GUI (Desktop) + PowerShell/CMD
Remote Access SSH (port 22) SSH RDP (port 3389)
Common Use Servers, cloud, containers, IoT Legacy servers, macOS (BSD-based) Desktops, enterprise workstations
File System ext4, xfs, btrfs UFS, ZFS NTFS

Key Takeaway

Linux uses SSH for secure remote command-line access. Windows uses RDP for graphical remote desktop access. Both can also use VPN for secure network tunnels.

🏗️ Linux System Architecture

Linux follows a layered architecture where each layer builds on the one below it. Understanding this stack is essential for troubleshooting and system administration.

Layered Architecture

// High-level flow (simplified) User / Application ↓ Shell (bash, zsh, sh) ↓ System Calls ↓ Kernel (core OS) ↓ Hardware (CPU, RAM, Disk, NIC)
Layer Component Description
1 Kernel Core of the OS. Manages CPU, memory, I/O devices, process scheduling, and communication between hardware and software.
2 Shell Command-line interface (CLI). Users type commands; shell interprets them and passes requests to the kernel.
3 SSH Secure Shell protocol. Encrypts remote login sessions so you can run shell commands on a remote machine safely.
4 Remote Access Ability to connect to a machine over a network (SSH, VPN, or tunnel) from a different physical location.

Kernel Responsibilities

  • 🔹 Process Management: Create, schedule, and terminate processes
  • 🔹 Memory Management: Allocate RAM, virtual memory, swap
  • 🔹 Device Drivers: Interface with hardware (disk, network, GPU)
  • 🔹 File System: Manage files, directories, and permissions
  • 🔹 Networking: Handle TCP/IP stack, sockets, firewalls
  • 🔹 Security: User authentication, access control, SELinux/AppArmor

Shell Types

Shell Path Notes
bash /bin/bash Default on most distros; scripting & interactive use
sh /bin/sh POSIX-compliant; often linked to dash or bash
zsh /bin/zsh Modern features; default on macOS

🚀 Linux Boot Process

When you power on a Linux machine, a sequence of programs runs before you reach a login prompt.

// Boot sequence Power On → Bootloader (GRUB) → Kernel loads into memory → Init (PID 1) starts → Daemons start (systemd services) → Shell / Login Manager → User session (SSH or local terminal)
Stage Component Role
1 Bootloader (GRUB) First program to run. Loads the kernel into RAM. Lets you choose OS/kernel at startup and supports recovery mode.
2 Kernel Initializes hardware, mounts root filesystem, starts the init process.
3 Init (PID 1) First user-space process. On modern systems, systemd is the init manager.
4 Daemons Background services (sshd, nginx, cron, networking) started by init.
5 Shell / SSH User logs in locally or remotely and gets a shell prompt.

GRUB (GRand Unified Bootloader)

GRUB is the most common bootloader on Linux. It reads configuration from /boot/grub/grub.cfg and presents a menu to select which kernel or OS to boot.

# View GRUB config cat /boot/grub/grub.cfg # Update GRUB after kernel changes (Debian/Ubuntu) sudo update-grub # Check boot logs journalctl -b

🖥️ Hardware Components

The kernel directly manages these hardware resources. Knowing them helps when diagnosing performance or connectivity issues.

Component Description Linux Commands
CPU Central Processing Unit — executes instructions and manages data flow between components. lscpu, top, htop
RAM (Memory) Volatile memory for fast access by the CPU. Cleared on power off. free -h, vmstat
Storage (HDD/SSD) Non-volatile storage. HDD uses spinning disks; SSD uses flash for faster I/O. df -h, du -sh, lsblk
I/O Devices Keyboards, mice, monitors, printers — peripherals for input/output. lsusb, lspci
Network Interface (NIC) Hardware for network connectivity — Ethernet (wired) or Wi-Fi (wireless). Built into motherboard or added as expansion card. ip addr, ifconfig, ethtool
# List block devices (disks, partitions) lsblk # List PCI devices (graphics, network cards) lspci # List USB devices lsusb # CPU info lscpu

🌐 Remote Access Overview

Remote Access is the ability to connect to a computer or network from a different location, typically over the internet.

Method Platform Port Use Case
SSH Linux, macOS, Windows (OpenSSH) 22 Secure command-line access, file transfer, tunneling
RDP Windows (built-in) 3389 Graphical remote desktop for Windows servers/desktops
VPN Cross-platform Varies Encrypted tunnel to a private network

Linux vs Windows Remote Access

  • 🐧 Linux: Primarily uses SSH for text-based remote administration
  • 🪟 Windows: Primarily uses RDP for full graphical desktop access
  • 🔐 Both support VPN for secure network-level access

🔐 SSH (Secure Shell)

SSH is a network protocol that provides encrypted remote login and command execution over an unsecured network.

SSH Key Facts

  • 🔹 Default Port: 22
  • 🔹 Encryption: All traffic (passwords, commands, data) is encrypted
  • 🔹 Authentication: Password or SSH key pair (public/private)
  • 🔹 Daemon: sshd runs on the server; client uses ssh command

Basic SSH Usage

# Connect to remote server ssh username@192.168.1.100 # Connect on custom port ssh -p 2222 username@hostname # Run a single remote command ssh user@server "df -h && free -m" # Generate SSH key pair ssh-keygen -t ed25519 -C "your_email@example.com" # Copy public key to server (passwordless login) ssh-copy-id user@server # SSH config (~/.ssh/config) for shortcuts Host myserver HostName 192.168.1.100 User admin Port 22 IdentityFile ~/.ssh/id_ed25519

SSH-Related Tools

Command Purpose Example
ssh Secure remote login ssh user@host
scp Secure copy (files over SSH) scp file.txt user@host:/path/
sftp Interactive secure file transfer sftp user@host

🖥️ RDP (Remote Desktop Protocol)

RDP is a Microsoft proprietary protocol for graphical remote desktop access to Windows machines.

  • 🔹 Default Port: 3389
  • 🔹 Built into Windows: Server and Pro editions include RDP server
  • 🔹 Cross-platform clients: Windows, macOS, Linux (Remmina, FreeRDP), mobile
  • 🔹 Use cases: Remote administration, technical support, remote work

On Linux servers, you typically do not use RDP. Use SSH instead. RDP is relevant when you also manage Windows servers alongside Linux infrastructure.

🔒 File Permissions

Linux uses a permission model with three categories: Owner, Group, and Others. Each has read (r), write (w), and execute (x) permissions.

# Example: -rw-r--r-- 1 user group 1024 Jan 1 12:00 file.txt # │││ │││ │││ # │││ │││ └── Others: r-- (read only) # │││ └────── Group: r-- (read only) # └──────── Owner: rw- (read + write)
Command Description Example
chmod Change file permissions chmod 755 script.sh
chown Change file owner chown user:group file.txt
chgrp Change group ownership chgrp developers project/

Numeric Permission Modes

Number Permission Meaning
4 r Read
2 w Write
1 x Execute
7 rwx 4+2+1 = full access
5 r-x 4+1 = read + execute
644 rw-r--r-- Owner: rw, Group/Others: read only
755 rwxr-xr-x Owner: full, Group/Others: read + execute

✨ Best Practices

Linux Administration Tips

  • ✅ Never run rm -rf / — it will destroy your system
  • ✅ Use sudo carefully — only when root privileges are needed
  • ✅ Prefer SSH keys over passwords for remote access
  • ✅ Check before you delete — use ls to verify paths
  • ✅ Read man pages — man command for full documentation
  • ✅ Use tab completion — press Tab to auto-complete paths and commands
  • ✅ Pipe commands — chain tools: cat file | grep error | wc -l
  • ✅ Back up before changes — especially config files in /etc/
