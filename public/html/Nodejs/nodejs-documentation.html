Node.js Complete Guide

JavaScript and TypeScript runtime for servers, CLIs, and APIs — updated for Node.js 24 LTS and Node.js 26

1) Introduction to Node.js

What is Node.js?

Node.js is an open-source, cross-platform JavaScript runtime that runs outside the browser. It is not a language and not a web framework. It is the engine that lets you write servers, CLIs, build tools, and workers in JavaScript or TypeScript.

🚀 Runtime, not a framework

Executes JS/TS with V8. Express, Fastify, and Nest sit on top of it.

⚡ V8 + libuv

V8 compiles JavaScript. libuv owns the event loop, thread pool, and OS I/O.

🔄 Event-driven I/O

One thread handles thousands of connections by never blocking on disk or network.

🌐 Server-side JS

Same language as the browser, plus filesystem, sockets, processes, and crypto.

📦 npm ecosystem

The largest package registry — plus first-party modules like node:test and node:sqlite.

🧑‍💻 Created by Ryan Dahl

Released in 2009. In 2026 it ships native TypeScript, fetch, WebSocket, and Temporal.

Why teams still choose Node.js

✅ One language

Share types, validation, and business rules between the API and the frontend.

✅ Fast at I/O

Non-blocking sockets and streams are the default, not an add-on.

✅ Web-standard APIs

fetch, WebSocket, AbortController, Blob, and Temporal work without polyfills.

✅ Real-time friendly

Chat, live dashboards, and collaborative tools fit the event-driven model.

When to use Node.js

Use case Why Node fits
I/O-bound APIs Database calls, HTTP proxies, file uploads — the event loop stays free while I/O completes.
Streaming Video, logs, CSV exports, and AI token streams without loading everything into RAM.
Real-time apps WebSockets and SSE keep many idle connections cheap.
Tooling & CLIs Build tools, code generators, and scripts. Native TypeScript means node app.ts just works.
BFF / SPA backends JSON APIs, session gateways, and GraphQL layers in the same language as the UI.
When not to use Node.js as the only process:
  • Heavy CPU work (image codecs, ML inference, huge JSON transforms) will stall the event loop.
  • Offload that work to Worker Threads, a child process, or a dedicated service.

2) Versions, LTS, and the 2026 runtime

Node 24 and 26 made TypeScript, SQLite, permissions, and web APIs first-class — no extra toolchain required.

As of September 2026, Node.js no longer ships two majors every year. Node 26 is the last biannual major. From Node 27 onward, there is one major per year and every release is LTS.

Version Status (Sep 2026) Use it for
Node.js 26 Current → LTS in October 2026 (EOL April 2029) New projects. Native TypeScript, Temporal on by default, Undici 8 fetch, V8 14.6.
Node.js 24 Active LTS (EOL April 2028) Production default until 26 is LTS. Type stripping, node:sqlite, --permission.
Node.js 22 Maintenance LTS (EOL April 2027) Existing apps. Plan the jump to 24 or 26 before 22 leaves maintenance.
Node.js 20 End of life (April 2026) Do not start here. Upgrade for security patches.

What “modern Node” means in practice

  • Run TypeScript directly: node server.ts — type annotations are stripped at load time.
  • No dotenv package required: node --env-file=.env server.js
  • No Jest required for unit tests: node --test with node:test and node:assert
  • No better-sqlite3 for local DBs: import { DatabaseSync } from 'node:sqlite'
  • No node-fetch: global fetch, Headers, FormData, WebSocket

3) Internal architecture

Node.js is a JavaScript facade over C++ systems. V8 executes your code. libuv talks to the operating system. Bindings glue the two together.

Your app never talks to the kernel directly. V8 runs JS; libuv owns I/O, timers, and the thread pool.

The architectural bridge: libuv

While V8 compiles JavaScript to machine code, libuv (C++) manages the event loop, the thread pool, and a portable API for files, DNS, networking, and child processes.

Why one thread can serve 10,000 connections

Classic thread-per-request servers pay for a stack and context switch on every client. Node registers a callback and moves on. The kernel notifies libuv when the socket or file is ready. CPU work still needs extra threads — that is what Worker Threads are for.

Architecture components

1. V8 Engine

  • Google's open-source JS engine
  • Parses, compiles (Ignition + TurboFan), GC
  • Same family as Chrome — Node 26 tracks V8 14.6
  • Embeddable; Node is one embedder

2. libuv

  • Event loop and thread pool
  • Async TCP/UDP, pipes, TTY
  • File system ops via the pool
  • Cross-platform OS abstraction

4) The event loop

The event loop is how Node.js does non-blocking I/O: it offloads work to the kernel (or the libuv thread pool) and runs your callbacks when results are ready.

Each loop turn walks six phases. After every phase, nextTick and Promise microtasks drain first.

Microtask order: nextTick vs Promises

  1. process.nextTick() — runs immediately after the current operation, before the next phase.
  2. Promise.then / queueMicrotask — after nextTick, still before the next phase.

Recursive nextTick can starve I/O: the loop never reaches poll. Prefer Promises for application code.

The six phases

1. Timers

setTimeout and setInterval callbacks whose delay has elapsed

2. Pending callbacks

Deferred I/O callbacks (for example some TCP errors)

3. Idle, prepare

Internal libuv bookkeeping

4. Poll

Retrieve new I/O events — the phase that does most of the work

5. Check

setImmediate callbacks

6. Close callbacks

socket.on('close') and similar

console.log('1. Start');

setTimeout(() => console.log('2. setTimeout'), 0);
setImmediate(() => console.log('3. setImmediate'));
process.nextTick(() => console.log('4. nextTick'));
Promise.resolve().then(() => console.log('5. Promise'));

console.log('6. End');

// Typical order:
// 1. Start
// 6. End
// 4. nextTick
// 5. Promise
// then timers vs check (2 vs 3) depending on context

Thread pool

libuv keeps a pool (default 4 threads, max 1024 via UV_THREADPOOL_SIZE) for work the kernel cannot do asynchronously on every OS: most fs calls, crypto (pbkdf2, scrypt, randomBytes), zlib, and some DNS lookups.

// Set before any I/O — typically in the shell, not mid-request
process.env.UV_THREADPOOL_SIZE = '8';

Do not block the event loop

  • Avoid readFileSync / pbkdf2Sync on the request path
  • Move heavy CPU to worker_threads
  • Watch huge JSON.parse and catastrophic regexes
import { readFile } from 'node:fs/promises';

const data = await readFile('large-file.txt', 'utf8');

6) Modules: CommonJS and ESM

CommonJS still works. New code should use ES modules — Node can also require() many ESM packages.

Three kinds of modules

📦 Core

node:fs, node:http, node:path, node:sqlite

📝 Local

Your ./lib/auth.js files

🌐 Packages

Installed from npm / pnpm / yarn

ES modules (recommended)

Set "type": "module" in package.json, or use .mjs / .mts extensions. ESM gives you top-level await, static analysis, and the same syntax as the browser.

// package.json
{ "type": "module" }

// math.js
export const add = (a, b) => a + b;
export default function subtract(a, b) {
    return a - b;
}

// app.js
import subtract, { add } from './math.js';
import { readFile } from 'node:fs/promises';

const text = await readFile('./readme.txt', 'utf8');
console.log(add(2, 3), text);
Always prefix core modules with node: — import fs from 'node:fs' makes it obvious you are not pulling an npm package named fs.

CommonJS (still everywhere)

// math.cjs
function add(a, b) { return a + b; }
module.exports = { add };

// app.cjs
const { add } = require('./math.cjs');
const path = require('node:path');

On Node 22+, require() can load many ESM graphs. Mixed packages still bite — prefer one module system per project.

// ESM equivalent of __dirname
import { fileURLToPath } from 'node:url';
import path from 'node:path';

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

// Node 20.11+ / 22+
console.log(import.meta.dirname);
console.log(import.meta.filename);

9) HTTP servers

A request is just bytes on a socket. Node parses HTTP, your code decides the status and body, then the response streams back.

Built-in http

import http from 'node:http';

const server = http.createServer((req, res) => {
    if (req.method === 'GET' && req.url === '/health') {
        res.writeHead(200, { 'content-type': 'application/json' });
        res.end(JSON.stringify({ ok: true }));
        return;
    }
    res.writeHead(404);
    res.end();
});

server.listen(3000, () => {
    console.log('http://localhost:3000');
});

For real APIs, use Fastify or Express — they handle routing, validation, and plugins. The built-in module is what those frameworks wrap.

10) fetch, WebSocket, and web standards

Node’s HTTP client is Undici. Global fetch is stable. Node 26 ships Undici 8 with stricter header validation — malformed header names now throw.

const ac = new AbortController();
const timer = setTimeout(() => ac.abort(), 5_000);

const res = await fetch('https://api.github.com/repos/nodejs/node', {
    headers: { 'user-agent': 'learning-docs' },
    signal: AbortSignal.timeout(5_000),
});
clearTimeout(timer);

if (!res.ok) throw new Error(`HTTP ${res.status}`);
const repo = await res.json();
console.log(repo.stargazers_count);

const ws = new WebSocket('wss://echo.websocket.org');
ws.addEventListener('open', () => ws.send('hello'));
ws.addEventListener('message', (event) => console.log(event.data));

Headers / FormData / Blob

Same constructors as the browser for multipart uploads and binary bodies.

AbortSignal.timeout

Built-in request deadlines without rolling your own timer.

URLPattern

Match routes with a web-standard pattern API.

11) Streams

Streams move data in chunks so a 2 GB file never sits entirely in RAM. Use them for files, HTTP bodies, compression, and pipes between processes.

Readable → Transform → Writable. pipeline() wires them together and handles backpressure and errors.

Backpressure

If the source is faster than the destination, memory grows until the process dies. Backpressure is the writable side saying “pause.” pipe() and pipeline() do this for you. Manual 'data' listeners do not, unless you pause/resume yourself.

📥 Readable

createReadStream, HTTP request

📤 Writable

createWriteStream, HTTP response

🔄 Duplex

Sockets — both directions

✨ Transform

gzip, crypto, parsers

import { createReadStream, createWriteStream } from 'node:fs';
import { pipeline } from 'node:stream/promises';
import { createGzip } from 'node:zlib';

await pipeline(
    createReadStream('app.log'),
    createGzip(),
    createWriteStream('app.log.gz'),
);

HTTP file download without buffering

import http from 'node:http';
import { createReadStream } from 'node:fs';

http.createServer((req, res) => {
    res.writeHead(200, { 'content-type': 'video/mp4' });
    createReadStream('movie.mp4').pipe(res);
}).listen(3000);

12) Events and EventEmitter

Node is event-driven. HTTP servers, streams, and many core objects inherit EventEmitter.

import { EventEmitter } from 'node:events';

class OrderBus extends EventEmitter {}
const bus = new OrderBus();

bus.on('paid', ({ id }) => console.log('receipt', id));
bus.once('paid', () => console.log('first payment only'));
bus.emit('paid', { id: 'ord_1' });

bus.on('error', (err) => console.error(err));
MethodPurpose
on / offSubscribe / unsubscribe
onceFire a single time
emitDispatch
listenerCountDebug leaks
Always handle the error event on emitters. An unhandled error can crash the process.

13) Buffers

A Buffer is a fixed-size chunk of binary memory outside the V8 heap. Streams, TCP, and files all speak buffers (or Uint8Array).

const buf = Buffer.from('Hello World', 'utf8');
buf.toString('utf8');
buf.toString('hex');

const empty = Buffer.alloc(16);          // zero-filled, safe
const fast = Buffer.allocUnsafe(16);     // may contain old memory

Buffer.concat([buf, Buffer.from('!')]);

Prefer Buffer.alloc over allocUnsafe unless you immediately overwrite every byte. Uint8Array and Buffer are interchangeable in most modern APIs.

14) Native TypeScript

Node strips type syntax at load time. On Node 24+ / 26 you run .ts files with no flags. This is type stripping, not a full TypeScript compiler — enums, namespaces, and parameter properties need a build step (or were covered by the removed --experimental-transform-types flag).

// server.ts
type User = { id: string; name: string };

export function greet(user: User): string {
    return `hello ${user.name}`;
}

console.log(greet({ id: '1', name: 'Ada' }));

// Run
// node server.ts

What works without tsc

  • Interfaces, type aliases, generics, as assertions
  • import type / export type
  • .mts / .cts module variants

What still needs a compiler

  • TypeScript enum and namespace
  • Decorators that emit runtime code (NestJS-style)
  • JSX / TSX

Keep tsc --noEmit (or typescript-eslint) in CI so types are still checked. Node will not type-check for you — it only erases types and runs the leftover JavaScript.

15) Built-in test runner

node:test plus node:assert/strict replaces Jest for a large class of unit and integration tests. Watch mode re-runs on save.

// math.test.ts
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { add } from './math.ts';

test('adds two numbers', () => {
    assert.equal(add(2, 3), 5);
});

test('async fetch mock', async (t) => {
    t.mock.method(globalThis, 'fetch', async () => {
        return new Response(JSON.stringify({ ok: true }), {
            headers: { 'content-type': 'application/json' },
        });
    });
    const res = await fetch('https://example.com');
    assert.equal((await res.json()).ok, true);
});

node --test --watch
node --test --test-reporter=spec
node --experimental-test-coverage

16) Built-in SQLite

node:sqlite is a zero-dependency, synchronous SQLite driver. Stable on Node 24 and 26. Perfect for CLIs, local caches, test fixtures, and single-process apps. It will block the event loop on large queries — do not use it as a busy multi-tenant primary database on the request thread.

import { DatabaseSync } from 'node:sqlite';

const db = new DatabaseSync('app.db'); // or ':memory:'

db.exec(`
  CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY,
    email TEXT UNIQUE NOT NULL
  );
`);

const insert = db.prepare('INSERT INTO users (email) VALUES (?)');
insert.run('ada@example.com');

const row = db.prepare('SELECT * FROM users WHERE email = ?')
    .get('ada@example.com');
console.log(row);

db.close();
Named parameters work too: VALUES ($email) with .run({ $email: 'ada@example.com' }). Wrap related writes in BEGIN / COMMIT.

17) Permission model

Start Node with --permission and the process cannot touch the filesystem, network, child processes, workers, inspector, native addons, WASI, or FFI unless you allow them. This is the right default for untrusted plugins and locked-down CLIs.

node --permission --allow-fs-read=./data --allow-net app.js

# Common allow flags
# --allow-fs-read=...
# --allow-fs-write=...
# --allow-net
# --allow-child-process
# --allow-worker
# --allow-addons
if (!process.permission.has('fs.read', './data/config.json')) {
    throw new Error('missing fs.read for config');
}
The model restricts node:fs. Other modules (including node:sqlite) can still reach disk. Existing file descriptors also bypass checks. Treat it as defense in depth, not a sandbox VM.

20) Worker threads and cluster

I/O stays on the event loop. CPU goes to workers. Multiple processes (cluster or a process manager) use every core for HTTP.

When to use which

Tool Isolation Best for
Event loop None — one thread Sockets, DB, files
worker_threads Same process, shared memory optional CPU: hashing, image, parsing
cluster / PM2 Separate processes Use all cores for an HTTP server
child_process Separate process, any binary ffmpeg, shells, other languages

Worker Threads

// main.ts
import { Worker } from 'node:worker_threads';

const worker = new Worker(new URL('./hash-worker.ts', import.meta.url));
worker.postMessage({ password: 'secret' });
worker.on('message', console.log);

// hash-worker.ts
import { parentPort } from 'node:worker_threads';
import { scryptSync } from 'node:crypto';

parentPort.on('message', ({ password }) => {
    const hash = scryptSync(password, 'salt', 64).toString('hex');
    parentPort.postMessage(hash);
});

cluster

import cluster from 'node:cluster';
import http from 'node:http';
import os from 'node:os';

if (cluster.isPrimary) {
    for (let i = 0; i < os.availableParallelism(); i++) cluster.fork();
    cluster.on('exit', () => cluster.fork());
} else {
    http.createServer((_req, res) => res.end('ok')).listen(8000);
}

In production, many teams skip cluster and run several containers behind a load balancer, or use PM2 / systemd.

21) Child processes

import { execFile, spawn, fork } from 'node:child_process';
import { promisify } from 'node:util';

const execFileAsync = promisify(execFile);
const { stdout } = await execFileAsync('node', ['-v']);

const ls = spawn('git', ['status', '--short']);
ls.stdout.on('data', (chunk) => process.stdout.write(chunk));

const worker = fork('./job.js');
worker.send({ type: 'start' });
worker.on('message', console.log);

Prefer execFile / spawn with an argument array over exec with a shell string — it avoids shell injection. fork is spawn specialized for another Node process with an IPC channel.

AsyncLocalStorage is how you keep a request id across await without passing it through every function — the foundation of tracing and OpenTelemetry in Node.

import { AsyncLocalStorage } from 'node:async_hooks';

const als = new AsyncLocalStorage();

export function withRequestId(id, fn) {
    return als.run({ id }, fn);
}

export function requestId() {
    return als.getStore()?.id;
}

26) Best practices

Do

  • Use ESM + the node: prefix for core modules
  • Run an LTS line (24 now, 26 after October 2026) in production
  • Type-check in CI even if Node strips types at runtime
  • Prefer fs/promises, pipeline, and fetch with timeouts
  • Handle unhandledRejection and error events
  • Keep secrets in env files that never hit git; load with --env-file
  • Pin engines in package.json: "engines": { "node": ">=24" }

Don't

  • Block the event loop with sync I/O or big CPU on the request path
  • Swallow errors in empty catch blocks
  • Commit .env or mix lockfiles from npm and pnpm
  • Assume node:sqlite is a Postgres replacement

Security

  • Helmet (or equivalent headers) behind HTTPS
  • Validate input (JSON Schema, Zod, Fastify schemas)
  • Rate-limit public routes
  • npm audit / pnpm audit in CI
  • Consider --permission for plugins and untrusted scripts
  • Never build shell strings from user input — use execFile
