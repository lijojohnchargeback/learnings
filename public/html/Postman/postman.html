📚 Introduction to Postman

Postman is a powerful API development and testing tool that simplifies the process of building, testing, and documenting APIs.

What is Postman?

  • ✅ API Testing Platform: Test REST, SOAP, and GraphQL APIs
  • ✅ Collaboration Tool: Share collections with team members
  • ✅ Automation: Run automated tests and monitor APIs
  • ✅ Documentation: Auto-generate API documentation

Key Features

  • 🔹 Collections: Group related API requests
  • 🔹 Environments: Manage variables for different setups
  • 🔹 Tests: Write automated tests using JavaScript
  • 🔹 Mock Servers: Simulate API responses
  • 🔹 Monitoring: Schedule API tests

🌐 HTTP Methods

GET Method

GET is used to retrieve data from a server. It should not modify server data.

Real-World Use Cases:

  • 📖 Fetching user profile information
  • 📖 Loading product lists from e-commerce site
  • 📖 Getting weather data from API

Query Parameters

Query params (query strings) help filter data. They start after ? and use & to separate multiple params.

// GET with query parameters GET https://api.example.com/products?category=electronics&price_max=1000 // Multiple query parameters GET https://api.example.com/users?role=admin&status=active&page=2 // Real example: Search GitHub repositories GET https://api.github.com/search/repositories?q=javascript&sort=stars

Path Variables

Path variables are part of the URL path and typically represent specific resources (IDs).

// GET with path variable (user ID) GET https://api.example.com/users/12345 // GET product by ID GET https://api.example.com/products/987 // GET order details GET https://api.example.com/orders/ORD-2024-001
Feature Query Parameters Path Variables
Format ?key=value&key2=value2 /users/123
Required Optional Mandatory
Use Case Filtering, sorting, pagination Identifying specific resources

POST Method

POST is used to send data to create a new resource on the server.

// POST - Create new user POST https://api.example.com/users Content-Type: application/json { "name": "John Doe", "email": "john@example.com", "age": 30 } // Real example: Create new order POST https://api.example.com/orders { "userId": 123, "items": [ {"productId": 456, "quantity": 2}, {"productId": 789, "quantity": 1} ], "totalAmount": 299.99 }

PUT vs PATCH

Method PUT PATCH
Purpose Replace entire resource Update specific fields
Data Sent Complete object Only changed fields
Example Replace user profile Update user email only
// PUT - Replace entire user PUT https://api.example.com/users/123 { "name": "John Smith", "email": "john.smith@example.com", "age": 31, "address": "123 Main St" } // PATCH - Update only email PATCH https://api.example.com/users/123 { "email": "newemail@example.com" }

DELETE Method

// DELETE - Remove user DELETE https://api.example.com/users/123 // DELETE - Remove product from cart DELETE https://api.example.com/cart/items/456

HEAD Method

HEAD is used to check if an API is working without getting the response body.

// HEAD - Check if resource exists HEAD https://api.example.com/users/123 // Response: Only headers, no body // Status: 200 OK means user exists

📁 Collections & Variables

What is a Collection?

A collection is a group of related API requests organized together.

Benefits of Collections:

  • ✅ Organize requests by feature or module
  • ✅ Share with team members
  • ✅ Run all requests together
  • ✅ Export and version control

Variables in Postman

1. Collection Variables

Variables scoped to a specific collection

// Set collection variable in Tests tab pm.collectionVariables.set("userId", 12345); // Get collection variable const userId = pm.collectionVariables.get("userId"); // Use in URL: {{userId}} GET https://api.example.com/users/{{userId}}

2. Environment Variables

Variables for different environments (dev, staging, production)

// Set environment variable pm.environment.set("baseUrl", "https://api.example.com"); pm.environment.set("apiKey", "secret-key-123"); // Get environment variable const baseUrl = pm.environment.get("baseUrl"); // Use in request GET {{baseUrl}}/users Headers: Authorization: Bearer {{apiKey}}

3. Global Variables

// Set global variable pm.globals.set("token", "eyJhbGc..."); // Get global variable const token = pm.globals.get("token"); // Clear variable pm.globals.unset("token");

⚠️ Security Best Practice:

Never store passwords in Initial Value - they are visible to anyone with access to the collection. Use Current Value instead, which is local to your machine.

🧪 API Testing

Types of Testing

1. Unit Testing

Testing individual components in isolation

Test each API endpoint separately to ensure it works correctly

2. Integration Testing

Testing combined components working together

3. End-to-End Testing

Testing complete user workflows from start to finish

// E2E Example: User Registration Flow // 1. Register user // 2. Login with credentials // 3. Get user profile // 4. Update profile // 5. Delete account

Writing Tests in Postman

Status Code Testing

// Test 200 OK status pm.test("Status code is 200", function() { pm.response.to.have.status(200); }); // Alternative syntax pm.test("Status is 200", () => { pm.expect(pm.response.code).to.equal(200); }); // Test multiple status codes pm.test("Status is 201 or 202", () => { pm.expect(pm.response.code).to.be.oneOf([201, 202]); });

Response Body Testing

// Get response as JSON const response = pm.response.json(); // Test response type pm.test("Response is an object", () => { pm.expect(response).to.be.an("object"); }); pm.test("Users is an array", () => { pm.expect(response.users).to.be.an("array"); }); // Test field values pm.test("Status is true", () => { pm.expect(response.status).to.be.true; }); pm.test("Job status is completed", () => { pm.expect(response.job_status).to.eql("Completed"); });

Response Time Testing

// Test response time pm.test("Response time is less than 500ms", () => { pm.expect(pm.response.responseTime).to.be.below(500); });

Real-World Testing Example

// Complete test suite for user API pm.test("User API Tests", () => { const response = pm.response.json(); // Status check pm.response.to.have.status(200); // Structure validation pm.expect(response).to.have.property("data"); pm.expect(response.data).to.be.an("object"); // Field validation pm.expect(response.data.email).to.include("@"); pm.expect(response.data.age).to.be.above(18); // Save user ID for next request pm.collectionVariables.set("userId", response.data.id); });

🤖 Automation & Runner

Collection Runner

Run entire collections automatically to test multiple requests sequentially.

Use Cases:

  • 🔄 Run regression tests
  • 🔄 Test with different data sets
  • 🔄 Validate complete workflows
  • 🔄 Generate test reports

Postman CLI (Newman)

# Install Newman npm install -g newman # Run collection newman run collection.json # Run with environment newman run collection.json -e environment.json # Generate HTML report newman run collection.json -r html

📊 HTTP Status Codes

1xx - Informational

Code Message Meaning
100 Continue Request received, continue with request
101 Switching Protocols Server switching protocols

2xx - Success

Code Message When to Use
200 OK Successful GET, PUT, PATCH
201 Created Resource successfully created (POST)
204 No Content Successful DELETE

3xx - Redirection

Code Message Meaning
301 Moved Permanently Resource permanently moved
303 See Other Response found at different URL

4xx - Client Errors

Code Message Common Cause
400 Bad Request Invalid request format/data
401 Unauthorized Missing or invalid authentication
403 Forbidden Authenticated but no permission
404 Not Found Resource doesn't exist

5xx - Server Errors

Code Message Meaning
500 Internal Server Error Server encountered an error
502 Bad Gateway Invalid response from upstream
503 Service Unavailable Server temporarily unavailable
