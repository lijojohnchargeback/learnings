🤝 6. AI Agents & Multi-Agent Systems

Step 6 of 12 — An agent is an LLM in a loop with tools, state, and a stop condition — not a personality.

When to use an agent

Use an agent when the task needs multiple steps, unknown tool order, or branching. Do not use an agent for a single RAG call or a form fill. Agents multiply cost, latency, and failure modes. Production agents need timeouts, max steps, human-in-the-loop for side effects, and full traces.

Learning steps (in order)

StepFocusDone when
1LoopYou can write observe → think → act → observe without a framework
2PlanningYou know plan-then-act vs ReAct vs graph routing
3ToolsEvery tool has a schema, timeout, and idempotency story
4MemoryYou split working memory vs long-term vs RAG

6FrameworksYou pick one graph-style runtime and ignore the rest until you need them

Agent loops

The minimal loop: model chooses a tool or a final answer; you execute the tool; you append the result; repeat until done or max_steps.

def run_agent(user: str, tools: dict, max_steps: int = 8) -> str: messages = [{"role": "user", "content": user}] for _ in range(max_steps): msg = llm_with_tools(messages, tools) if msg.tool_calls: messages.append(msg) for call in msg.tool_calls: result = tools[call.name](**call.args) messages.append({"role": "tool", "tool_call_id": call.id, "content": result}) continue return msg.content return "Stopped: max steps reached."
Always cap steps, tokens, and wall-clock time. Infinite loops are a billing incident.

Planning

StyleHowRisk
ReActInterleave thought + tool in one modelVerbose; can wander
Plan-and-executeWrite a plan, then run stepsStale plans when the world changes
Router / graphDeterministic nodes + LLM only at decision pointsMore code, much more control

Production systems trend toward graphs: you own the edges (auth, retries, approvals); the LLM fills slots, not the whole control plane.

Tools

Tools are functions with JSON schemas. Treat them like public APIs: validate args, least privilege, no raw SQL from the model, confirm before emails/payments/deletes.

TOOLS = [{ "type": "function", "function": { "name": "search_docs", "description": "Search internal docs. Read-only.", "parameters": { "type": "object", "properties": {"query": {"type": "string"}}, "required": ["query"] } } }]

Memory

  • Working: the current messages / scratchpad (fits in context)
  • Episodic: summaries of past threads
  • Semantic: RAG over facts, tickets, code
  • Profile: user prefs stored in a DB, not hoped-for in the prompt

Do not "let the agent remember" by stuffing unbounded history. Summarize, retrieve, and store structured facts.

State

Durable state is a checkpoint: thread id, node, tool results, pending approval. If the process dies mid-tool, you must not double-charge a customer. Use idempotency keys on side-effecting tools.

LangGraph

Graph runtime from the LangChain team: nodes, edges, conditional routing, persistence. Good when you want explicit control flow (support bot: retrieve → generate → grade → retry) instead of a free-form ReAct soup.

Learn: StateGraph, reducers, checkpointers, human-in-the-loop interrupts.

LangChain

Ecosystem of model/tool/document loaders. Useful for prototyping. In production, keep the surface small: you own prompts, retrieval, and tracing. Avoid mega-chains you cannot debug.

CrewAI

Role-based multi-agent: researcher, writer, reviewer. Fine for content workflows with a human editor. Risky for ops: more agents = more latency and contradictory tools. If you use it, pin tasks, share one retrieval layer, and log every agent’s output.

OpenAI Agents

OpenAI’s agents SDK: handoffs, tools, tracing, guardrails, close to their API. Good if you are already on that stack. Same rules apply: schemas, max turns, approvals.

Google ADK

Google Agent Development Kit — agents, tools, and orchestration aimed at Gemini / Vertex. Use when your enterprise is already on GCP. Compare on tracing, eval, and how tools map to IAM — not on demo videos.

Multi-agent rule: Prefer a supervisor that routes to specialists over a debating committee. Specialists should not all have write access to production.

Checkpoint — move on when

  • You can implement a tool loop with max steps without a framework
  • You can draw a graph for a real workflow (retrieve, act, approve, reply)
  • You persist state and never fire a payment tool twice by accident
