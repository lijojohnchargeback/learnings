☁️ 10. Cloud AI & AI Infrastructure

Step 10 of 12 — Managed model APIs vs train/serve yourself, plus where the app runs.

The three-layer split

Production AI infrastructure is not “pick a cloud logo.” It is three layers you mix deliberately: foundation model APIs (Bedrock, Vertex, Azure Foundry), custom train/serve (SageMaker, Vertex Training, Azure ML, self-hosted GPUs), and app compute (Cloud Run, Kubernetes). Most products start on a managed chat API and add GPU serving only when cost, latency, or data gravity forces it.

Read top → bottom. Layer 1 is calling someone else’s weights. Layer 2 is owning weights and GPU fleets. Layer 3 is where your FastAPI / RAG / workers live. The dashed arrows are the two common call paths — start with managed APIs.

Managed models

IAM, quotas, guardrails, and a model ID in config. Fastest path to a product when you do not need custom weights.

Custom train/serve

Fine-tunes, open LLMs, private endpoints. You pay for GPUs whether traffic is busy or idle — measure utilization.

App compute

Gateways, RAG, agents, workers. Scale-to-zero containers first; graduate to Kubernetes when GPUs and multi-service demand it.

Canonical progression

  1. Call one managed LLM API with IAM, private networking, logging, and quotas
  2. Deploy the app API on Cloud Run (or cousin) behind auth
  3. Add custom GPU serving only with a cost/latency/data reason
  4. Move to EKS/GKE/AKS when you need long-running GPUs, mesh, or many services

How to choose

Start from the need, not the coolest SKU. Enterprise shops almost always inherit a cloud from data and IAM — stay there unless compliance or cost forces a second home.

Four forks. Fastest LLM path → managed catalogs. Own weights → train/serve platforms. HTTP scale-to-zero → Cloud Run cousins. Long GPU + mesh → managed Kubernetes. The footer badges are non-optional on every path.
NeedLean towardWatch out
Fastest enterprise path, many modelsBedrock / Vertex / Azure FoundryQuotas, region availability, data-residency flags
Fine-tune + host your weightsSageMaker, Vertex, Azure ML, or self-host on GPU nodesIdle GPUs dominate the bill
Scale-to-zero HTTP APIsCloud Run, Lambda, Azure Container AppsTimeouts, cold starts, GPU availability
Long-running GPU, custom mesh, multi-serviceEKS / GKE / AKSYou own node pools, operators, and packing
Always: VPC endpoints / Private Link where possible, customer-managed keys if required, no public GPU notebooks with secrets, model IDs and regions as config — never hard-coded in app logic.

AWS Bedrock

Managed access to Anthropic, Amazon, Meta, and others on AWS. Use IAM roles (not long-lived keys), CloudWatch metrics, Guardrails, Knowledge Bases (managed RAG), and Agents. Best when the rest of the company is already on AWS. Invoke via SDK; treat model IDs and inference profiles as config.

# boto3 sketch — model id from env/config import boto3, json, os brt = boto3.client("bedrock-runtime", region_name=os.environ["AWS_REGION"]) resp = brt.invoke_model( modelId=os.environ["BEDROCK_MODEL_ID"], body=json.dumps({ "anthropic_version": "bedrock-2023-05-31", "max_tokens": 256, "messages": [{"role": "user", "content": "Summarize the ticket."}], }), )
FeatureWhy it matters
IAM + VPC endpointsNo public internet for model calls in regulated stacks
GuardrailsCentral policy for PII / topics without rewriting every prompt
Knowledge BasesManaged RAG when you accept vendor chunking tradeoffs
Provisioned throughputBuy capacity when on-demand quotas throttle you
Cross-region inferenceUse only when residency policy allows
Quotas are a product feature. Load-test early. A silent 429 storm looks like “the model is down” to users.

GCP Vertex AI

Gemini + Model Garden + Vector Search + pipelines + Agent Builder. Strong if you want Google models and GCP data (BigQuery). Vertex Prediction hosts custom containers. Wire IAM and VPC Service Controls for regulated data.

  • Gemini / Model Garden: managed chat and embeddings with GCP IAM
  • Vertex AI Search / Vector Search: managed retrieval when you stay in GCP
  • Custom prediction: your container on GPUs when you own the serving stack
  • Pipelines: training and eval jobs with Artifact Registry images
BigQuery adjacency is the usual reason teams pick Vertex: feature tables and eval sets already live next door.

Azure AI Foundry

Azure’s hub for models (including Azure OpenAI), evaluations, and content safety. Fits Microsoft 365 / Entra shops. Foundry is the productized “model catalog + playground + deploy” layer on top of Azure ML / OpenAI resources.

SageMaker

Train, tune, and host custom models (including open LLMs) on AWS. Endpoints, batch transform, pipelines, Feature Store. Heavier than Bedrock. Use when you own the weights or need a private GPU fleet with AWS ops.

ModeWhen
Training / Tuning jobsFine-tunes, LoRA, classic ML on managed clusters
Real-time endpointsLow-latency custom models; pay for instance hours
Serverless / async inferenceSpiky or long-running jobs without always-on nodes
Batch transformOffline scoring of large corpora
Pipelines + Model RegistryPromotion gates, approved images, lineage
Endpoints are not free when idle. Autoscale to zero where supported, or schedule capacity. Compare $/1M tokens on Bedrock vs GPU hours before you “save money” by self-hosting.

Azure Machine Learning

Classic MLOps on Azure: workspaces, compute clusters, jobs, managed endpoints. Use for custom training and SKLearn/PyTorch jobs; use Foundry/OpenAI for hosted frontier models. Same discipline: environments, registries, approved base images.

  • Workspaces isolate projects; registries share models across them
  • Managed online endpoints wrap scoring containers with auth and scale rules
  • Keep training images in ACR; pin digests, not floating latest

GPU serving layout

When you host open models (vLLM, TGI, TensorRT-LLM), the API gateway stays on CPU; GPUs sit behind a router that cares about queue depth and KV cache, not only CPU utilization.

CPU in front, GPU in back. Continuous batching and KV cache dominate throughput. Autoscale on queue depth. One large replica can idle an entire node — measure before you buy more.
ConceptWhy it matters
Continuous batchingPack many requests onto one GPU without waiting for a full batch
KV cacheMemory bound; long contexts shrink concurrent slots
Tensor / pipeline parallelSplit large models across GPUs; adds complexity and failure modes
Quantization (AWQ/GPTQ/FP8)Fit bigger models; measure quality on your golden set
Scale on queue depthCPU HPA alone will not scale GPU workers correctly

Cloud Run (and cousins)

Container → HTTPS, scale to zero, pay per request. Perfect for FastAPI gateways and light RAG. Limits: request timeout, concurrency settings, and GPU availability (GPU Cloud Run exists in some regions — check current quotas). Put heavy ingest on Cloud Tasks / Pub/Sub workers instead of the request path.

Start left; graduate right. Cloud Run for gateways and light workers. Kubernetes when you need sticky GPUs, many services, and custom networking. The center arrow is a product decision, not a resume decision.

EKS / GKE / AKS

Managed Kubernetes. You still own: node pools (CPU vs GPU), NVIDIA device plugin / GPU operator, autoscaling, ingress, secrets, network policies. Typical AI layout: API Deployment, worker Deployment (GPU), Redis, and a vector DB (in-cluster or managed).

ObjectAI use
Deployment + HPAScale chat API on CPU/RPS
GPU node poolvLLM / TGI; scale on queue depth, not only CPU
Job / CronJobEval, re-embed, batch inference
Ingress / GatewayTLS, WAF, auth at the edge
NetworkPolicyGPU workers only talk to the API / model ports you allow
External SecretsPull keys from cloud secret managers — never bake into images
GPU bins pack badly. One 70B replica can idle a whole node. Measure utilization before you add nodes. Prefer fewer larger nodes only when parallelism requires it.

Advanced topics

Advanced cloud AI is not more logos — it is control planes, money, and blast radius. These topics show up the moment you leave a demo notebook.

Six control surfaces. Networking, failover, cost, routing, platform security, and hybrid/edge. Master these after you can deploy one API and one managed model call cleanly.

Blast radius

Private endpoints, scoped IAM, and per-env model IDs keep a leaked key from becoming a company-wide incident.

Money meters

Tokens and GPU-hours both have unit economics. Tag every call with tenant and feature for FinOps.

Resilience

Timeouts, fallbacks, multi-region, and circuit breakers — LLMs fail as often as any other SaaS dependency.

Private networking

Regulated stacks do not call public model endpoints from the open internet. Prefer VPC endpoints / Private Link / Private Service Connect, private DNS, and egress controls so only approved hosts can leave the VPC.

PatternPractice
Private model accessBedrock/Vertex/Azure OpenAI via private endpoints
Egress allowlistsAPI pods may only reach model + vector DB hosts
No public notebooksDev boxes in private subnets with brokered auth
mTLS / service meshWhen many internal AI services talk to each other
Data residency: region pick is a compliance control. Cross-region inference and global load balancers can silently move data — document the path.

Model routing & fallbacks

Production gateways rarely hard-wire one model. Route by task (cheap model for classify, strong model for reason), and fail over on timeouts, 429s, and regional outages.

# Conceptual router def complete(task: str, prompt: str) -> str: primary = MODELS[task]["primary"] backup = MODELS[task]["backup"] try: return call(primary, prompt, timeout_s=20) except (Timeout, RateLimit, Unavailable): return call(backup, prompt, timeout_s=30)
  • Task routing: embeddings ≠ chat ≠ rerank — different SLOs and prices
  • Canary: send 5% to a new model id; compare quality + cost before cutover
  • Circuit breaker: stop hammering a failing region; open the backup path
  • Idempotency: retries must not double-charge side effects (tickets, emails)

FinOps for tokens & GPUs

Cloud AI bills hide in two meters: tokens in/out on managed APIs and GPU-hours on self-hosted fleets. Tag every request with tenant, feature, and model_id.

LeverEffect
Smaller / cheaper model for easy tasksBiggest durable win after prompt slimming
Cache embeddings & frequent answersCuts repeat spend on RAG and FAQ traffic
Truncate context aggressivelyInput tokens dominate many RAG bills
Autoscale GPUs / schedule offline jobsStops paying full price for idle night capacity
Provisioned throughput vs on-demandTrade commitment for stable latency under load
Spot / preemptible for batchEval and re-embed jobs — never for user-facing p95
Self-hosting is not automatically cheaper. Include idle time, engineering ops, and eval cost. Run the spreadsheet before the migration.

Multi-region & failover

Treat model APIs like any critical dependency: health checks, regional failover, and clear RTO/RPO. Stateless gateways are easy to multi-home; GPU fleets and vector indexes are not.

  • Active-passive: primary region serves; standby warm for model + app
  • Active-active: only when data stores (sessions, indexes) can multi-master or shard cleanly
  • Stateless first: put sticky state in managed DBs/caches with their own DR story
  • Drill: game-day kill a region and watch the router + alerts, not just the architecture slide

Hybrid & edge inference

Some workloads cannot leave the building: air-gapped plants, hospital networks, factory cameras. Pattern: cloud for training / heavy models where allowed; on-prem or edge GPUs for inference with strict egress.

PatternWhen
Cloud API onlyDefault SaaS; data policy allows egress
VPC-private cloud modelsEnterprise SaaS with residency controls
On-prem inference + cloud control planeWeights stay local; metrics/config sync out
Edge devicesLatency < tens of ms or intermittent connectivity
Ops tax: hybrid means two patch trains, two secret stores, and two incident runbooks. Budget for that before you celebrate “air gap.”

Secure ML platforms

Cloud AI security is platform engineering: approved images, secret managers, CMKs, and no long-lived keys in notebooks. Align with your company’s landing zone — do not invent a parallel identity system for “the ML team.”

ControlPractice
IdentityWorkload identity / IRSA / managed identities — short-lived tokens
KeysCMKs for model artifacts, vector indexes, and logs when required
ImagesPinned digests from a private registry; scan on push
NotebooksNo prod secrets; brokered access; auto-shutdown
AuditLog model id, principal, tenant, and prompt/response policy (retain carefully)
Supply chainSign serving images; verify at deploy
Prompt logs are sensitive. They can contain PII and secrets users pasted. Encrypt, retain with policy, and restrict who can replay traces.

Checkpoint — move on when

  • You can deploy an AI API on your company’s cloud with IAM (not a laptop key)
  • You can explain Bedrock/Vertex/Foundry vs SageMaker/Azure ML vs Cloud Run/K8s
  • You know when Cloud Run is enough and when you need a GPU cluster
  • You can sketch private networking, a fallback router, and a basic FinOps tag scheme
  • You can say when hybrid/edge is justified — and what ops tax it adds
