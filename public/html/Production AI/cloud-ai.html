☁️ 10. Cloud AI & AI Infrastructure

Step 10 of 12 — Managed model APIs vs train/serve yourself, plus where the app runs.

The split

Foundation models (Bedrock, Vertex, Azure OpenAI / Foundry) vs custom training/serving (SageMaker, Vertex Training, Azure ML) vs app compute (Cloud Run, Kubernetes). Most products start on a managed chat API and add GPU serving only when cost, latency, or data gravity forces it.

How to choose

NeedLean toward
Fastest enterprise path, many modelsBedrock / Vertex / Azure Foundry
Fine-tune + host your weightsSageMaker, Vertex, Azure ML, or self-host on GPU nodes
Scale-to-zero HTTP APIsCloud Run, Lambda, Azure Container Apps

Always: VPC endpoints where possible, customer-managed keys if required, no public GPU notebooks with secrets.

AWS Bedrock

Managed access to Anthropic, Amazon, Meta, etc. on AWS. Use IAM, CloudWatch, Guardrails, Knowledge Bases (managed RAG), Agents. Good when the rest of the company is already on AWS. Invoke via SDK; treat model IDs as config.

# boto3 sketch import boto3, json brt = boto3.client("bedrock-runtime", region_name="us-east-1") resp = brt.invoke_model( modelId="anthropic.claude-sonnet-4-20250514-v1:0", body=json.dumps({"anthropic_version": "bedrock-2023-05-31", "max_tokens": 256, "messages": [...]}), )

SageMaker

Train, tune, and host custom models (including open LLMs) on AWS. Endpoints, batch transform, pipelines, Feature Store. Heavier than Bedrock. Use when you own the weights or need a private GPU fleet with AWS ops.

GCP Vertex AI

Gemini + Model Garden + Vector Search + pipelines + Agent Builder. Strong if you want Google models and GCP data (BigQuery). Vertex Prediction hosts custom containers. Wire IAM and VPC-SC for regulated data.

Azure AI Foundry

Azure’s hub for models (including Azure OpenAI), evaluations, and content safety. Fits Microsoft 365 / Entra shops. Foundry is the productized "model catalog + playground + deploy" layer on top of Azure ML/OpenAI resources.

Azure Machine Learning

Classic MLOps on Azure: workspaces, compute clusters, jobs, managed endpoints. Use for custom training and SKLearn/PyTorch jobs; use Foundry/OpenAI for hosted frontier models. Same discipline: environments, registries, approved base images.

Cloud Run (and cousins)

Container → HTTPS, scale to zero, pay per request. Perfect for FastAPI gateways and light RAG. Limits: request timeout, no sticky GPU (GPU Cloud Run exists in some regions — check current quotas). Put heavy ingest on Cloud Tasks / Pub/Sub workers instead.

gcloud run deploy ai-api --source . --region us-central1 --allow-unauthenticated=false

EKS / GKE / AKS

Managed Kubernetes. You still own: node pools (CPU vs GPU), NVIDIA device plugin, autoscaling, ingress, secrets, network policies. Typical AI layout: API Deployment, worker Deployment (GPU), Redis, and a vector DB (in-cluster or managed).

GPU bins pack badly. One 70B replica can idle a whole node. Measure utilization before you add nodes.

Checkpoint — move on when

  • You can deploy an AI API on your company’s cloud with IAM (not a laptop key)
  • You can explain Bedrock/Vertex/Foundry vs SageMaker/Azure ML
  • You know when Cloud Run is enough and when you need a GPU cluster
