🚀 11. Production AI / LLMOps / MLOps

Step 11 of 12 — If you cannot deploy, observe, evaluate, and roll back, you do not have a production system.

MLOps vs LLMOps

MLOps is training pipelines, registries, feature stores, drift. LLMOps adds prompt/versioning, traces, token cost, retrieval indexes, and non-deterministic eval. You still need Docker, Kubernetes (or a PaaS), CI/CD, and SLOs. Ship the gateway like any other microservice, then add model-specific gates.

Docker

Pin base images, install only what you need, copy lockfiles, run as non-root, and use multi-stage builds. GPU images need matching CUDA. Never bake API keys into layers.

FROM python:3.12-slim WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt COPY . . USER 1000 EXPOSE 8000 HEALTHCHECK CMD python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health')" CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

Kubernetes

Readiness vs liveness: a model loading should be unready, not killed. Resource requests/limits for CPU; for GPUs, nvidia.com/gpu: 1. Use PDBs so you do not evict the only replica. ConfigMaps for prompt versions if you must; prefer an artifact store.

CI/CD

  • PR: unit tests, lint, secret scan, tiny eval set
  • Main: build image, full eval job, deploy staging
  • Prod: canary or blue/green; keep previous prompt+model pair rollbackable

Version together: model_id, prompt_hash, index_version, app_git_sha.

Evaluation

Offline: golden Q&A, RAGAS-style faithfulness, tool-call exact match, safety suites. Online: thumbs, implicit (retry, hangup), shadow traffic. LLM-as-judge needs a held-out human audit. Gate releases on a scorecard, not vibes.

# eval.yml (conceptual) gate: faithfulness_min: 0.85 hit_at_5_min: 0.7 p95_latency_ms_max: 2500 cost_per_query_usd_max: 0.02

Observability

Logs, metrics, traces. For LLMs add: Langfuse, Phoenix, Braintrust, OpenTelemetry spans around retrieve/generate/tools. Redact PII. Sample raw prompts if legally allowed. Dashboards: error rate, p95, tokens, $/day, tool failure rate, eval score over time.

Reliability

Timeouts, retries (idempotent GETs only), circuit breakers, fallback model, graceful degradation (keyword search if vector DB is down). SLOs: availability and latency. Error budgets for prompt experiments. Chaos: kill a replica, expire a vendor key in staging.

Scaling

Scale the API on RPS/CPU. Scale workers on queue depth. Scale GPU servers on KV cache and concurrent sequences, not HTTP alone. Backpressure: 429 the client rather than melting the GPU. Separate ingest from query paths.

Caching

CacheWhat
Exact prompt cacheIdentical requests (rare in chat, common in classification)
Semantic cacheNear-duplicate questions — watch correctness
Embedding cacheSame chunk text → skip re-embed
Provider prompt cacheAnthropic/OpenAI cached prefixes for long system+docs
HTTP CDNStatic assets, never personalized model output unless keyed

Model serving

Do not serve 70B models with a naive generate() loop. Use vLLM, TGI, TensorRT-LLM, or a cloud endpoint. Features you want: continuous batching, paged KV cache, streaming, LoRA multiplex, metrics. Put a queue in front for bursty traffic.

GPUs in production

Binpack sequences, watch fragmentation, use MIG only if it matches your models. Mixed precision. Quantize when quality evals pass. Multi-GPU: tensor parallel for big models, replica parallel for small ones. Cost = (GPU-hours) + (idle time). Autoscale to zero only if cold start is acceptable.

Checkpoint — move on when

  • You can roll back a prompt+model+index as one unit
  • You have traces and a CI eval gate
  • You can explain how you would 10× traffic without 10× GPU spend (batching, cache, smaller models)
