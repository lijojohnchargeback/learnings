🔌 7. MCP, Tools & AI Automation

Step 7 of 12 — Standardize how models call the world: protocols, APIs, and workflow engines.

Two layers

Tooling for agents/IDEs (MCP, function calling) and business automation (n8n, Make, Zapier, queues). Production AI engineers build the first and often wire the second. The shared rule: least privilege, audit logs, and no secrets in prompts.

MCP (Model Context Protocol)

MCP is an open protocol for connecting AI apps to tools and data: resources (read), prompts (templates), and tools (actions). Clients (Cursor, Claude Desktop, custom agents) speak MCP to servers you run.

PrimitiveUse
ToolsActions: create ticket, query metrics
ResourcesReadable context: files, tickets, schemas
PromptsReusable instruction packs
# Conceptual MCP server (Python SDK pattern) # - list_tools / call_tool # - list_resources / read_resource # Transport: stdio for local IDEs, Streamable HTTP for remote
Production MCP: authenticate remote servers, scope tools per user, rate-limit, and never mount a shell tool on a shared server.

Function calling

Vendor-native tool calling (OpenAI, Anthropic, Gemini) is how models emit structured tool requests. MCP often sits underneath as the catalog; the model still needs a schema. Validate arguments server-side even if the model "promised" types.

APIs as tools

Each external API becomes a narrow tool, not a generic http_request. Allowlist hosts. Inject auth from a secret store. Map 4xx to the model as "user error" and 5xx as "retry later."

ALLOWED = {"https://api.github.com"} async def github_get(path: str) -> str: url = "https://api.github.com" + path if not url.startswith(tuple(ALLOWED)): raise ValueError("host not allowed") # Authorization: Bearer from env, never from the model ...

Database tools

Prefer parameterized queries and views. Give the agent a small set of queries (get_order, list_open_tickets), not "run any SQL." For analytics, a read replica and a row limit.

Never: execute(user_sql) from the model. Prompt injection + SQL = data breach.

n8n

Open, self-hostable workflow tool. Good for ops: webhook → LLM node → Slack/ticket. You can keep data in your VPC. Treat workflows as code: export, review, version. Put API keys in n8n credentials, not in node fields that get logged.

Make

Visual automation (formerly Integromat). Strong SaaS connectors. Same caution as Zapier: great for internal glue, weak as the core of a product SLA unless you add monitoring and retries you control.

Zapier

Fastest way to connect SaaS for non-engineers. AI actions exist, but you still need: rate limits, PII policy, and an owner. Promote critical paths to your own workers when volume or compliance grows.

Workflows

A workflow is a directed graph with retries: ingest → classify → human review → notify. LLMs are steps, not the orchestrator of record. Use Temporal, Step Functions, or a simple queue if you need durability. Visual tools are for edges; your domain logic belongs in tested functions.

Event-driven automation

Triggers: webhooks, pub/sub, inbox, cron. Pattern: event → validate signature → enqueue → worker → LLM/tool → persist → emit result. Idempotency key = event id. Dead-letter after N failures. Alert on queue depth.

# Webhook handler sketch def handle_stripe(event): if seen(event["id"]): return enqueue("refund.review", event) mark_seen(event["id"])

Checkpoint — move on when

  • You can ship an MCP or function-calling tool with auth and an allowlist
  • You can explain when to use n8n vs a queue worker
  • You never let a model run arbitrary SQL or HTTP
