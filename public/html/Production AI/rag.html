📚 5. RAG & Knowledge Engineering

Step 5 of 12 — Retrieve the right evidence, then generate. Most "hallucinations" are retrieval failures.

What RAG is

Retrieval-Augmented Generation fetches relevant documents at query time and puts them in the prompt so the model answers from your data. Knowledge engineering is the boring work that makes it true: parsing, chunking, metadata, ACLs, freshness, and evals.

Canonical pipeline

  1. Ingest: parse PDF/HTML/tickets → clean text + metadata
  2. Chunk + embed + index
  3. Query: embed question → retrieve → (optional) rerank
  4. Generate with citations → log → evaluate

Embeddings

An embedding is a dense vector that places similar meaning nearby. Use a dedicated embedding model (not a chat model). Same model at index time and query time. Watch dimension, multilingual support, and instruction prefixes (e.g. "query:" vs "passage:").

from openai import OpenAI client = OpenAI() def embed(texts: list[str]) -> list[list[float]]: r = client.embeddings.create(model="text-embedding-3-small", input=texts) return [d.embedding for d in r.data]
Never mix models in one index. Re-embed everything if you change the embedding model.

Vector databases

Stores vectors + metadata and runs ANN search (HNSW, IVF). Options: pgvector (start here if you already have Postgres), Pinecone, Weaviate, Qdrant, Chroma, OpenSearch k-NN.

Chunking

Chunks are the unit of retrieval. Too big: diluted similarity. Too small: missing context. Overlap helps sentences that straddle a boundary. Prefer structure: headings, pages, tickets, functions — not only N characters.

def chunk(text: str, size: int = 800, overlap: int = 120) -> list[str]: out, i = [], 0 while i < len(text): out.append(text[i:i + size]) i += size - overlap return out

Better: split on markdown headings, then pack until a token budget. Keep source, title, page, updated_at on every chunk.

Retrieval

Query rewrite, HyDE (hypothetical document), and multi-query can lift recall. Always log the retrieved chunk ids. If the answer is wrong, first ask: was the evidence in top-k?

def retrieve(q: str, k: int = 8, tenant: str | None = None): qv = embed([q])[0] filt = {"tenant": tenant} if tenant else None return vector_db.query(qv, top_k=k, filter=filt)

Reranking

Bi-encoders (embeddings) are fast and approximate. A cross-encoder reranker reads query+chunk together and scores relevance. Pattern: retrieve 50, rerank to 5. Worth it when latency budget allows (~50–200ms extra).

Hybrid search

Keyword search (BM25) wins on SKUs, error codes, names, and exact phrases. Vectors win on paraphrase. Fuse with RRF (reciprocal rank fusion) or a weighted score. This is the production default for support and docs.

def rrf(rank_lists, k=60): scores = {} for ranks in rank_lists: for r, doc_id in enumerate(ranks, start=1): scores[doc_id] = scores.get(doc_id, 0) + 1.0 / (k + r) return sorted(scores, key=scores.get, reverse=True)

Multimodal RAG

PDFs are not text. Tables, screenshots, and diagrams need OCR, table extractors, or vision embeddings. Options: caption images into text and embed; or use a multimodal embedding space (image+text). Store the original asset URL so the UI can show the figure, not only the caption.

RAG evaluation

MetricQuestion it answers
Context recall / hit@kDid we retrieve a chunk that contains the answer?
Context precisionAre retrieved chunks actually relevant?
FaithfulnessDoes the answer stick to the context?
Answer relevanceDoes it address the user question?
Citation accuracyDo cited chunks support the claims?

Build a golden set of 50–200 real questions with labeled source docs. Automate with LLM-as-judge only after you sample-check the judge. Track regressions when you change chunking or models.

Checkpoint — move on when

  • You can ingest a corpus, retrieve with metadata filters, and cite sources
  • You have an eval set and know your hit@k
  • You can debug a bad answer by looking at retrieved chunks first
