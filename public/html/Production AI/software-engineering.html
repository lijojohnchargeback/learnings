🧑‍💻 1. Software Engineering

Step 1 of 12 — The foundation every Production AI Engineer needs before models, agents, or GPUs.

Why this comes first

Production AI is software engineering with models in the loop. If you cannot ship an API, persist data, test it, and run it on Linux, you cannot ship RAG, agents, or LLMOps. Models fail in interesting ways; engineering is what keeps the product up.

What you will be able to do

  • Write backend services in Python and Node.js
  • Design REST/JSON APIs with auth, validation, and errors
  • Store and query data in SQL and document databases
  • Use Git, Linux, and tests as daily tools
  • Reason about services, queues, and failure in distributed systems

Python

Primary language for ML, RAG, agents, and FastAPI backends. Learn syntax, typing, packaging, async, and how to structure a service — not just notebooks.

# FastAPI skeleton you should be able to write from memory from fastapi import FastAPI, HTTPException from pydantic import BaseModel app = FastAPI() class AskRequest(BaseModel): question: str user_id: str @app.post("/ask") def ask(body: AskRequest): if not body.question.strip(): raise HTTPException(status_code=400, detail="question required") return {"answer": f"echo: {body.question}", "user_id": body.user_id}
Practice: venv, pip/poetry, type hints, dataclasses, logging, pytest, and a 3-file project (api / services / tests).

JavaScript / TypeScript

Needed for AI apps (React/Next.js), tool UIs, and many agent SDKs. TypeScript is the production default — types catch contract bugs between frontend, APIs, and model JSON.

type ChatMessage = { role: "user" | "assistant"; content: string }; async function sendChat(messages: ChatMessage[]): Promise<string> { const res = await fetch("/api/chat", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ messages }), }); if (!res.ok) throw new Error(`HTTP ${res.status}`); const data = (await res.json()) as { reply: string }; return data.reply; }

Node.js

Runtime for JS backends, MCP servers, and automation workers. Learn the event loop, streams, env config, and calling Python services over HTTP.

import express from "express"; const app = express(); app.use(express.json()); app.post("/tools/search", async (req, res) => { const q = String(req.body.query ?? ""); // call vector search or Python RAG service res.json({ results: [], query: q }); }); app.listen(3000);

APIs

Every LLM feature is an API: chat, retrieve, tool-call, evaluate. Design resources, not ad-hoc functions. Always define auth, validation, idempotency keys, and error shapes.

ConcernProduction rule
ContractsJSON Schema / OpenAPI / Pydantic / Zod — never "whatever the model returns"
AuthAPI keys or JWT at the edge; never put model keys in the browser
ErrorsStable codes: 400 validation, 401/403 auth, 404 missing, 429 rate limit, 500 unexpected
Versioning/v1/... when clients are external; additive changes only

Databases

AI apps still need users, threads, traces, documents, and billing. Learn SQL first (PostgreSQL), then a document store (MongoDB). Vector DBs come later in RAG — they are not a replacement for your system of record.

-- Typical AI product tables CREATE TABLE users (id uuid PRIMARY KEY, email text UNIQUE NOT NULL); CREATE TABLE threads ( id uuid PRIMARY KEY, user_id uuid REFERENCES users(id), created_at timestamptz DEFAULT now() ); CREATE TABLE messages ( id uuid PRIMARY KEY, thread_id uuid REFERENCES threads(id), role text CHECK (role IN ('user', 'assistant', 'tool')), content text NOT NULL, tokens_in int, tokens_out int );

Git

Production teams live in PRs. Learn branching, rebasing vs merge, .gitignore, conventional commits, and how to review diffs that include prompts, evals, and infra.

git checkout -b feat/rag-rerank git add -p git commit -m "Add cross-encoder rerank step to retrieval pipeline" git push -u origin HEAD

Linux

Servers, containers, and GPU boxes are Linux. You need the shell, files, permissions, processes, logs, curl, and SSH. Docker comes in LLMOps; Linux is the base.

# Inspect a running AI API curl -i http://127.0.0.1:8000/health journalctl -u my-api -n 100 --no-pager ss -tlnp | grep 8000 tail -f /var/log/my-api/app.log

Testing

Model output is non-deterministic, so tests must split: deterministic code (chunking, tools, parsers) vs evals (quality). Start with pytest / Vitest on everything that is not an LLM.

def test_rejects_empty_question(client): r = client.post("/ask", json={"question": " ", "user_id": "u1"}) assert r.status_code == 400 def test_tool_schema_is_valid(): schema = load_tool("search_docs") assert "query" in schema["parameters"]["properties"]

Microservices

Split when a team or scaling axis needs it — not because a blog said so. Common AI split: API gateway, retrieval service, inference/worker, eval job. Communicate with HTTP or a queue; share a contract, not a database, unless you must.

Rule: A chat app with one FastAPI process is not a failure. Premature microservices add latency around every LLM call.

Distributed systems

LLMs time out, GPUs OOM, and vendors rate-limit. You need timeouts, retries with jitter, idempotency, circuit breakers, and "at least once" vs "exactly once" thinking for tool side effects.

import httpx async def call_model(prompt: str) -> str: async with httpx.AsyncClient(timeout=30.0) as client: for attempt in range(3): try: r = await client.post(MODEL_URL, json={"prompt": prompt}) r.raise_for_status() return r.json()["text"] except httpx.TimeoutException: if attempt == 2: raise

Checkpoint — move on when

  • You can ship a small authenticated API with a database and tests
  • You can deploy it (even locally with Docker) and debug it from the shell
  • You can explain what happens if a downstream call fails twice
