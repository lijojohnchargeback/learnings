⚡ Python Performance & Profiling

Measure, find hotspots, then optimize — timing, cProfile, memory, and practical speedups

🎯 Measure First

Premature optimization wastes time. For backends, latency usually comes from I/O, N+1 queries, and serialization — not from a slow for loop.

  1. Define the SLA (p50 / p99 latency, throughput)
  2. Reproduce with realistic data
  3. Profile CPU and memory separately
  4. Fix the top hotspot; re-measure

⏱️ Timing

import time from time import perf_counter start = perf_counter() # ... work ... print(f"took {perf_counter() - start:.4f}s") # Micro-benchmarks # python -m timeit "sum(range(1000))" import timeit print(timeit.timeit("sum(range(1000))", number=10_000))

📊 cProfile

# CLI # python -m cProfile -o out.prof app.py # python -m cProfile -s cumtime app.py import cProfile import pstats from pstats import SortKey def main(): ... cProfile.run("main()", "out.prof") stats = pstats.Stats("out.prof") stats.strip_dirs().sort_stats(SortKey.CUMULATIVE).print_stats(20) # Visualize (optional tools): snakeviz, tuna, py-spy # pip install snakeviz # snakeviz out.prof # py-spy top --pid <pid> # sampling profiler, low overhead
💡 Read profiles by cumulative time to find who calls expensive work, and by tottime to find who burns CPU itself.

🧮 NumPy, C Extensions & Friends

Move hot numeric loops out of pure Python. Libraries that release the GIL can also use multiple threads.

import numpy as np xs = np.arange(1_000_000) print((xs * xs).sum()) # vectorized — runs in C # Other options: # - Cython / mypyc / rust (PyO3) for custom extensions # - PyPy for long-running pure-Python services # - orjson / ujson for faster JSON # - uvloop for faster asyncio event loop (Unix)

💾 Caching

from functools import lru_cache import hashlib @lru_cache(maxsize=1024) def expensive(key: str) -> str: return hashlib.sha256(key.encode()).hexdigest() # Process-local cache only — for multi-worker apps use Redis/Memcached # Cache keys must include every input that affects the result # Set TTLs for data that can go stale

✅ Backend Performance Checklist

  • Fix N+1 DB queries (eager load / joins / selectinload)
  • Add indexes that match real filters
  • Paginate list endpoints; stream large downloads
  • Cache expensive reads (HTTP cache headers + Redis)
  • Use connection pools (DB, HTTP)
  • Prefer async or thread pools for concurrent I/O
  • Profile before micro-optimizing Python loops
  • Compress responses / use efficient serializers when payloads are large
💡 Bottom line: Correctness and clarity first. Profile with real traffic shape. Optimize the top 1–2 hotspots, then stop.
