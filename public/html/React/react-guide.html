⚛️ The React Architecture

React is more than a library; it's a declarative UI engine that abstracts away the complexity of state synchronization and manual DOM manipulation. For a senior engineer, React is a tool for building predictable, component-driven interfaces.

The Paradigm Shift: Declarative vs Imperative

In traditional jQuery (Imperative), you tell the browser how to change (e.g., "Find the button, add a class, change text"). In React (Declarative), you tell the browser what the UI should look like for a given state, and React handles the state-to-view transformation efficiently.

Why React Wins

  • 🧱 Component Atomic Design: Build complex systems from small, testable, and reusable atoms.
  • 🔄 One-Way Data Flow: Predictable state management where data only flows downwards (Parents to Children).
  • 🚀 Ecosystem Maturity: From Next.js for SSR to React Native for mobile, the knowledge is cross-platform.

✨ Key Features

FeatureDescription
Virtual DOM Uses VirtualDOM instead of RealDOM (RealDOM manipulations are expensive)
Server-Side Rendering Supports SSR for better performance and SEO
Unidirectional Data Flow Data flows from parent to child (Efficiency, Better control, Easier debugging)
Declarative Programming Tell what UI should look like, React handles the rest
Component-Based Reusable/composable UI components

Advantages

  • ✓ Component-based approach
  • ✓ Declarative programming (tell what UI should look like)
  • ✓ DOM updates handled gracefully
  • ✓ Increased application performance
  • ✓ Easy to integrate
  • ✓ Reusable code
  • ✓ Helps build rich UI
  • ✓ Rich ecosystem

Disadvantages

  • ✗ Only a library (handles only View in MVC)
  • ✗ Library size is relatively large
  • ✗ Difficult to understand for novices

📝 JSX (JavaScript XML)

JSX is an extension to JavaScript that allows us to write HTML elements in JavaScript and place them in the DOM without using createElement() or appendChild().

What is JSX?

  • JSX converts HTML tags into React elements
  • Provides syntactic sugar for React.createElement()
  • Gives expressiveness of JavaScript with HTML-like template syntax
  • JSX files don't render directly - uses transformers like Babel
// Without JSX React.createElement('div', null, 'Hello World') // With JSX <div>Hello World</div>
💡 Note: JSX makes your code elegant and simple. Browsers don't understand JSX directly - it must be transformed to JavaScript using tools like Babel.

🧩 Components

A component is a small unit of design that can be reused or nested in other components.

Types of Components

1. Functional Components

JavaScript functions that return HTML (JSX).

const Welcome = (props) => { return <h1>Hello, {props.name}</h1>; }

2. Class-Based Components

ES6 classes that extend React.Component.

class Welcome extends React.Component { render() { return <h1>Hello, {this.props.name}</h1>; } }

Functional vs Class Components

FeatureFunctionalClass-Based
Definition JavaScript function JavaScript class
Render Method No render method Has render() method
State Management React Hooks (useState, etc.) this.state, this.setState()
Lifecycle useEffect hook Lifecycle methods
Constructor Not available Available
'this' keyword Absent Present

When to Use Class Components

  • When you need lifecycle hooks (before Hooks were introduced)
  • Error boundaries (still require class components)

🔄 Props & State

Props (Properties)

"Props" is a special keyword in React for passing data from parent to child component.

Key Characteristics:

  • Immutable: Cannot be changed by the child component
  • Read-only: Component configuration
  • How components communicate: Props are how components talk to each other

State

State is a data structure that holds information that may change over the lifetime of the component.

Props vs State

FeaturePropsState
Passed to Component (from parent) Managed within component
Mutability Immutable Mutable
Can be changed? No Yes (using setState or useState)
Ownership Parent component Component itself

setState() in Class Components

⚠️ Important: setState is asynchronous!
// ❌ Wrong - won't reflect immediately this.setState({count: this.state.count + 1}) console.log(this.state.count) // Old value // ✅ Correct - use callback this.setState({count: this.state.count + 1}, () => { console.log(this.state.count) // Updated value }) // ✅ Best - use previous state this.setState(prevState => ({ count: prevState.count + 1 }))

State Best Practices

  • ✓ Do not modify state directly (won't trigger re-render)
  • ✓ Use callback if code needs to execute after state update
  • ✓ Use previous state when updating based on current state
  • ✓ React groups multiple setState calls for performance

🌳 Virtual DOM & Reconciliation

The Virtual DOM (VDOM) is React's "draft" version of the actual DOM. It allows React to perform calculations in JavaScript memory, which is orders of magnitude faster than communicating with the browser's DOM engine.

Senior Technical Deep Dive: The Reconciliation Algorithm

Directly comparing two DOM trees has an O(n³) complexity. React uses a Heuristic O(n) Algorithm based on two assumptions:

  1. Two elements of different types will produce different trees.
  2. The developer can hint at which child elements may be stable across different renders with a key prop.

React Fiber: The Engine Behind the UI

React Fiber is the re-implementation of React's core algorithm. It allows React to pause, abort, or reuse work. This enables "Concurrent Features" like Time Slicing (preventing long renders from blocking the main thread) and Suspense.

🖱️ Event Handling

Event handlers in React should be functions, not function calls.

// ❌ Wrong - calls function immediately <button onClick={this.handleClick()}>Click</button> // ✅ Correct - passes function reference <button onClick={this.handleClick}>Click</button>

Binding Event Handlers (Class Components)

Because of the "this" keyword in JavaScript, it's necessary to bind events:

Method 1: Bind in JSX

<button onClick={this.handleClick.bind(this)}> {this.state.message} </button>

Method 2: Arrow Functions (Most Common)

<button onClick={() => this.handleClick()}> {this.state.message} </button>

Method 3: Binding in Constructor (Best Performance)

constructor(props) { super(props); this.state = { message: "hello" }; this.handleClick = this.handleClick.bind(this); }

Methods as Props

You can pass methods as props to child components and also pass parameters.

🔀 Conditional Rendering

1. If/Else (Outside JSX)

if(this.state.loggedIn) { return <h1>Welcome Lijo</h1>; } else { return <h1>Welcome Guest</h1>; }

2. Element Variables

render() { let message; if(this.state.loggedIn) { message = "Welcome Lijo"; } else { message = "Welcome Guest"; } return <h1>{message}</h1>; }

3. Ternary Operator

return ( <h1> {this.state.loggedIn ? "Welcome Lijo" : "Welcome Guest"} </h1> );

4. Short Circuit (&&)

return this.state.loggedIn && <h1>Welcome Lijo</h1>;

📋 Lists & Keys

Rendering Lists

const numbers = [1, 2, 3, 4, 5]; const listItems = numbers.map((number) => <li key={number.toString()}>{number}</li> );

Importance of Keys

  • Stable Identity: Keys help React identify which items changed, added, or removed
  • Efficient Updates: Keys play a crucial role in efficiently updating the UI
  • Performance: Help React optimize rendering
⚠️ Warning: Do NOT use index as key! If you add or remove items, indices will change, causing issues.

🔄 Lifecycle Methods (Class Components)

Lifecycle methods are special methods in class components that run at specific points in a component's life.

⬆️ Mounting Phase

When an instance of a component is being created and inserted into the DOM.

Order of Execution

  1. constructor() - Called when component is created
  2. getDerivedStateFromProps() - Static method, rarely used
  3. render() - Only required method, returns JSX
  4. componentDidMount() - Called after component is mounted

componentDidMount()

  • Called only once
  • Invoked immediately after render()
  • Perfect for HTTP requests
  • Can call setState() here

Parent-Child Execution Order

ComponentA constructor ComponentA getDerivedStateFromProps ComponentA render ComponentB constructor ComponentB getDerivedStateFromProps ComponentB render ComponentB componentDidMount ComponentA componentDidMount

🔄 Updating Phase

Called when component re-renders due to changes in state or props.

Order of Execution

  1. getDerivedStateFromProps() - Static method
  2. shouldComponentUpdate() - Decides whether to re-render
  3. render() - Re-renders component
  4. getSnapshotBeforeUpdate() - Captures info from DOM (e.g., scroll position)
  5. componentDidUpdate(prevProps, prevState, snapshot) - Called after update

⬇️ Unmounting Phase

When a component is removed from the DOM.

componentWillUnmount()

  • Clean up work
  • Cancel network requests
  • Remove event listeners
  • Clear timers

🪝 React Hooks: Functional Power

Introduced in React 16.8, Hooks allow functional components to "hook into" React state and lifecycle features, effectively making class components optional for most use cases.

How React Tracks Hooks Internally

React doesn't use magic; it uses a Linked List. Each time a Hook is called, it's added to a list for that component instance. On the next render, React traverses this list to find the previous state.


⚠️ Why Order Matters: This is why Hooks cannot be called inside loops or conditions. If the order of calls changes between renders, React will lose track of which state belongs to which Hook.

Junior vs Senior Perspective

  • 👶 Junior: "Hooks are easier to write than classes."
  • 👨‍💻 Senior: "Hooks enable better logic extraction via Custom Hooks, allowing us to share side-effect logic without Higher-Order Components (HOCs) or Render Props."

📊 useState Hook

Manages state in functional components.

Basic Usage

const [count, setCount] = useState(0); // Update state setCount(count + 1); // Update based on previous state (recommended) setCount(prevCount => prevCount + 1);

useState vs setState

FeaturesetState (Class)useState (Hooks)
State Type Must be object Can be anything (number, string, object, array)
Merging Automatically merges Does NOT merge (must spread manually)
Return Value N/A Array with [value, setter]

Multiple State Variables

const [name, setName] = useState(''); const [age, setAge] = useState(0); const [email, setEmail] = useState('');

Object State (Manual Merging)

const [user, setUser] = useState({ name: '', email: '' }); // Must spread to merge setUser(prevUser => ({ ...prevUser, name: 'John' }));

⚡ useEffect Hook

The useEffect hook is the Swiss Army Knife of functional components. It's often misunderstood as a lifecycle method replacement, but its true purpose is Synchronization.

The Mental Model: Synchronizing with External Systems

Instead of thinking "when does this run?", think "with what state does this effect synchronize?". An effect is a way to step outside of the React paradigm and synchronize with the DOM, a network request, or a third-party library.


Senior Tip: Avoid the "God Effect". Don't put unrelated logic in a single useEffect. Use multiple effects to separate concerns, making them easier to debug and optimize.

Senior Perspective: Race Conditions

When fetching data inside useEffect, always handle Race Conditions. If a user triggers a request and then quickly navigates away or triggers another, you might update state with "stale" data. Use a boolean flag or an AbortController in the cleanup function to cancel pending updates.

ComponentWillUnmount Equivalent

useEffect(() => { // Setup window.addEventListener('resize', handleResize); // Cleanup (runs on unmount) return () => { window.removeEventListener('resize', handleResize); }; }, []);
💡 Tip: Always clean up subscriptions and event listeners in the return function to prevent memory leaks!

🌐 useContext Hook

Context API is React's native solution for Prop Drilling—passing data through intermediate elements that don't need it.

Architectural Choice: Context API vs. Redux

Context API: Best for low-frequency updates (e.g., Theme, Locale, User Auth). It's built into React and requires no extra boilerplate.
Redux/Zustand: Best for high-frequency updates or complex state transitions. Context re-renders all consumers whenever the value changes, which can be a performance bottleneck if the state is massive.

Senior Tip: Component Composition

Before reaching for Context, consider Component Composition. Passing the child component itself as a prop can often eliminate the need for prop drilling without adding the complexity of a Context Provider.

🔄 useReducer Hook

Alternative to useState for complex state logic.

const reducer = (state, action) => { switch(action.type) { case 'increment': return { count: state.count + 1 }; case 'decrement': return { count: state.count - 1 }; default: return state; } }; const [state, dispatch] = useReducer(reducer, { count: 0 }); // Usage dispatch({ type: 'increment' });

🎯 useCallback Hook

Returns a memoized callback function that only changes if dependencies change.

Why useCallback?

  • Prevents unnecessary re-renders
  • Useful when passing callbacks to optimized child components
  • Improves performance
const memoizedCallback = useCallback( () => { doSomething(a, b); }, [a, b] // Only recreate if a or b changes );
💡 Remember: Use React.memo for components and useCallback for functions.

💾 useMemo Hook

Returns a memoized value that only recomputes when dependencies change.

Why useMemo?

  • Avoid expensive calculations on every render
  • Optimize performance for CPU-intensive operations
const expensiveValue = useMemo(() => { return computeExpensiveValue(a, b); }, [a, b]); // Only recompute if a or b changes

useCallback vs useMemo

useCallbackuseMemo
Caches function instance Caches result/value
Returns memoized callback Returns memoized value

🔗 useRef Hook

Allows you to access DOM nodes directly or persist values across renders.

Accessing DOM Elements

const inputRef = useRef(); // Focus input inputRef.current.focus(); // Get value const value = inputRef.current.value; <input ref={inputRef} />

Persisting Values

const countRef = useRef(0); // Doesn't cause re-render countRef.current += 1;

🧩 Fragments

Fragments let you group a list of children without adding extra nodes to the DOM.

Why Fragments?

  • Avoid unnecessary div wrappers
  • Better CSS performance
  • Cleaner DOM structure
// Long syntax <React.Fragment> <h1>Title</h1> <p>Content</p> </React.Fragment> // Short syntax <> <h1>Title</h1> <p>Content</p> </>
💡 Note: The only attribute you can pass to Fragment is key (when mapping).

⚡ React Performance & Optimization

React is fast by default, but complex applications can suffer from "Jank" if unnecessary re-renders aren't managed. Optimization in React is about avoiding reconciliation work.

The Memoization Matrix: memo vs useMemo vs useCallback

  • 🧩 React.memo: HOC that prevents a component from re-rendering if its props haven't changed (Shallow Comparison).
  • 💾 useMemo: Hook that caches the result of an expensive calculation.
  • 🎯 useCallback: Hook that caches the function instance to prevent breaking React.memo in child components.

⚠️ Senior Warning: Optimization is not free. Re-calculating dependencies and comparing props has an overhead. Don't wrap everything in memo—use profiling tools first.

📦 Code Splitting & Dynamic Imports

Modern SPAs can become massive. Code Splitting allows you to split your bundle into smaller chunks, loading them only when the user actually needs them.

// Dynamic Import with React.lazy const HeavyComponent = React.lazy(() => import('./HeavyComponent')); function MyComponent() { return ( <React.Suspense fallback={<Spinner />}> <HeavyComponent /> </React.Suspense> ); }

Why it Matters for Core Web Vitals

By using React.lazy and Suspense, you significantly reduce the LCP (Largest Contentful Paint) and TBT (Total Blocking Time), as the browser doesn't have to parse and execute unused code on the initial load.

🎯 Refs

Refs allow you to access DOM nodes directly within React.

Use Cases

  • Focusing text inputs
  • Triggering animations
  • Integrating with third-party DOM libraries

Ref Forwarding

Forwarding refs from parent to child component:

const FancyInput = React.forwardRef((props, ref) => ( <input ref={ref} {...props} /> )); // Parent can access child's input const inputRef = useRef(); <FancyInput ref={inputRef} />

🚪 Portals

Portals provide a way to render children into a DOM node that exists outside the parent component's DOM hierarchy.

Use Cases

  • Modals
  • Tooltips
  • Dropdowns
// index.html <div id="root"></div> <div id="portal-root"></div> // Component const PortalDemo = () => { return ReactDOM.createPortal( <div>Portal Content</div>, document.getElementById('portal-root') ); };
💡 Note: Event bubbling works normally even though the element is in a different DOM tree!

🛡️ Error Boundaries

Error boundaries are React components that catch JavaScript errors anywhere in their child component tree.

Features

  • Catch errors during rendering
  • Display fallback UI
  • Log error information
class ErrorBoundary extends React.Component { constructor(props) { super(props); this.state = { hasError: false }; } static getDerivedStateFromError(error) { return { hasError: true }; } componentDidCatch(error, errorInfo) { console.log('Error:', error, errorInfo); } render() { if (this.state.hasError) { return <h1>Something went wrong.</h1>; } return this.props.children; } }
⚠️ Note: Error boundaries currently must be class components. There's no hook equivalent yet.

🎁 Higher-Order Components (HOC)

A higher-order component is a function that takes a component and returns a new component.

const withLoading = (Component) => { return (props) => { if (props.isLoading) { return <div>Loading...</div>; } return <Component {...props} />; }; }; // Usage const EnhancedComponent = withLoading(MyComponent);
💡 Important: Don't forget to pass {...props} to the wrapped component!
