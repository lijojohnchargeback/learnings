⚛️ React

Complete Guide to React — Basics, Hooks, Architecture & Advanced Concepts

⚛️ The React Architecture

React is more than a library; it's a declarative UI engine that abstracts away the complexity of state synchronization and manual DOM manipulation. You describe what the UI should look like for a given state; React figures out the minimal set of DOM updates to get there.

Describe state → React updates the DOM. Your components return a description of the UI. React diffs that description against the previous tree and applies only the necessary browser updates.

What React is

A library for building UIs from composable components. It owns the View layer — rendering and state-driven updates.

What React owns

Component tree, reconciliation, hooks, and (with React DOM / Native) painting to a host environment.

What React is not

A full framework. Routing, data fetching, and global store are ecosystem choices (Next.js, React Router, TanStack Query, Zustand, etc.).

The Paradigm Shift: Declarative vs Imperative

In traditional jQuery (Imperative), you tell the browser how to change (e.g., "Find the button, add a class, change text"). In React (Declarative), you tell the browser what the UI should look like for a given state, and React handles the state-to-view transformation efficiently.

Core mental model

  1. UI = f(state) — the same state always produces the same UI description.
  2. Components are functions (or classes) that return elements, not imperative DOM scripts.
  3. Data flows down — parents pass props; children notify parents via callbacks.
  4. State changes trigger re-renders — React re-runs components and reconciles the result.

Why React Wins

  • 🧱 Component Atomic Design: Build complex systems from small, testable, and reusable atoms.
  • 🔄 One-Way Data Flow: Predictable state management where data only flows downwards (Parents to Children).
  • 🚀 Ecosystem Maturity: From Next.js for SSR to React Native for mobile, the knowledge is cross-platform.
  • 🧪 Testability: Pure render functions and hooks make unit and integration testing straightforward.

✨ Key Features

These are the pillars that make React feel different from older jQuery-style UI code — and from heavier MVC frameworks.

Virtual DOM

Diff in memory, patch the real DOM sparingly — fewer expensive browser operations.

Unidirectional flow

Props down, events up. Easier to reason about than two-way binding sprawl.

Components

Reusable, composable units. Build screens from atoms instead of page scripts.

FeatureDescription
Virtual DOM Uses Virtual DOM instead of mutating Real DOM directly (Real DOM ops are expensive)
Server-Side Rendering Supports SSR (via frameworks like Next.js) for performance and SEO

Advantages

  • ✓ Component-based approach and strong composition model
  • ✓ Declarative programming (tell what UI should look like)
  • ✓ DOM updates handled via reconciliation
  • ✓ Huge ecosystem (Next.js, React Native, testing libs)
  • ✓ Easy to integrate into existing apps gradually
  • ✓ Reusable code via components and custom hooks

Trade-offs

  • ✗ Only a library for the View — you choose routing, data, and store
  • ✗ Build tooling and concepts (JSX, hooks) have a learning curve
  • ✗ Misused re-renders can hurt performance without profiling

📝 JSX (JavaScript XML)

JSX is an extension to JavaScript that lets you write markup-like syntax that compiles into React element trees. It is not HTML in the browser — it is sugar over React.createElement() (or the modern JSX transform).

JSX never runs in the browser as-is. Babel (or your bundler) turns <Button /> into createElement calls, which become React elements, which React turns into host DOM nodes.

What is JSX?

  • JSX converts HTML-like tags into React elements (plain objects)
  • Provides syntactic sugar for React.createElement()
  • Gives the expressiveness of JavaScript with template-like syntax
  • Must be transformed at build time — browsers do not understand JSX natively
// Without JSX React.createElement('div', null, 'Hello World') // With JSX <div>Hello World</div> // Expressions inside curly braces <h1>Hello, {user.name}</h1> <button disabled={isLoading}>Save</button>

JSX rules that trip people up

One root node (or a Fragment). Use className not class. Use htmlFor not for. Self-close void tags: <img />.

JSX is just JavaScript

You can assign elements to variables, return them from functions, and store them in arrays. Conditionals and maps live in JS — not a separate template language.

💡 Note: With the automatic JSX runtime (React 17+), you often don't need to import React just for JSX — but you still import hooks and APIs you use.

🧩 Components

A component is a reusable unit of UI — a function (or class) that returns a description of what to render. Apps are trees of nested components, each owning a clear responsibility.

Compose, don't copy. Break screens into focused pieces: layout shells, feature cards, and leaf widgets. Nest them until each piece has one job.

Types of Components

1. Functional Components

JavaScript functions that accept props and return JSX. This is the modern default.

const Welcome = ({ name }) => { return <h1>Hello, {name}</h1>; }; // Composition: components as children function Card({ title, children }) { return ( <section className="card"> <h2>{title}</h2> {children} </section> ); }

2. Class-Based Components

ES6 classes that extend React.Component. Still needed for error boundaries; otherwise prefer functions + hooks.

class Welcome extends React.Component { render() { return <h1>Hello, {this.props.name}</h1>; } }

Design tip

Prefer many small presentational components over one mega component. Lift state only as high as shared consumers need it.

Naming

PascalCase for components (UserAvatar). Keep props explicit. Avoid dumping an entire domain object when three fields suffice.

Functional vs Class Components

FeatureFunctionalClass-Based
Definition JavaScript function JavaScript class
Render Method No render method Has render() method
State Management React Hooks (useState, etc.) this.state, this.setState()
Lifecycle useEffect hook Lifecycle methods
Constructor Not available Available
'this' keyword Absent Present

When to Use Class Components

  • Error boundaries (still require class components today)
  • Maintaining legacy code that hasn't migrated to hooks

🔄 Props & State

Two kinds of data drive a React UI: props (inputs from outside) and state (memory owned by the component). Mixing them up is the most common source of confusing bugs for beginners.

Props in, state inside. Parents configure children with props. A component that needs to remember something across renders owns that value as state and updates it with a setter.

Props (Properties)

"Props" is a special keyword in React for passing data from parent to child component.

Key Characteristics:

  • Immutable: Cannot be changed by the child component
  • Read-only: Treat props as configuration for this render
  • Communication: Data and callbacks both travel through props
  • Children: Special prop for nested JSX passed between tags
function Parent() { const [count, setCount] = useState(0); return ( <Child label="Clicks" count={count} onIncrement={() => setCount(c => c + 1)} /> ); }

State

State is a data structure that holds information that may change over the lifetime of the component. Updating state schedules a re-render of that component and its descendants.

Props vs State

FeaturePropsState
Passed to Component (from parent) Managed within component
Mutability Immutable Mutable
Can be changed? No Yes (using setState or useState)
Ownership Parent component Component itself

setState() in Class Components

⚠️ Important: setState is asynchronous!
// ❌ Wrong - won't reflect immediately this.setState({count: this.state.count + 1}) console.log(this.state.count) // Old value // ✅ Correct - use callback this.setState({count: this.state.count + 1}, () => { console.log(this.state.count) // Updated value }) // ✅ Best - use previous state this.setState(prevState => ({ count: prevState.count + 1 }))

State Best Practices

  • ✓ Do not modify state directly (won't trigger re-render)
  • ✓ Use callback if code needs to execute after state update
  • ✓ Use previous state when updating based on current state
  • ✓ React groups multiple setState calls for performance

🌳 Virtual DOM & Reconciliation

The Virtual DOM (VDOM) is React's lightweight description of the UI — plain JS objects, not browser nodes. React compares the previous tree to the next tree in memory, then applies only the necessary patches to the real DOM.

Diff in memory, patch in the browser. Changing one label does not rebuild the whole page — React finds the mismatch and updates that host node.

Why Virtual DOM helps

Reading/writing the real DOM is expensive. Batching calculations in JS and committing once keeps interactions snappy.

What it is not

Not magic speed for free. Unnecessary re-renders still cost CPU. Keys, memoization, and clean state design still matter.

Senior Technical Deep Dive: The Reconciliation Algorithm

Directly comparing two DOM trees has an O(n³) complexity. React uses a Heuristic O(n) Algorithm based on two assumptions:

  1. Two elements of different types will produce different trees (React tears down and rebuilds).
  2. The developer can hint at which child elements may be stable across different renders with a key prop.

React Fiber: The Engine Behind the UI

React Fiber is the re-implementation of React's core algorithm. It allows React to pause, abort, or reuse work. This enables Concurrent Features like time slicing (preventing long renders from blocking the main thread), Suspense, and prioritized updates (e.g. typing stays responsive while a heavy list updates).

🖱️ Event Handling

Event handlers in React should be functions, not function calls.

// ❌ Wrong - calls function immediately <button onClick={this.handleClick()}>Click</button> // ✅ Correct - passes function reference <button onClick={this.handleClick}>Click</button>

Binding Event Handlers (Class Components)

Because of the "this" keyword in JavaScript, it's necessary to bind events:

Method 1: Bind in JSX

<button onClick={this.handleClick.bind(this)}> {this.state.message} </button>

Method 2: Arrow Functions (Most Common)

<button onClick={() => this.handleClick()}> {this.state.message} </button>

Method 3: Binding in Constructor (Best Performance)

constructor(props) { super(props); this.state = { message: "hello" }; this.handleClick = this.handleClick.bind(this); }

Methods as Props

You can pass methods as props to child components and also pass parameters.

🔀 Conditional Rendering

1. If/Else (Outside JSX)

if(this.state.loggedIn) { return <h1>Welcome Lijo</h1>; } else { return <h1>Welcome Guest</h1>; }

2. Element Variables

render() { let message; if(this.state.loggedIn) { message = "Welcome Lijo"; } else { message = "Welcome Guest"; } return <h1>{message}</h1>; }

3. Ternary Operator

return ( <h1> {this.state.loggedIn ? "Welcome Lijo" : "Welcome Guest"} </h1> );

4. Short Circuit (&&)

return this.state.loggedIn && <h1>Welcome Lijo</h1>;

📋 Lists & Keys

When you render a collection, React needs a stable identity for each sibling so it can reuse DOM nodes correctly when the list reorders, inserts, or deletes.

Keys are identity, not decoration. Index keys shift when you insert at the top — React remounts the wrong items. Stable IDs keep component state and DOM attached to the right row.

Rendering Lists

const users = [ { id: 'u1', name: 'Ada' }, { id: 'u2', name: 'Grace' }, ]; const listItems = users.map((user) => <li key={user.id}>{user.name}</li> );

Importance of Keys

  • Stable Identity: Keys help React identify which items changed, added, or removed
  • Efficient Updates: Correct keys avoid remounting inputs and losing focus/state
  • Performance: Reconciliation can move nodes instead of recreating them

Good keys

Database IDs, UUIDs, or any unique stable field from your data model.

Acceptable index keys

Only for static lists that never reorder, filter, or insert — otherwise prefer real IDs.

⚠️ Warning: Do NOT use index as key for dynamic lists. If you add or remove items, indices shift and React may reuse the wrong component instance (wrong local state, wrong focus).

📝 Forms

In React, form inputs are usually controlled: the displayed value lives in React state, and every keystroke updates that state. Uncontrolled inputs let the DOM own the value and are read via refs when needed.

Controlled vs Uncontrolled Components

ControlledUncontrolled
Value controlled by React state Value controlled by DOM
Use useState/setState Use refs to access value
Easy validation, formatting, disable submit Less re-renders; fine for simple one-shot reads
Recommended default File inputs, integrating non-React widgets

Controlled Component Example

const [email, setEmail] = useState(''); const [error, setError] = useState(''); function onSubmit(e) { e.preventDefault(); if (!email.includes('@')) { setError('Enter a valid email'); return; } submitForm({ email }); } <form onSubmit={onSubmit}> <input value={email} onChange={(e) => setEmail(e.target.value)} /> {error && <p>{error}</p>} <button type="submit">Join</button> </form>

Uncontrolled Component Example

const inputRef = useRef(); <input ref={inputRef} defaultValue="hello" /> // Access value: inputRef.current.value
💡 Tip: Prefer controlled inputs when you need live validation, character counters, or dependent fields. Reach for libs (React Hook Form, Formik) when forms grow large.

🔄 Lifecycle Methods (Class Components)

Lifecycle methods are special methods in class components that run at specific points in a component's life: creation, updates, and removal. In function components, the same ideas map mainly to useEffect (and related hooks).

Three phases. Mount once, update whenever props/state change, unmount with cleanup. Know which phase fits fetch, subscriptions, and teardown.

Mounting

Constructor → render → componentDidMount. Ideal for first fetch and subscriptions.

Updating

Prop/state change → optional shouldComponentUpdate → render → componentDidUpdate.

Unmounting

componentWillUnmount — cancel timers, abort fetches, remove listeners.

⬆️ Mounting Phase

When an instance of a component is being created and inserted into the DOM.

Order of Execution

  1. constructor() - Called when component is created
  2. getDerivedStateFromProps() - Static method, rarely used
  3. render() - Only required method, returns JSX
  4. componentDidMount() - Called after component is mounted

componentDidMount()

  • Called only once
  • Invoked immediately after render()
  • Perfect for HTTP requests
  • Can call setState() here

Parent-Child Execution Order

ComponentA constructor ComponentA getDerivedStateFromProps ComponentA render ComponentB constructor ComponentB getDerivedStateFromProps ComponentB render ComponentB componentDidMount ComponentA componentDidMount

🔄 Updating Phase

Called when component re-renders due to changes in state or props.

Order of Execution

  1. getDerivedStateFromProps() - Static method
  2. shouldComponentUpdate() - Decides whether to re-render
  3. render() - Re-renders component
  4. getSnapshotBeforeUpdate() - Captures info from DOM (e.g., scroll position)
  5. componentDidUpdate(prevProps, prevState, snapshot) - Called after update

⬇️ Unmounting Phase

When a component is removed from the DOM.

componentWillUnmount()

  • Clean up work
  • Cancel network requests
  • Remove event listeners
  • Clear timers

🪝 React Hooks: Functional Power

Introduced in React 16.8, Hooks let function components tap into state, lifecycle-like effects, context, refs, and memoization — making class components optional for almost every case.

Hooks are a linked list per component. Call them in the same order every render. That is why the Rules of Hooks ban hooks inside loops and conditionals.

Rules of Hooks

  1. Only call Hooks at the top level of a React function (not inside if, loops, or nested functions).
  2. Only call Hooks from React function components or custom Hooks.

How React Tracks Hooks Internally

React doesn't use magic; it uses a Linked List. Each time a Hook is called, it's added to a list for that component instance. On the next render, React traverses this list to find the previous state.


⚠️ Why Order Matters: This is why Hooks cannot be called inside loops or conditions. If the order of calls changes between renders, React will lose track of which state belongs to which Hook.

Built-in Hooks

useState, useEffect, useContext, useReducer, useMemo, useCallback, useRef, plus concurrent helpers like useTransition.

Custom Hooks

Extract reusable logic into useSomething() functions. They compose other hooks and share behavior without HOCs or render props.

Junior vs Senior Perspective

  • 👶 Junior: "Hooks are easier to write than classes."
  • 👨‍💻 Senior: "Hooks enable better logic extraction via Custom Hooks, allowing us to share side-effect logic without Higher-Order Components (HOCs) or Render Props."

📊 useState Hook

Manages state in functional components.

Basic Usage

const [count, setCount] = useState(0); // Update state setCount(count + 1); // Update based on previous state (recommended) setCount(prevCount => prevCount + 1);

useState vs setState

FeaturesetState (Class)useState (Hooks)
State Type Must be object Can be anything (number, string, object, array)
Merging Automatically merges Does NOT merge (must spread manually)
Return Value N/A Array with [value, setter]

Multiple State Variables

const [name, setName] = useState(''); const [age, setAge] = useState(0); const [email, setEmail] = useState('');

Object State (Manual Merging)

const [user, setUser] = useState({ name: '', email: '' }); // Must spread to merge setUser(prevUser => ({ ...prevUser, name: 'John' }));

⚡ useEffect Hook

The useEffect hook is the Swiss Army Knife of functional components. It's often misunderstood as a lifecycle method replacement, but its true purpose is Synchronization with systems outside React.

The Mental Model: Synchronizing with External Systems

Instead of thinking "when does this run?", think "with what state does this effect synchronize?". An effect is a way to step outside of the React paradigm and synchronize with the DOM, a network request, or a third-party library.


Senior Tip: Avoid the "God Effect". Don't put unrelated logic in a single useEffect. Use multiple effects to separate concerns, making them easier to debug and optimize.

Dependency array cheat sheet

DepsWhen it runsTypical use
[] After mount (and cleanup on unmount) Subscribe once, load initial data
[a, b] After mount + whenever a or b changes Re-fetch when filters change
omitted After every render Rare — usually a bug
useEffect(() => { let cancelled = false; async function load() { const data = await fetchUser(userId); if (!cancelled) setUser(data); } load(); return () => { cancelled = true; }; }, [userId]);

Senior Perspective: Race Conditions

When fetching data inside useEffect, always handle Race Conditions. If a user triggers a request and then quickly navigates away or triggers another, you might update state with "stale" data. Use a boolean flag or an AbortController in the cleanup function to cancel pending updates.

Cleanup (componentWillUnmount equivalent)

useEffect(() => { // Setup window.addEventListener('resize', handleResize); // Cleanup (runs on unmount / before re-run) return () => { window.removeEventListener('resize', handleResize); }; }, []);
💡 Tip: Always clean up subscriptions and event listeners in the return function to prevent memory leaks!

🌐 useContext Hook

Context API is React's native solution for Prop Drilling — passing data through intermediate elements that don't need it.

Skip the middlemen. Providers publish a value; any descendant can subscribe with useContext without threading props through every layer.
const ThemeContext = createContext('light'); function App() { return ( <ThemeContext.Provider value="dark"> <Toolbar /> </ThemeContext.Provider> ); } function ThemedButton() { const theme = useContext(ThemeContext); return <button className={theme}>Save</button>; }

Architectural Choice: Context API vs. Redux

Context API: Best for low-frequency updates (e.g., Theme, Locale, User Auth). It's built into React and requires no extra boilerplate.
Redux/Zustand: Best for high-frequency updates or complex state transitions. Context re-renders all consumers whenever the value changes, which can be a performance bottleneck if the state is massive.

Senior Tip: Component Composition

Before reaching for Context, consider Component Composition. Passing the child component itself as a prop can often eliminate the need for prop drilling without adding the complexity of a Context Provider.

🔄 useReducer Hook

Alternative to useState for complex state logic.

const reducer = (state, action) => { switch(action.type) { case 'increment': return { count: state.count + 1 }; case 'decrement': return { count: state.count - 1 }; default: return state; } }; const [state, dispatch] = useReducer(reducer, { count: 0 }); // Usage dispatch({ type: 'increment' });

🎯 useCallback Hook

Returns a memoized callback function that only changes if dependencies change.

Why useCallback?

  • Prevents unnecessary re-renders
  • Useful when passing callbacks to optimized child components
  • Improves performance
const memoizedCallback = useCallback( () => { doSomething(a, b); }, [a, b] // Only recreate if a or b changes );
💡 Remember: Use React.memo for components and useCallback for functions.

💾 useMemo Hook

Returns a memoized value that only recomputes when dependencies change.

Why useMemo?

  • Avoid expensive calculations on every render
  • Optimize performance for CPU-intensive operations
const expensiveValue = useMemo(() => { return computeExpensiveValue(a, b); }, [a, b]); // Only recompute if a or b changes

useCallback vs useMemo

useCallbackuseMemo
Caches function instance Caches result/value
Returns memoized callback Returns memoized value

🔗 useRef Hook

Allows you to access DOM nodes directly or persist values across renders.

Accessing DOM Elements

const inputRef = useRef(); // Focus input inputRef.current.focus(); // Get value const value = inputRef.current.value; <input ref={inputRef} />

Persisting Values

const countRef = useRef(0); // Doesn't cause re-render countRef.current += 1;

🧩 Fragments

Fragments let you group a list of children without adding extra nodes to the DOM.

Why Fragments?

  • Avoid unnecessary div wrappers
  • Better CSS / flex / grid layouts (no phantom wrappers)
  • Cleaner DOM structure
// Long syntax <React.Fragment> <h1>Title</h1> <p>Content</p> </React.Fragment> // Short syntax <> <h1>Title</h1> <p>Content</p> </>
💡 Note: The only attribute you can pass to Fragment is key (when mapping). Use the long form when you need key.

🧊 Pure Components

A pure component re-renders only when its props (or state) actually change. In class form that is React.PureComponent; in function form it is React.memo.

React.PureComponent

Class base with a shallow shouldComponentUpdate. Skips render when props/state are shallow-equal.

React.memo

Wrap a function component. Same shallow prop compare. Optionally pass a custom compare function.

const Item = React.memo(function Item({ title, onSelect }) { return <button onClick={onSelect}>{title}</button>; }); // Pair with useCallback so onSelect identity stays stable const onSelect = useCallback(() => select(id), [id]);
⚠️ Caveat: Shallow compare fails for new object/array/function props created inline every render. Stabilize with useMemo / useCallback, or don't memoize yet — profile first.

⚡ React Performance & Optimization

React is fast by default, but complex applications can suffer from "Jank" if unnecessary re-renders aren't managed. Optimization in React is about avoiding reconciliation work.

The Memoization Matrix: memo vs useMemo vs useCallback

  • 🧩 React.memo: HOC that prevents a component from re-rendering if its props haven't changed (Shallow Comparison).
  • 💾 useMemo: Hook that caches the result of an expensive calculation.
  • 🎯 useCallback: Hook that caches the function instance to prevent breaking React.memo in child components.

⚠️ Senior Warning: Optimization is not free. Re-calculating dependencies and comparing props has an overhead. Don't wrap everything in memo—use profiling tools first.

📦 Code Splitting & Dynamic Imports

Modern SPAs can become massive. Code Splitting splits your bundle into smaller chunks and loads them only when the user actually needs that route or feature.

Ship less on first paint. Keep the shell small; lazy-load dashboards, settings, and heavy editors behind routes or user actions.
// Dynamic Import with React.lazy const HeavyComponent = React.lazy(() => import('./HeavyComponent')); function MyComponent() { return ( <React.Suspense fallback={<Spinner />}> <HeavyComponent /> </React.Suspense> ); }

Where to split

Route boundaries, admin panels, charts/editors, rarely used modals — anything large and not needed for first paint.

Fallback UX

Suspense shows a spinner or skeleton while the chunk downloads. Match the layout to avoid content jump.

Why it Matters for Core Web Vitals

By using React.lazy and Suspense, you significantly reduce the LCP (Largest Contentful Paint) and TBT (Total Blocking Time), as the browser doesn't have to parse and execute unused code on the initial load.

🎯 Refs

Refs allow you to access DOM nodes directly within React.

Use Cases

  • Focusing text inputs
  • Triggering animations
  • Integrating with third-party DOM libraries

Ref Forwarding

Forwarding refs from parent to child component:

const FancyInput = React.forwardRef((props, ref) => ( <input ref={ref} {...props} /> )); // Parent can access child's input const inputRef = useRef(); <FancyInput ref={inputRef} />

🚪 Portals

Portals provide a way to render children into a DOM node that exists outside the parent component's DOM hierarchy.

Use Cases

  • Modals
  • Tooltips
  • Dropdowns
// index.html <div id="root"></div> <div id="portal-root"></div> // Component const PortalDemo = () => { return ReactDOM.createPortal( <div>Portal Content</div>, document.getElementById('portal-root') ); };
💡 Note: Event bubbling works normally even though the element is in a different DOM tree!

🛡️ Error Boundaries

Error boundaries are React components that catch JavaScript errors anywhere in their child component tree.

Features

  • Catch errors during rendering
  • Display fallback UI
  • Log error information
class ErrorBoundary extends React.Component { constructor(props) { super(props); this.state = { hasError: false }; } static getDerivedStateFromError(error) { return { hasError: true }; } componentDidCatch(error, errorInfo) { console.log('Error:', error, errorInfo); } render() { if (this.state.hasError) { return <h1>Something went wrong.</h1>; } return this.props.children; } }
⚠️ Note: Error boundaries currently must be class components. There's no hook equivalent yet.

🎁 Higher-Order Components (HOC)

A higher-order component is a function that takes a component and returns a new component.

const withLoading = (Component) => { return (props) => { if (props.isLoading) { return <div>Loading...</div>; } return <Component {...props} />; }; }; // Usage const EnhancedComponent = withLoading(MyComponent);
💡 Important: Don't forget to pass {...props} to the wrapped component!
