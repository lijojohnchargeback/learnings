🧰 Redux Toolkit

The official way to write Redux: slices, Immer, thunks, DevTools, and RTK Query — less boilerplate, same model.

📚 Why Toolkit?

Redux Toolkit (RTK) is the standard for new Redux apps. Classic Redux made you hand-write action types, action creators, immutable updates, and store enhancers. Toolkit wraps that into a few functions without changing the three principles.

createSlice writes reducer + actions. configureStore wires DevTools. RTK Query caches server data.
Classic painToolkit answer
Action type strings + creators + switch createSlice generates all three
Spread nested state by hand Immer: write “mutating” syntax safely
Wire DevTools + thunk yourself configureStore does it by default
Hand-rolled fetch cache RTK Query endpoints, cache, and hooks
npm install @reduxjs/toolkit react-redux

🏪 configureStore

import { configureStore } from '@reduxjs/toolkit'; import counterReducer from './features/counter/counterSlice'; import cartReducer from './features/cart/cartSlice'; export const store = configureStore({ reducer: { counter: counterReducer, cart: cartReducer } // middleware: thunk + immutability + serializable checks // devTools: enabled in development });

Add saga or extra middleware with the callback form:

middleware: (getDefaultMiddleware) => getDefaultMiddleware().concat(sagaMiddleware, listenerMiddleware.middleware)
⚠️ Serializable check: By default RTK warns if you put non-JSON values in state or actions. That is intentional. If you must store a class instance, you are probably fighting Redux — keep it in a ref or Context instead.

🍰 createSlice

A slice is a reducer plus the actions for one feature. Name the slice after the state key.

import { createSlice } from '@reduxjs/toolkit'; const counterSlice = createSlice({ name: 'counter', initialState: { value: 0 }, reducers: { increment(state) { state.value += 1; // Immer }, addBy(state, action) { state.value += action.payload; }, reset: () => ({ value: 0 }) } }); export const { increment, addBy, reset } = counterSlice.actions; export default counterSlice.reducer; // generated action: { type: 'counter/increment' } // generated action: { type: 'counter/addBy', payload: 5 }

Use in a component

import { useSelector, useDispatch } from 'react-redux'; import { increment, addBy } from './counterSlice'; function Counter() { const value = useSelector((state) => state.counter.value); const dispatch = useDispatch(); return ( <> <p>{value}</p> <button onClick={() => dispatch(increment())}>+1</button> <button onClick={() => dispatch(addBy(5))}>+5</button> </> ); }

🧊 Immer Inside Slices

Inside createSlice reducers you may mutate a draft. Immer produces the next immutable state. Nested updates become readable.

reducers: { toggleTodo(state, action) { const todo = state.items.find((t) => t.id === action.payload); if (todo) todo.done = !todo.done; }, removeTodo(state, action) { state.items = state.items.filter((t) => t.id !== action.payload); } }
Outside slices (selectors, tests, extra helpers) you still treat state as immutable. Do not mutate store.getState().

⏳ createAsyncThunk

Describes an async call and auto-dispatches lifecycle actions: pending, fulfilled, rejected.

import { createAsyncThunk, createSlice } from '@reduxjs/toolkit'; export const fetchUser = createAsyncThunk( 'user/fetch', async (userId, { rejectWithValue }) => { const res = await fetch(`/api/users/${userId}`); if (!res.ok) return rejectWithValue(await res.text()); return res.json(); } ); const userSlice = createSlice({ name: 'user', initialState: { data: null, status: 'idle', error: null }, reducers: {}, extraReducers: (builder) => { builder .addCase(fetchUser.pending, (state) => { state.status = 'loading'; }) .addCase(fetchUser.fulfilled, (state, action) => { state.status = 'succeeded'; state.data = action.payload; }) .addCase(fetchUser.rejected, (state, action) => { state.status = 'failed'; state.error = action.payload || action.error.message; }); } }); // component dispatch(fetchUser('42'));

The thunk receives thunkAPI: dispatch, getState, rejectWithValue, signal (AbortController). Abort happens if you use the returned promise’s .abort() or when the component unmounts with RTK’s hooks in some setups.

➕ extraReducers

Use extraReducers for actions defined outside the slice (thunks, another slice’s actions). Prefer the builder callback (TypeScript-friendly) over the map object notation.

extraReducers: (builder) => { builder.addCase(logout.fulfilled, () => initialState); builder.addMatcher( (action) => action.type.endsWith('/rejected'), (state, action) => { state.lastError = action.error.message; } ); }

📡 RTK Query

RTK Query is a cache for server state: endpoints, auto-generated hooks, deduped requests, and cache lifetimes. It is usually better than hand-written thunks for CRUD APIs.

Component useGetUserQuery('42') │ ▼ RTK Query cache ── providesTags: User/42 │ ├── HIT → return cached data └── MISS → fetchBaseQuery → /api/users/42 │ useUpdateUserMutation ── invalidatesTags: User/42 │ ▼ refetch getUser
import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react'; export const api = createApi({ reducerPath: 'api', baseQuery: fetchBaseQuery({ baseUrl: '/api' }), tagTypes: ['User', 'Post'], endpoints: (build) => ({ getUser: build.query({ query: (id) => `users/${id}`, providesTags: (result, err, id) => [{ type: 'User', id }] }), updateUser: build.mutation({ query: ({ id, ...body }) => ({ url: `users/${id}`, method: 'PATCH', body }), invalidatesTags: (result, err, { id }) => [{ type: 'User', id }] }) }) }); export const { useGetUserQuery, useUpdateUserMutation } = api; // store configureStore({ reducer: { [api.reducerPath]: api.reducer }, middleware: (gDM) => gDM().concat(api.middleware) }); // component const { data, isLoading, error } = useGetUserQuery('42');
💡 Tags: providesTags / invalidatesTags refetch related queries after a mutation. That replaces a lot of manual “reload the list” thunks.

📇 createEntityAdapter

Normalized lists: { ids: [], entities: { [id]: item } }. Fast lookup, no duplicate rows, reusable CRUD reducers.

import { createEntityAdapter, createSlice } from '@reduxjs/toolkit'; const todosAdapter = createEntityAdapter({ selectId: (todo) => todo.id, sortComparer: (a, b) => a.text.localeCompare(b.text) }); const todosSlice = createSlice({ name: 'todos', initialState: todosAdapter.getInitialState(), reducers: { todoAdded: todosAdapter.addOne, todosReceived: todosAdapter.setAll, todoRemoved: todosAdapter.removeOne } }); export const { selectAll: selectAllTodos, selectById: selectTodoById } = todosAdapter.getSelectors((state) => state.todos);

🎯 Selectors in RTK

import { createSelector } from '@reduxjs/toolkit'; const selectCart = (state) => state.cart; export const selectItemCount = createSelector( [selectCart], (cart) => cart.items.reduce((n, i) => n + i.qty, 0) ); export const selectTotal = createSelector( [selectCart], (cart) => cart.items.reduce((n, i) => n + i.qty * i.price, 0) );

Memoized selectors keep components from recalculating when unrelated store keys change — as long as the selected inputs are stable.

🚚 Migrate from Classic Redux

  1. Install @reduxjs/toolkit. Replace createStore with configureStore.
  2. Move one feature at a time into createSlice. Keep old reducers in the same reducer map.
  3. Replace hand-written thunks with createAsyncThunk or RTK Query.
  4. Delete duplicate action type files once slices own those actions.
  5. Keep Saga if you still need it — run saga middleware next to the defaults.

✅ Best Practices

  • One slice per feature, not one giant appSlice.
  • Keep UI-only flags (modal open) in component state unless many distant trees need them.
  • Put server lists in RTK Query, not a manual items array you refetch by hand.
  • Export action creators and selectors from the slice file; components should not string-match types.
  • Use TypeScript RootState and AppDispatch inferred from the store for typed hooks.
// app/hooks.js import { useDispatch, useSelector } from 'react-redux'; export const useAppDispatch = () => useDispatch(); export const useAppSelector = useSelector;

Where Saga still fits

Toolkit does not replace saga. Use thunks/RTK Query for typical HTTP. Add saga when you need cancellation graphs, websocket loops, or multi-step transactions that are painful as nested thunks. See Redux Saga.
