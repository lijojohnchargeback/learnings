🟣 Redux

A predictable global store: actions in, pure reducers, one state tree, and a one-way data flow.

📚 What is Redux?

Redux is a state container. The whole app (or a large domain) has one store. You never mutate that store in place. You dispatch a plain object called an action. A reducer function returns the next state.

Classic Redux is verbose on purpose: every change is visible in DevTools. In production you almost always write it with Redux Toolkit. This page is the mental model underneath.

One store. Actions describe what happened. Reducers compute the next state. The UI only reads.

The loop

UI → dispatch(action) → reducer(state, action) → new state → UI. Side effects (HTTP, timers) do not live in reducers. They live in middleware: thunks, sagas, or RTK Query.

📜 Three Principles

PrincipleMeaning
Single source of truth One store object. You can still split reducers with combineReducers.
State is read-only The only way to change it is to dispatch an action. No state.count++ from a component.
Changes with pure functions Reducers: (state, action) => nextState. No fetch, no random, no mutation of state.

🧱 Building Blocks

  • State — a plain serializable object (JSON-like).
  • Action — { type, ...payload }. type is a string.
  • Reducer — pure function that returns new state.
  • Store — holds state, exposes getState, dispatch, subscribe.
  • Middleware — intercepts actions (logging, async).
  • UI bindings — react-redux Provider, useSelector, useDispatch.
store.getState() { counter: { count: 0 }, todos: { items: [] }, user: { data: null, status: 'idle' } } UI ──dispatch──► middleware ──► reducer ──► new state ──► UI

🎫 Actions

An action is a fact that something happened. Convention: string type in 'domain/event' form, plus a payload.

const increment = { type: 'counter/increment' }; const addTodo = { type: 'todos/add', payload: { id: '1', text: 'Learn Redux', done: false } }; // Action creator — a function that returns an action function addTodo(text) { return { type: 'todos/add', payload: { id: crypto.randomUUID(), text, done: false } }; } dispatch(addTodo('Learn Redux'));
⚠️ Serializable: Do not put Promises, class instances, or functions in actions if you use DevTools and persist. IDs, strings, numbers, plain objects, arrays only.

🧮 Reducers

A reducer is (state, action) => newState. It must not mutate state. Copy objects/arrays you change.

const initialState = { count: 0 }; function counterReducer(state = initialState, action) { switch (action.type) { case 'counter/increment': return { ...state, count: state.count + 1 }; case 'counter/addBy': return { ...state, count: state.count + action.payload }; default: return state; // unknown actions must return current state } }

combineReducers

Each slice owns a key of the root state. An action is passed to every slice reducer; most return their previous slice unchanged.

import { combineReducers } from 'redux'; const rootReducer = combineReducers({ counter: counterReducer, todos: todosReducer }); // store.getState() → { counter: { count: 0 }, todos: { items: [] } }
💡 Reducers must handle undefined state on first run by returning initialState. That is why state = initialState is the default parameter.

🏪 The Store

import { createStore } from 'redux'; const store = createStore(rootReducer); store.getState(); // current tree store.dispatch({ type: 'counter/increment' }); store.subscribe(() => { console.log(store.getState()); });

createStore is considered a legacy API; Toolkit’s configureStore wraps it with DevTools and thunk middleware. The methods above are still the store contract.

Dispatch from anywhere

UI, middleware, and tests can dispatch. Components should not call store.dispatch directly in React — use useDispatch so they stay testable and bound to the Provider’s store.

🔌 Middleware

Middleware is a pipeline around dispatch. Signature: store => next => action => result.

const logger = (store) => (next) => (action) => { console.log('dispatching', action); const result = next(action); console.log('next state', store.getState()); return result; }; const store = createStore(rootReducer, applyMiddleware(logger));

Thunks (simple async)

redux-thunk lets you dispatch a function. That function receives dispatch and getState and can await APIs, then dispatch plain actions.

function fetchUser(id) { return async (dispatch, getState) => { dispatch({ type: 'user/pending' }); try { const user = await api.getUser(id); dispatch({ type: 'user/fulfilled', payload: user }); } catch (err) { dispatch({ type: 'user/rejected', error: err.message }); } }; } dispatch(fetchUser('42'));

When thunks grow into cancellation, races, and long workflows, use Redux Saga. For most REST caches, use RTK Query inside Redux Toolkit.

⚛️ react-redux

Wrap the tree once. Hooks subscribe components to the store.

import { Provider, useSelector, useDispatch } from 'react-redux'; root.render( <Provider store={store}> <App /> </Provider> ); function Counter() { const count = useSelector((state) => state.counter.count); const dispatch = useDispatch(); return ( <button onClick={() => dispatch({ type: 'counter/increment' })}> {count} </button> ); }

useSelector re-renders the component only when the selected value changes (strict === by default). Selecting the whole state defeats that.

connect (legacy)

Class apps used connect(mapState, mapDispatch)(Component). New code should use hooks.

🎯 Selectors

A selector is a function state => derivedValue. Keep them next to the reducer. Use Reselect (or Toolkit’s createSelector) to memoize expensive derived data.

const selectTodos = (state) => state.todos.items; const selectOpenTodos = (state) => selectTodos(state).filter((t) => !t.done); // memoized import { createSelector } from 'reselect'; const selectOpenTodosMemo = createSelector( [selectTodos], (items) => items.filter((t) => !t.done) );

📁 Folder Structure

Classic “Rails-style” folders (actions/, reducers/) scatter one feature. Prefer feature folders (and Toolkit slices):

src/ store/ index.js // createStore / configureStore features/ todos/ todosSlice.js // or todosReducer.js + todosActions.js TodosList.jsx cart/ cartSlice.js CartDrawer.jsx

🎯 When to Use Redux

  • Many components, distant in the tree, share the same domain data
  • You need a replayable log of what happened (support, undo, analytics)
  • Several teams must update state the same way

Skip Redux for a marketing page, a form-only wizard, or a single context value like theme.

Immutability cheat sheet

  • Object: { ...state, count: 1 }
  • Array add: [...list, item]
  • Array update: list.map(x => x.id === id ? { ...x, done: true } : x)
  • Array remove: list.filter(x => x.id !== id)
  • Toolkit + Immer lets you write state.count++ inside createSlice.
